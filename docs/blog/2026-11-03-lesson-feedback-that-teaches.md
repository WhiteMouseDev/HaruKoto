# 정답률 뒤에, 다시 이해할 수 있는 레슨 결과 만들기

하루코토의 학습 저장과 이어하기를 보완한 뒤에는 결과 화면이 학습에 어떤 도움을 주는지 확인했다. 서버는 정답 보기 ID와 문장 배열의 올바른 토큰 순서를 보내지만, 기존 모바일 카드는 문제·정오·해설·복습 상태 위주였다. 사용자가 틀린 표현의 정답 자체를 찾기 어려운 구조였다.

이번에는 기존 응답의 정답 ID를 해당 문항의 보기 원문으로 연결하고, 배열은 정답 토큰을 순서대로 이어 완성 문장으로 표시했다. 같은 토큰이 여러 번 나오는 일본어 문장도 그대로 유지한다. 문항은 목록 위치가 아니라 고유한 order로 대응하며, ID가 없거나 중복된 경우 임의의 정답을 만들지 않는다.

결과는 오답이 있을 때 ‘오답만’으로 시작하고 전체 결과로 전환할 수 있게 했다. 이 보기는 원본 점수나 답안을 바꾸지 않으며 새 복습 퀴즈도 만들지 않는다. 기존 재도전 버튼은 ‘레슨 전체 다시 풀기’로 명확히 해 결과 필터와 재제출 범위가 혼동되지 않게 했다.

복습 안내에서도 데이터의 뜻을 먼저 확인했다. 결과의 nextReviewAt은 현재 일정이 아니라 해당 문항을 제출할 때 기록한 예정 시각이다. 뒤이어 같은 표현을 학습하면 실제 기한이 달라질 수 있다. 따라서 현재 시각과 빼서 ‘-30분 후’ 같은 안내를 만들지 않고, ‘제출 당시 복습 예정’과 한국 시간의 날짜를 표시했다. 현재 복습 일정은 학습 탭에서 확인하도록 했다.

레슨 목록 오류에는 해당 영역의 다시 불러오기 버튼을 추가했다. 조회 중·실패·정상적으로 비어 있는 상태를 구분하고, 재시도는 해당 레벨의 레슨 목록만 갱신한다. 계정 전환 직전의 응답이나 버튼이 다른 계정에 적용되지 않도록 조회 전후와 콜백 시점의 계정을 확인한다. 복습과 가나 영역은 독립적으로 사용할 수 있다.

교차 검토에서는 테스트 환경과 실제 앱의 재시도 정책 차이도 찾았다. 테스트 컨테이너는 자동 재시도를 껐지만 실제 앱은 기본 Riverpod 정책을 사용해 실패 후 여러 번 요청할 수 있었다. 레슨 목록에만 수동 재시도 정책을 명시하고, 기본 컨테이너에서도 첫 오류 이후 요청이 늘지 않으며 버튼을 눌렀을 때만 복구되는지 검증했다.

과거 제출 결과 복구는 신중하게 경계를 유지했다. 예전 결과에는 옛 보기 원문 전체가 없으므로, 바뀐 최신 문제와 자동 결합하면 틀린 정답을 가르칠 수 있다. 기존의 요약 전용 복구 화면을 유지하고 이번 개선은 정상 레슨 결과의 표현에 적용했다. API·DB·기존 복습 기한·목표·학습 기록·로그인 저장 방식은 바꾸지 않았다.

회귀 테스트와 합성 네이티브 시뮬레이터의 확인 범위, 운영 적용 전 검증 결과와 롤백안은 [구현 기록](../operations/plans/lesson-result-feedback-and-retry-2026-11-03.md)에 연결한다. 화면이 이해하기 쉬워졌는지와 다음날 기억에 도움이 되는지는 실제 입문자 관찰에서 이어서 확인할 과제다.

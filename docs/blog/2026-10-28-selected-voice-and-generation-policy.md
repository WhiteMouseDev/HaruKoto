# 마음에 드는 음성을 골랐는데, 다음 음원도 같은 설정으로 만들어질까?

대화의 남녀 화자가 같은 목소리로 들리던 문제를 고친 뒤에도 작업이 남았다. 비교용 화면에서 마음에 드는 음성을 고르는 일과 실제 앱의 다음 음원을 그 설정으로 생성하는 일은 서로 다른 경로였기 때문이다.

사용자는 대표 레슨의 원문 12문장을 직접 듣고 Kenzo B와 Shizuka를 모두 v4로 채택했다. 남성의 stability는 0.5, 여성은 0.8이었다. 승인한 HN5-004 네 파일은 정확한 원음 지문을 고정해 별도 업로드·캐시 갱신으로 적용했다. 앱에서 잘 재생된다는 확인은 이 네 파일에 대한 근거였다.

그런데 새 파일을 만드는 코드를 다시 보니 모델 기본값은 여전히 전역 TTS 설정을 따랐고, 여성의 stability도 0.5였다. 비교 도구에서만 v4를 명시적으로 넘기고 있었다. 짧은 문장 뒤에 마침표를 무조건 붙이는 기존 처리도 있어 `学生です。`가 요청에서는 `学生です。。`가 될 수 있었다. 이미 적용한 네 파일은 맞지만, 다음 캐시 누락이 생겼을 때 같은 선택 조건으로 생성된다는 보장은 없었다.

전역 모델을 바꾸는 방법은 피했다. 단어·가나·문제 안내와 다른 레벨의 음성까지 바뀔 수 있기 때문이다. 기존에 선택형으로 분리한 N5 대화 adapter에 v4 기본 정책을 두고, 역할별 안정성을 남성 0.5·여성 0.8로 나눴다. v4 요청의 원문과 구두점은 그대로 보낸다. 다른 모델을 명시적으로 지정하는 검수 작업의 호환성은 유지하며 새 환경변수는 추가하지 않는다.

검사는 함수가 돌려준 값만 보는 것으로 끝내지 않는다. 합성 보이스 ID와 메모리 HTTP transport를 사용해 실제 잠금 SDK가 만든 요청의 모델·텍스트·역할별 파라미터를 확인하고, 서비스에 저장되는 모델과 업로드 경로까지 연결한다. 전역 모델이 비어 있거나 잘못된 값이어도 전용 기본값은 유지되는지, 이전 캐시가 있으면 설정이 불완전해도 새 생성 없이 반환하는지도 회귀 조건이다. 외부 TTS나 운영 DB를 시험 대상으로 사용하지 않는다.

새 회귀 51개가 수정 전 실패했고, 수정 뒤 관련 128개가 통과했다. API 전체는 1,000개 통과·기존 fixture 준비 대기 13개 skip, 필수 격리 PostgreSQL 회귀는 85개 모두 실행해 통과했다. 정적 검사와 공개 OpenAPI 전체 비교도 통과했다. 이 수치를 새로 생성한 음원 개수나 사람이 확인한 발음 정확도로 읽어서는 안 된다.

기존 캐시를 우선하는 선택에는 효과와 한계가 함께 있다. 학습 중인 사용자의 음원이 갑자기 교체되지 않고 비용도 불필요하게 발생하지 않는다. 반면 생성 설정을 고쳤다고 기존 음성이 자동으로 바뀌지는 않는다. 채택한 음성을 확대할 때는 공개 콘텐츠의 최신 목록과 비용 상한, 교체할 정확한 행 수, 이전 파일 지문과 조건부 원복을 다시 준비해야 한다. 역할 설정 활성화는 HN5-004만의 허용 목록도 아니므로, 이후 모든 N5 대화의 캐시 누락 요청에 영향을 줄 수 있다는 점을 적용안에 적었다.

레슨 본문의 alias나 전체 음원 URL은 바꾸지 않는다. 모바일이 저장 위치를 복원할 때 콘텐츠 서명을 사용하기 때문이다. 음성 개선이 기존 학습 위치를 잃게 만드는 변경으로 번지지 않도록 생성 정책·파일 교체·앱 재생 기능을 각각 검증한다. 코드 롤백만으로 이미 적용한 캐시가 되돌아가지 않는다는 점도 원복안에 포함했다.

이 기록의 범위는 후속 소스 수정과 회귀 검증이다. PR 병합·배포·운영 역할 설정 활성화·추가 음원 교체와 일본어 청취 인증을 완료한 것으로 해석하지 않는다. 이번 검증 결과는 [상세 구현 기록](../operations/plans/n5-selected-voice-generation-policy-2026-10-28.md)에 따로 남긴다. [처음 화자 연결을 고친 과정](2026-10-26-dialogue-speaker-voice-routing.md)의 당시 결과와 합산하지 않는다.

## 이후 승인받은 운영 활성화

위 소스 준비를 마친 뒤 사용자가 PR #196 병합과 서버 배포, 선택한 역할 설정 활성화를 승인했다. 기존 캐시는 유지하고 캐시가 없는 N5 대화에만 새 정책을 적용하는 범위였다. 실제 적용 결과는 [별도 운영 기록](../operations/plans/n5-selected-voice-production-rollout-2026-10-28.md)에 남겼다.

두 보이스 ID는 새 Secret Manager 항목으로 분리하고, 현재 서버 계정에는 그 두 항목의 읽기 권한만 부여했다. 버전을 1로 고정한 참조 두 개만 추가했다. 배포 전후 실제 서비스 상태를 비교해 전역 모델·다른 환경·실행 계정이 그대로인지 확인하고, 새 리비전으로 트래픽 100%가 향하는 것도 별도 조회로 검증했다.

흥미로운 점은 공개 N5 대사 198문장 모두에 이미 캐시가 있었다는 것이다. 설정을 켠다고 이 198개의 목소리가 바뀌는 것은 요구한 동작이 아니었다. 검증을 위해 캐시를 지우는 대신, 기존 198행의 전체 지문과 콘텐츠·권한/RLS 지문이 동일한지 확인했다. 향후 생성 경로는 회귀 테스트와 배포 코드·설정으로 확인하고, 이번 운영에서 새 음원을 만들지는 않았다는 한계를 남겼다.

기존 QA 계정의 정상 로그인과 프로필·학습 데이터 조회, 네 문장 TTS URL 반환도 실제 운영에서 확인했다. 네 파일의 SHA와 전체 디코딩 결과는 적용 전 원음과 같았다. Data API는 차단된 상태였다. 실제 아이폰의 로그인과 저장 레슨 진입, 사용자 재생·정지·다시 듣기 보고를 확인하고, 강제 재실행 전후 같은 이해 체크 4/4와 문제·복원 안내가 유지되는 것도 실제 화면으로 비교했다. 시뮬레이터의 카드 이동·닫고 이어하기·강제 재실행 뒤 같은 2/5 위치 복원도 별도로 확인했다. 음성을 직접 들은 검수와 파일을 읽을 수 있다는 검사를 섞지 않는 원칙은 운영에서도 유지했다.

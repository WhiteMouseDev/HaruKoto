# 문장은 맞는데 대화의 두 사람이 같은 목소리였다

사용자는 문장 대응과 잘림, 정지·다시 듣기, 화면 이동 뒤 겹침, 편한 속도가 정상이라고 확인했다. 하지만 두 화자가 같은 여성 목소리라 어색하다는 피드백이 남았다. 파일이 있고 문장이 일치하는 기계 검사는 대화 속 누가 말하는지의 구분까지 보장하지 않았다.

먼저 등장인물을 조사했다. 정식 소스 81레슨·322대사와 실제 공개 76레슨·302대사를 구분했다. 김·사토·다나카·스즈키·야마다라는 이름형 표기와 선생님·점원 같은 역할 표기가 있었다. 같은 성씨를 전역의 동일 인물이나 특정 성별로 정하지 않았다. 공개 콘텐츠의 목소리 역할은 원본과 일치했고, 콘텐츠에 이미 있는 남성·여성 alias가 실제 생성에 전달되지 않는 것이 문제였다.

resolver는 text만 꺼내고 서버는 ElevenLabs의 단일 기본 voice ID로 생성했다. 새 전용 adapter로 N5 대화의 alias를 실제 voice ID에 연결했다. 기본 경로와 기존 캐시를 보존하고, 설정이 불완전하거나 역할이 알 수 없을 때 기본 여성 음성으로 조용히 합류하지 않게 했다. 단어·가나·문제 안내·N4는 기존 정책을 유지했다.

독립 검토는 두 가지를 보완했다. 같은 요청 지문으로도 음성은 달라질 수 있어 프로필 해시만으로 파일 경로를 정하면 재시도 때 덮어쓸 수 있었다. 생성별 UUID를 더하고 DB commit 실패 뒤 같은 프로필 재시도에서도 새 파일을 쓰는 회귀를 추가했다. SDK 원시 오류 본문·헤더가 서비스 로깅 체인에 전달되는 문제도 원인을 숨기고 민감 표식이 로그에 없는지 확인하는 회귀로 막았다.

최종 API 949개 통과·기존 fixture 대기 13개 skip, 필수 PostgreSQL 85개 무스킵과 정적 검사를 통과했다. 실제 SDK의 HTTP 직렬화도 외부 호출 없이 다섯 모델에서 확인했다. 첫 sandbox의 PostgreSQL 초기화 제한과 최종 허용된 로컬 격리 검증을 구분했다. 로컬 검사 수를 이전 버전이나 별도 표본 수와 합산하지 않았다.

품질 선택은 별도 실험으로 뒀다. 사용자에게 후보와 범위를 제시하고 같은 네 줄을 일본어 두 voice로 Multilingual v2와 v4에서 한 번씩, 정확히 여덟 파일·114자로 생성했다. HTTP·디코딩은 모두 통과했으나 이를 일본어 정확성·자연스러움 승인으로 바꾸지 않았다. 로컬 A/B 화면과 이어듣기·ZIP을 준비하고 사람 판정은 대기로 남겼다. 공급업체 character-cost 헤더 합계 114와 즉시 사용량 카운터 0을 구분하며 무료나 최종 청구 0으로 해석하지 않았다.

기존 로그인·학습·답안·기한·권한·Data API 설정과 운영 음성 캐시는 바꾸지 않았다. 특히 전체 듣기 URL이나 콘텐츠 voice alias를 바꾸면 모바일 레슨 체크포인트 서명이 달라질 수 있어, 기존 콘텐츠와 저장 위치를 유지하는 줄별 캐시 교체를 후속 적용안으로 남겼다. 이번 단계는 코드·회귀·검수 표본 준비이며 PR 병합·배포·운영 캐시 교체는 실행하지 않았다.

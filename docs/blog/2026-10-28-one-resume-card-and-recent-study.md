# 저장된 진행은 보존하면서 이어하기 화면을 짧게 만들기

레슨을 중단한 위치에서 이어하는 기능을 붙이자 다음 문제가 보였다. 여러 레슨을 오가며 공부하는 사용자에게는 저장 목록도 계속 쌓인다. 기존 구현은 본문 세 개와 전체 보기로 이미 상한을 두었지만, 세 개의 큰 카드와 추천 배너만으로도 학습 노선이 화면 아래로 밀렸다. 같은 레슨을 위의 이어하기 카드와 아래 저장 카드에서 다시 보여주기도 했다.

저장 상태를 줄이는 대신 화면에서 차지하는 공간을 줄이기로 했다. 학습 탭과 전체 레슨 페이지에서 하나의 이어하기 영역을 사용한다. 저장된 진행이 있으면 대표 한 개와 전체 보기 진입점을 제공하고, 없으면 기존 추천 레슨을 보여준다. 전체 목록은 간결한 행으로 바꾸되 모든 저장 위치에 접근할 수 있게 한다. 제출이 대기 중이거나 기록 확인이 필요한 항목의 안전한 동작도 보존한다.

대표 항목을 고르려면 ‘최근’의 의미부터 정해야 했다. 기존 저장 데이터에는 마지막 학습 시각이 없으므로 순서를 추정할 근거도 없었다. 현재 시각을 이전 기록 전체에 붙이면 새로 저장된 듯한 잘못된 이력이 된다. 따라서 기존 체크포인트는 그대로 읽고, 이후 실제 카드 이동이나 답안 선택처럼 학습 상태가 바뀔 때 선택형 시각 메타데이터를 남긴다. 단순 목록 조회나 백그라운드 저장, 재시도로 최근순이 바뀌지는 않는다.

새 시각 정보는 답안과 콘텐츠 서명을 바꾸지 않는 체크포인트 최상위 필드다. 기존 v1 버전과 저장 키를 유지하고 시각이 없거나 잘못돼도 유효한 학습 위치와 답안은 그대로 복원한다. 시각이 있는 기록을 최신순으로, 같은 시각이나 이전 기록은 기존 학습 순서로 정렬한다. 정렬의 동률 처리를 명시해 리스트 정렬 함수의 안정성에 기대지 않는다.

하나의 대표 카드로 합치는 과정에서도 실패 상태를 조심해야 한다. 저장 정보를 읽지 못했다고 추천과 다른 레슨까지 사라져서는 안 된다. 반대로 계정이나 레벨이 바뀐 뒤 예전 callback이 이전 레슨을 열어서도 안 된다. 기존의 계정 검사, 부분 실패 재시도, 시트에서 결과를 반환한 뒤 부모가 화면을 여는 흐름을 유지한다. 새 메타데이터가 서버 요청에 섞이지 않는지도 확인한다.

UI 검토에서는 새 ‘모두 보기’ 버튼의 기본 글자색도 확인했다. 브랜드 핑크를 작은 글자에 그대로 쓰면 밝은 배경에서 명도 대비가 부족했다. 이 버튼의 글자는 테마의 본문색을 사용하고 핑크 강조는 나머지 요소에 유지하는 쪽으로 보완했다. 밝은·어두운 모드에서 텍스트 대비와 큰 글자 배치를 함께 확인한다.

검증에서는 카드 개수만 확인하는 대신 이전 체크포인트의 실제 답안·선택·위치 복원과 저장 실패 후 재시도를 함께 확인한다. 두 화면의 중복 제거, 전체 항목 접근, 작은 화면과 큰 글자도 검사한다. 최종 구현·검증 결과와 한계는 [상세 실행 기록](../operations/plans/mobile-resume-recent-study-2026-10-28.md)에 남긴다.

대표적인 두 동작은 수정 전 실패를 재현했고, 신규 회귀 34개를 포함해 모바일 전체 748개가 통과했다. 저장 위치를 40개 만든 경우에도 대표 카드는 한 개였으며, 전체 목록의 마지막 항목을 선택할 수 있었다. 폭 320px·글자 200%의 밝은/어두운 모드와 실제 Flutter 위젯의 합성 데이터 렌더링도 확인했다. 이 미리보기를 실제 사용자 계정이나 아이폰에 업데이트해 검수한 결과로 바꾸지는 않는다.

이 변경은 모바일 표시와 로컬 메타데이터에 한정한다. 로그인·운영 학습 기록·복습 기한·DB 권한과 Data API 설정을 변경하지 않는다. 기기 간 진행 동기화를 제공하는 기능으로 확대해 설명하지 않는다.

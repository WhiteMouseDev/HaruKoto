# N5 Kenzo·Shizuka v4 생성 정책 운영 활성화

실시일: 2026-10-28 KST. 사용자는 PR #196 병합·서버 배포·Kenzo/Shizuka v4 설정 활성화와 음성 재생·학습·이어하기 확인을 승인했다. 기존 캐시는 유지하고 캐시가 없는 N5 대화에만 새 정책을 적용한다. [소스 정책과 회귀 검증](n5-selected-voice-generation-policy-2026-10-28.md)의 미배포 표시는 준비 시점의 기록이며, 이번 실제 실행 상태는 이 문서를 기준으로 한다.

## 실행 범위와 롤백 기준

변경은 서버 코드 배포와 선택형 역할 설정 두 개로 제한한다. 기존 전역 모델·단일 보이스·다른 secret 값과 로그인·학습 기록·기한·콘텐츠·DB 스키마·권한/RLS·Data API 설정은 수정 대상이 아니다.

운영 계정은 명시적으로 `whitemousedev@gmail.com`, 프로젝트 `harukoto`, 리전 `asia-northeast3`, 서비스 `harukoto-api`를 사용했다. Mac의 기본 gcloud 계정은 전환하지 않는다. 적용 전 서비스 전체 상태와 Secret 참조를 비공개 파일로 보존했으며, 키·실제 voice ID·사용자 정보를 저장소 문서나 공유 출력에 복사하지 않는다.

## 새 설정

적용 전 두 역할 설정과 해당 Secret Manager 항목이 모두 없음을 확인했다. 기존에 승인한 프로필의 보이스 ID 지문을 대조하고 ElevenLabs에서 두 보이스와 `eleven_v4` 접근을 GET으로 재확인했다. 새 음성 생성은 이 단계에 포함하지 않는다.

- `ELEVENLABS_LESSON_MALE_VOICE_ID`: 선택한 Kenzo, Secret 버전 `1` 고정.
- `ELEVENLABS_LESSON_FEMALE_VOICE_ID`: 선택한 Shizuka, Secret 버전 `1` 고정.
- 새 secret 2개·최초 버전 2개, 현재 서버 서비스 계정에 해당 두 secret의 `secretAccessor`만 추가한다. 기존 secret 값이나 프로젝트 전체 IAM은 변경하지 않는다.
- 기본 v4·남성 stability 0.5·여성 0.8·similarity 0.75는 병합한 N5 전용 소스 정책을 따른다. 전역 `ELEVENLABS_MODEL_ID`는 변경하지 않는다.
- 서비스 갱신은 두 secret 바인딩만 추가한다. 활성화 직전 리비전·템플릿과 런타임 계정을 비교하고, 갱신 뒤 별도 describe로 이미지·다른 환경 바인딩·계정·트래픽을 다시 확인한다.

현재 배포 action v3의 secret 갱신 기본 전략은 merge다. 기존 워크플로의 전역 secret 목록에 두 역할이 없더라도 이후 배포에서 해당 바인딩을 제거하지 않는다. 실제 실행 중 확인한 [공식 action 설정](https://raw.githubusercontent.com/google-github-actions/deploy-cloudrun/v3/action.yml)과 운영 상태를 근거로 하며, 별도 워크플로 소스 변경은 하지 않았다.

## 기존 캐시와 콘텐츠 보존

TLS 호스트·인증서 검증과 `REPEATABLE READ, READ ONLY` 트랜잭션으로 N5 콘텐츠·캐시·보안 카탈로그만 조회했다. 조회 상한과 statement/lock timeout을 두었고 사용자·학습 기록 테이블은 조회하지 않았다.

활성화 전 N5 레슨은 50개, 공개 대사는 198문장이고 **198문장 모두 기존 캐시가 있다**. 기존 N5 대화 캐시는 모든 속도를 포함해 198행, 원문/alias 연결 이상과 orphan target은 0개다. 실제 공개 캐시 누락 후보는 0개다.

따라서 운영 캐시를 삭제하거나 임의 레슨을 만들어 새 생성을 시험하지 않는다. 이번 설정 활성화는 기존 198개의 음원을 교체하지 않으며, 향후 새로 캐시가 누락된 N5 대화 요청에만 적용된다. 실제 신규 운영 음원 생성은 이번 검증에서 실행하지 않았다는 한계를 표시한다. 선택 프로필·실제 SDK 직렬화·캐시 누락 경로는 소스 회귀 51개와 기존 관련 테스트로 검증했다.

사후 스냅샷은 기존 각 캐시 행의 전체 JSON 지문을 비교한다. 정상적인 새 캐시 삽입은 구분하되, 기존 행 변경·삭제나 레슨 콘텐츠 지문·보안 카탈로그 변경을 숨기지 않는다. Data API 차단은 익명 키를 사용한 `HEAD /rest/v1/users?select=id&limit=0`의 차단 응답으로 별도 확인하고 행 데이터를 읽지 않는다.

## 기능 확인 범위

운영 인증·레슨 조회·기존 문장 TTS 반환·공개 MP3 형식/지문, 앱의 대화 재생·학습 위치·재실행 복원을 구분해 기록한다. 과거 HN5-004 파일럿이나 PR #197의 실기기 사용자 확인을 이번 배포 후 검수로 재사용하지 않는다.

`GET /quiz/incomplete`에는 오래된 미완료 퀴즈를 종료 처리하는 기존 쓰기가 있으므로 읽기 전용 점검으로 호출하지 않는다. 운영 점검용 계정은 기존 계정의 정상 인증만 사용하고 계정 생성·암호 변경·관리자 로그인 대행·기록 초기화는 하지 않는다. 앱의 정상 QA 조작이 만드는 학습 동작과 운영 설정 변경을 구분한다.

## 원복안

문제가 생기면 먼저 역할 활성화 전 `harukoto-api-00245-tmw`로 트래픽을 되돌려 새 역할 생성을 중단할 수 있다. 지속적인 설정 원복은 두 역할 바인딩만 제거한 새 리비전을 준비해 활성화한다. 코드 자체 문제가 있다면 적용 전 `harukoto-api-00244-ljc`를 기준으로 되돌린다. 원복 직전 현재 리비전과 후속 변경을 확인해 다른 운영 변경을 덮어쓰지 않는다.

코드나 트래픽 원복이 새 캐시를 삭제하거나 과거 음원으로 자동 교체하지는 않는다. 이번에는 기존 캐시 교체가 없으므로 기존 198행의 DB 원복도 없다. 새 secret·버전·파일을 파괴적으로 정리하거나 학습 기록을 초기화하지 않는다.

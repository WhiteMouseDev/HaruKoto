# 레슨 결과 피드백·오답 보기·조회 재시도 개선

2026-11-03 KST. 사용자가 결과의 정답·완성 문장·해설, 오답 우선 보기, 복습 안내 및 레슨 조회 재시도 개선과 회귀·시뮬레이터 검증을 승인했다. 운영 적용 전 결과를 보고하며, API·DB 변경이 필요하면 구체안을 먼저 확인한다. 기준 main은 PR #227까지 병합된 `48715838`이다.

## 구현 범위

1. 결과의 서버 `isCorrect` 판정을 유지한다. `order`가 유일하게 일치하는 문제에서만 정답 보기 ID를 원문으로 바꾸고, 배열 정답은 `correctOrder`의 토큰과 중복을 보존해 완성 문장으로 표시한다. 누락·중복·알 수 없는 ID에 다른 문제나 임의 정답을 대입하지 않는다.
2. 오답이 있으면 ‘오답만’ 보기를 기본으로 하고 ‘전체’로 전환한다. 각 보기 안의 기존 문항 순서를 유지하며 원본 결과·점수·답안은 변경하지 않는다. 전부 정답·문항 없음·결과 재빌드도 다룬다.
3. 기존 결과 해설과 학습자용 복습 문구를 표시한다. `nextReviewAt`은 제출 당시의 문항별 일정 스냅샷이므로 ‘제출 당시 복습 예정’으로 한국 시간의 절대 시각을 표시한다. 현재의 복습 기한으로 오해시키거나 음수 상대 시간을 표시하지 않는다. 현재 일정은 학습 탭에서 확인하도록 안내한다.
4. 학습 탭의 레슨 조회 실패는 해당 영역에서 재시도한다. 조회 중·실패·성공한 빈 목록을 구분하고, 복습·가나 영역은 계속 사용한다. 계정·레벨 전환과 늦은 응답, 재시도 연타를 기존 Riverpod·계정 가드 패턴으로 다룬다.

## 보존과 계약 경계

- 기존 API에 정답 ID·정답 배열·해설·일정이 있어 계약·DB 변경 없이 모바일에서 구현한다. 백엔드 담당자가 각 필드의 의미를 읽기 전용으로 확인했다.
- 과거 제출 결과 복구는 기존 요약 전용 화면을 유지한다. 과거 결과에는 옛 질문·보기 전체가 없으므로 변경된 최신 콘텐츠와 자동 결합하지 않는다.
- 보기 전환·결과 읽기·조회 재시도는 레슨 시작·답안·제출·XP·SRS 갱신을 수행하지 않는다. 기존 명시적 ‘다시 풀기’ 동작과 결과가 불명확한 제출 재시도는 바꾸지 않는다.
- 로그인·학습 기록·복습 기한·오늘 단어 목표·음원·Data API·권한·클라우드 설정은 변경 대상이 아니다. 새 의존성·환경 계약·플랫폼 설정도 추가하지 않는다.

## 검증 계획

- 결과: 선택형 보기 ID 대응, 배열 중복 토큰과 문장, 해설, 오답/전체 전환, 전부 정답·빈 목록·잘못된 order/옵션·nullable 필드, 재빌드·제출 결과 복구의 보존.
- 복습 문구: 제출 당시 의미, KST 날짜 경계, 과거·미래·잘못된 날짜 및 시간대가 없는 문자열.
- 조회: 최초/갱신 실패→재시도→성공·정상 빈 목록, 연타·계정/레벨 전환·늦은 응답, 다른 학습 영역 진입과 추가 쓰기 없음.
- 320px·글자 200%·라이트/다크를 회귀 테스트로 확인하고 모바일 전체 테스트·분석·포맷 검사를 수행한다.
- 전용 시뮬레이터와 합성 응답으로 실제 위젯·프로세스·화면을 확인한다. 운영 로그인·API·DB·아이폰을 사용한 검증으로 표현하지 않는다.

## 적용 및 되돌리기

이번 작업은 구현·검증과 결과 보고까지다. 운영 병합·배포·아이폰 업데이트는 포함하지 않는다. 모바일 코드만 적용할 수 있으며 서버 선행 배포나 마이그레이션은 없다. 문제가 생기면 결과 표시·레슨 영역만 호환 코드로 되돌리며, 저장 키·기존 데이터·서버 정책은 보정하지 않는다. 운영 적용 전에는 실제 변경 파일·검증 결과·시뮬레이터 확인 범위를 갱신해 보고한다.

## 교차 검토에서 추가한 보완

실제 앱은 Riverpod 기본 자동 재시도를 사용하는데 기존 테스트 컨테이너는 retry를 꺼서 오류가 즉시 보였다. 이 차이를 그대로 두면 실제 화면은 여러 번 조회하는 동안 로딩에 머물 수 있다. 레슨 목록 provider에만 자동 재시도를 끄고, 앱과 같은 기본 컨테이너로 실패 후 대기·요청 수 유지·사용자 재시도를 검증한다. 전역 네트워크·인증 재시도 정책은 바꾸지 않는다.

## 전용 네이티브 시뮬레이터 검증

전용 bundle `com.harukoto.lessonfeedbackqa`에 최종 제품 Dart433개 파일을 그대로 복사하고 manifest를 대조했다. 별도 합성 진입점·로컬 폰트·외부 소켓 차단을 사용하며 실제 운영 Auth 초기화와 운영 API·DB·아이폰 접근은 없다. 앱 전체의 실제 사용자 로그인이나 운영 학습 제출 검사로 확대하지 않는다.

- 혼합 결과에서 ‘오답만2’가 기본이며 ‘전체3’ 전환과 원래 순서 유지, 다시 오답만 보기, 전부 정답일 때 전체 기본을 확인했다.
- 정답 원문·해설·완성 문장·고정 KST 날짜가 실제 제품 위젯에서 보였다. 제출 당시 예정 시각을 현재 기한으로 표현하거나 음수 상대 시간을 표시하지 않았다.
- 기본 ProviderContainer에서 레슨503을 계속 반환해도10.9초 동안 해당 GET1회를 유지했다. 오류 안내와 수동 버튼이 보이며, 다른 가나 버튼으로 실제 KanaHubPage 진입이 가능했다.
- 수동 재시도 뒤 레슨 GET2회째만 추가되고, 응답을 보류한 동안 로딩·버튼 비활성, 이후 성공 목록과 노선도 복구를 확인했다.
- 최종 합성 누적 GET5회(레슨2/복습1/대시보드1/가나1), 학습 쓰기·외부 소켓·Flutter 오류는 모두0이었다. 이는 계측된 합성 앱의 범위이며 운영 서버의 모든 요청이0이었다는 의미로 사용하지 않는다.

화면 이동은 디버그 VM을 통해 실제 위젯 콜백을 실행했다. 사람의 물리 터치 검사·일본어 전문 감수와는 구분한다. 구현 중 자동 재시도 보완 이전 캡처는 최종 근거로 사용하지 않고, 최종 빌드에서 다시 캡처했다.

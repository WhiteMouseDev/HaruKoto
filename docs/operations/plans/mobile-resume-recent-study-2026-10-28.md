# 이어하기 카드 한 개와 최근 학습순 저장 목록

작성일: 2026-10-28 KST. 사용자는 학습 메인을 이어하기 카드 한 개와 전체 보기로 정리하고 최근 학습순 정렬·기존 위치/답안 보존·회귀 테스트를 요청했다. 범위는 모바일 소스·검증·리뷰용 PR이며 병합·기기 설치·운영 배포는 별도 단계다.

## 문제와 현재 구조

현재 저장 목록은 무한히 펼쳐지는 구현은 아니다. 본문에 최대 세 카드, 네 개 이상이면 80% 높이의 전체 보기 시트를 제공한다. 하지만 추천/이어하기 배너와 같은 레슨을 중복으로 표시하고 큰 카드 세 장이 학습 노선을 밀어낸다. 저장된 레슨의 정렬은 챕터·레슨 순서이며, 마지막 학습 시각은 기록하지 않는다.

## 변경 설계

1. 학습 탭과 전체 레슨 페이지에 이어하기 영역을 하나씩 둔다. 저장된 진행이 있으면 정렬된 첫 항목 하나만 대표 카드로 표시하고, 나머지를 포함한 전체 목록에는 작은 ‘모두 보기’ 진입점을 제공한다. 같은 레슨이 추천 배너와 저장 카드로 중복되지 않게 한다.
2. 저장된 항목이 없으면 기존 서버 추천 카드를 제공한다. 저장 정보가 읽히는 동안이나 일부 조회가 실패해도 계정·레벨 경계를 지키고, 노선과 다른 레슨을 계속 사용할 수 있게 한다. 조회 실패 시 기존 재시도 동작을 유지한다.
3. 전체 보기 시트는 간결한 행과 학습 단계·안전한 진입 동작을 제공한다. 시트는 선택 결과만 반환하고, 닫힌 뒤 부모에서 레슨을 연다. 계정/레벨 변경·연속 탭·오래된 callback의 기존 방어를 유지한다.
4. 선택형 마지막 학습 시각을 체크포인트 최상위 메타데이터로 추가한다. 콘텐츠 서명·서버 진도 지문·답안·셔플/매칭/배열 순서·체크포인트 버전과 계정별 저장 키는 유지한다. 인증 저장소를 건드리지 않는다.
5. 최근 학습은 유효한 카드/단계 이동·선택/답안 등 실제 학습 상태 변화와 연습 시작 시각이다. 단순 목록 조회·복원 초기화·flush/화면 이탈·백그라운드 저장으로 갱신하지 않는다. 같은 위치나 같은 선택을 다시 전달한 no-op도 최근 학습으로 만들지 않는다.
6. 최신 유효 시각을 먼저 정렬하고, 같은 시각 또는 시각이 없는 이전 데이터는 기존 학습 순서로 안정적으로 정렬한다. 시각 누락·형식 오류·범위 오류는 정렬 정보만 없는 것으로 처리하고 정상 위치/답안을 무효화하지 않는다. 이전 데이터를 읽었다는 이유만으로 마이그레이션 쓰기를 하지 않는다.
7. 실제 학습 시점의 시각은 저장 실패 뒤 재시도에서도 유지한다. 제출 대기/알 수 없는 형식의 raw 체크포인트 보호를 유지하며, 확인용 항목을 일반 이어하기나 확정 진행률로 표시하지 않는다. 시각 필드만으로 기존 512×1024 문자열 길이 상한을 넘는 경우에는 선택형 시각만 생략해 위치·답안 저장을 우선한다. 기존 상한은 올리지 않는다.

로컬 메타데이터는 기기 시계를 사용한다. 기기 간 동기화나 서버의 학습 시각을 제공하는 기능으로 표현하지 않는다. 기존 기록의 알 수 없는 시각을 추정하거나 과거 기록을 일괄 재작성하지 않는다.

## 검증 계획

- 수정 전 실패를 재현하는 테스트 후 좁은 범위부터 검증하고, 최종 전체 모바일 format/analyze/test를 실행한다.
- 새 데이터의 최근순·동률·레거시 fallback, 목록의 대표 카드 한 개·추천 중복 제거·모든 항목 접근, 로딩/실패/재시도를 검증한다.
- 기존 시각 없는 체크포인트의 단계·위치·답안·선택·배열 복원, 시각만 잘못된 데이터의 정상 복원, 저장 실패/재시도와 재실행 후 순서 보존을 검증한다.
- 제출 완료 정리·제출 대기/손상 기록 보호·계정/레벨 전환·오래된 callback·중복 탭과 시트 후 부모 내비게이션 회귀를 유지한다.
- 작은 화면·큰 글자·다크 모드에서 카드와 목록의 읽기/탭 영역을 점검하고 실제 Flutter 위젯을 합성 데이터로 렌더링한다. 사용자 기기 데이터와 계정을 사용하지 않으며, 네이티브 앱의 설치·실기기 UAT와 구분한다.
- 공개 API·서버/DB·권한·RLS·Data API·로그인 모듈·의존성/환경변수 변경이 없는지 diff로 확인한다. 기존 다른 미커밋 작업을 이 PR에 포함하지 않는다.

## 보존과 롤백

기존 저장 위치와 답안의 복원은 기존 검증을 그대로 거친다. 신규 시각 필드는 이전 앱에서 알 수 없는 메타데이터로 무시할 수 있도록 하고 버전을 올리지 않는다. 기능 원복은 모바일 소스 commit을 revert하는 것으로 분리한다. 저장 데이터를 삭제하거나 DB 이력을 되돌릴 필요가 없는 설계다.

## 실행 상태

구현·회귀·독립 검토와 실제 Flutter 위젯 렌더링 검증을 완료했다. 모바일 소스 8개·테스트 4개가 변경됐으며, API·DB·환경변수·의존성·인증 모듈은 변경하지 않았다. 이번 작업의 운영 API/DB·클라우드 설정 쓰기와 사용자 기기 설치·로그아웃·초기화는 없다.

백엔드 호환성 읽기 전용 검토에서 API·DB·환경변수 변경이 필요하지 않음을 확인했다. 기존 챕터/상세 GET, 본문 없는 시작 POST, `answers`만 전송하는 제출 POST를 유지한다. 시각은 서버 요청 모델과 레슨 콘텐츠 모델에 추가하지 않는다.

독립 검토에서 추천 fallback의 오래된 callback이 위젯 상태 재사용과 레벨 변경 뒤 다른 레벨 레슨을 열 수 있음을 발견했다. 실제 target의 챕터 레벨을 표시·진입·await 이후에 검증하는 조건을 보완하고, 위젯과 설정 모두 N4로 바뀐 뒤 이전 N5 callback을 호출하는 회귀를 추가한다. 기존 추천/노선의 의미나 인증 모듈은 변경하지 않는다.

UI 검토에서 새 전체 보기 버튼의 기본 primary 글자색은 밝은 배경의 작은 텍스트 대비가 부족함을 확인했다. 기존 테마의 `onSurface`를 해당 버튼에만 명시하고 밝은·어두운 모드 대비를 회귀로 보강한다. 앱 전체 색상 토큰이나 다른 화면의 테마는 수정하지 않는다.

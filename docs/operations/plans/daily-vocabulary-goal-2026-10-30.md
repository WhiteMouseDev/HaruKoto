# 홈 단어 카드의 오늘 목표 진행률

작성일: 2026-10-30 KST. 사용자는 N5 숙련도 대신 오늘 단어 목표 달성률을 보여주는 개선을 승인했다. 기존 단어 수/XP 집계와 별도로 정확한 오늘 단어 수 API를 추가하는 범위다. 운영 배포·DB/권한·환경 변경은 이 구현 작업에 포함하지 않는다.

## 문제와 표시 원칙

현재 단어 카드의 원형 링은 미완료 퀴즈가 있으면 해당 퀴즈의 저장 답안 비율, 없으면 선택 레벨의 누적 숙련도를 표시한다. 바로 옆의 하루 목표와 기준이 달라 오늘 얼마나 학습했는지 해석하기 어렵다.

단어 탭의 링은 **오늘 목표** 한 가지 의미로 고정한다. 오늘 8개를 풀고 목표가 20개라면 `8/20개`, `40%`, 남은 12개를 표시한다. 목표를 넘으면 실제 수치는 `24/20개`로 남기되 링은 100%로 제한한다. 목표 달성은 차분한 문구로 알리고 기존 학습 진입은 유지한다.

미완료 퀴즈의 `이번 퀴즈 3/20문제 저장됨`과 이어 풀기 진입은 별도 정보로 보존한다. 목표 편집은 미완료 퀴즈가 있어도 사용할 수 있게 한다. 문법·문장 탭의 지표, N5 숙련도 데이터와 통계는 이번 변경에서 바꾸지 않는다.

## 오늘 단어 수의 정의

- 단어 퀴즈 및 단어 오답 복습의 저장된 답안을 대상으로 한다. 일반·스마트·복습과 진행 중/완료 세션을 구분해 제외하지 않는다.
- 정답과 오답을 모두 인정한다. 같은 단어 ID는 여러 세션에서 풀어도 한국 기준 하루에 한 번만 센다.
- 인증된 계정의 `VOCABULARY` 세션과 `VOCABULARY` 답안만 포함한다. JLPT 레벨을 바꾸더라도 사용자 하루 목표의 수치는 유지한다.
- 답안 저장 시각이 한국 날짜의 자정 이상, 다음 자정 미만인 항목을 센다. 퀴즈 완료일로 하루를 옮기지 않는다.
- 문법·가나·한자·듣기·문장 퀴즈와 레슨 카드 열람은 이 지표에 포함하지 않는다. 레슨까지 포함하려면 별도 학습 이벤트 정의가 필요하다.
- 기존 `wordsStudied`는 완료 퀴즈의 정답 누적, `goalProgress`는 XP 기반이므로 재사용하거나 의미를 바꾸지 않는다.

## 공개 API 계약과 호환성

`GET /api/v1/stats/dashboard`의 200 응답에 다음 객체만 추가한다. 요청·인증·오류 계약과 다른 경로는 유지한다.

```json
{
  "today": {
    "vocabularyGoal": {
      "date": "2026-10-30",
      "answeredCount": 8
    }
  }
}
```

- `date`: 이 집계를 계산한 KST 날짜, `YYYY-MM-DD`.
- `answeredCount`: 해당 날짜의 고유 단어 수, 0 이상의 정수.
- 새 서버는 객체를 항상 반환한다. 위 예시는 추가 부분만 나타내며 기존 `today` 필드를 제거하지 않는다.
- 모바일은 새 객체가 없는 구 서버, 잘못된 값, 날짜가 지난 응답, 조회 중/실패 상태를 알 수 없음으로 표시한다. 이를 0%로 만들거나 XP·누적 숙련도로 대체하지 않는다.
- 목표값은 기존 사용자 설정을 사용한다. 0 이하 목표는 안전하게 처리한다. 목표 편집의 취소·실패 시 복원 정책을 보존한다.
- 미완료 퀴즈 조회의 실패가 유효한 오늘 목표 표시까지 지우지 않게 한다. 퀴즈 이어하기 자체는 기존 오류·재시도 보호를 유지한다.

### 별도 승인한 단어 추천 정합성

기존 `GET /api/v1/quiz/smart-preview`는 모든 종류의 답안 행 수를 `todayCompleted`로 사용했다. 문법 10문제를 풀었을 때 단어 목표는 0/10인데 단어 추천이 1문제만 나올 수 있었다. 사용자에게 기존 필드의 의미 변경을 구체적으로 제시한 뒤 2026-10-30 **‘추천대로 함께 수정’** 승인을 받았다.

`category=VOCABULARY`의 `todayCompleted`만 위의 KST 고유 단어 수와 동일하게 계산하고, 추천 배분의 입력을 남은 목표 수로 맞춘다. 응답 구조와 문법 카테고리의 기존 계산은 유지한다. 복습 기한·풀 선택 정책·분배 알고리즘을 바꾸지 않으며, 목표 달성 후 기존 추가 학습 진입도 유지한다. 모바일에서는 KST 날짜와 목표 변경 뒤 단어 미리보기를 새로 조회한다.

## 구현과 검증 순서

1. Backend: 기존 답안·세션의 사용자/타입/날짜 범위를 이용한 읽기 전용 집계, 명시적 Pydantic 응답, OpenAPI와 계약 회귀.
2. Mobile: 새 객체의 구 응답 지원 파싱, 오늘 목표와 퀴즈 진행의 분리, 답안 저장 후 홈 복귀 시 새 집계 조회.
3. Shared: 최신 OpenAPI에서 TS 타입 재생성, 기존 경로·오답 복습 계약 보존, 직접 소비자 호환성 검증.
4. Root: 실제 PostgreSQL 필수 사례의 CI 실행/skip 방지, 문서와 독립 검토, 검토 가능한 PR.

회귀 검사는 사용자 경계, 정오답, 반복 단어/재전송, 진행 중 세션, 제외 카테고리, KST 자정 양끝과 전날 시작한 퀴즈를 포함한다. 과거 naive UTC와 timezone-aware 답안 저장 타입도 실제 PostgreSQL에서 확인한다. 모바일에서는 0·일부·달성·초과, 구 응답·실패·지난 날짜·계정 변경·목표 편집·이어 풀기·작은 화면을 검사한다.

기존 로그인·학습 기록·복습 기한·XP·연속일·달력·음원 캐시·Kenzo/Shizuka 설정과 Data API 차단을 유지한다. 새 집계는 저장된 답안을 읽으며 기존 데이터를 보정하거나 새 테이블에 기록하지 않는다. DB 인덱스 등 추가 변경이 필요하다고 확인되면 별도 구체안과 승인 없이 적용하지 않는다.

## 롤백과 적용 범위

서버의 추가 객체를 제거한 이전 응답에도 새 앱은 알 수 없음 상태로 동작한다. 앱은 이전 바이너리로 같은 앱 위에 업데이트할 수 있다. DB downgrade·기록/음원 삭제·로그아웃이 필요 없다. 이 작업은 소스·회귀 테스트·PR 준비까지이며 운영 서버와 아이폰 반영은 해당 PR 승인 후 별도 검증한다.

API 검사는 환경변수를 비운 합성 설정과 폐기형 로컬 PostgreSQL로 실행했다. admin 빌드는 합성 localhost 설정과 오프라인 폰트 픽스처를 사용했다. 기존 웹 전체 unit test의 7개 실패는 이번 변경과 무관하며 typecheck 성공을 전체 웹 테스트 성공으로 표현하지 않는다.

새 집계의 SQL은 기존 사용자/세션 인덱스를 활용한다. 합성 데이터 200명·3만 세션·30만 답안에서 일반 사용자(100세션·1,000답안)는 두 인덱스를 사용해 0.462ms, 큰 이력 사용자(10,100세션·101,000답안)는 병렬 답안 스캔을 선택해 14.491ms였다. 운영 성능 측정이나 부하 보장은 아니다. epoch 비교는 timestamp 형태 차이를 안전하게 처리하지만 보유 이력이 커질수록 비용이 늘며, 향후 시간 범위 인덱스를 추가하려면 별도 설계·승인이 필요하다. 이번에는 DDL을 추가하지 않았다.

1차 독립 읽기 전용 검토에서는 새 correctness/security finding을 발견하지 못했다. 기존 스마트 미리보기의 전체 답안 행 집계가 새 단어 목표와 다른 P2 정합성 문제는 [별도 결정 항목](../../../.planning/escalations/2026-10-30-vocabulary-preview-goal-alignment.md)에서 사용자 승인 후 범위를 추가했다. 서버는 공개 서비스 `get_vocabulary_goal`을 대시보드와 단어 미리보기에서 공유한다. 기존 4개 PostgreSQL 사례를 확장해 두 API의 값이 날짜·계정별로 같은지 검사했고, 문법의 기존 쿼리와 배분 정책을 보존하는 회귀도 통과했다. 추가 범위의 서버 독립 검토에서도 새 finding은 없었다.

모바일 최종 전체 검사는 **918 passed**, 정적 분석은 문제 0개, Dart 포맷은 577개 파일/변경 0개였다. 새 단어 목표·파싱·홈 상태·저장 후 갱신과 추가 미리보기/시트 검사를 포함한다. 추가 범위의 focused 검사 28개는 KST 자정·계정 변경·늦은 응답, 목표 저장 성공 후 한 번 갱신, 취소·실패 시 요청하지 않음, 최신 추천 대기 중 시작 차단과 오류 재시도, 문법 경로 보존을 검사했다. focused 검사는 전체와 겹치므로 합산하지 않는다.

시각 검토는 합성 데이터의 실제 Flutter 위젯으로 수행했다. 390px·320px와 1.6배 글자, 밝은/어두운 테마의 5개 렌더를 확인했고 시각 변경 후 카드/렌더 검사 14개가 통과했다. 목표 편집은 최소 48dp 터치 영역으로 만들고 좁은 화면의 저장 문구는 의도적으로 두 줄로 나눴다. 어두운 테마의 정답률 글자와 링 트랙도 테마 색을 사용해 보완했다. 실제 계정·서버·기기 캡처로 표현하지 않는다.

최종 독립 검토 중 로컬 목표 20과 최신 서버 목표 30이 다르면 유효한 추천이 있어도 시작이 계속 막히는 P2 조건을 발견해 고쳤다. 단어 시트는 저장 중인 임시 상태 외에는 최신 미리보기의 목표를 사용한다. 22문제 시작과 이미 선택된 서버 목표를 다시 고를 때 불필요한 요청이 없다는 회귀를 추가했고, 수정 후 남은 actionable finding은 없었다.

구현 배경·합성 화면·집계의 의미는 [블로그 초안](../../blog/2026-10-30-daily-word-goal-and-quiz-progress.md)에 남겼다. 문서·이미지 상대 링크의 누락이 없음을 확인했다. 아직 운영 배포·아이폰 설치/실기기 검수는 수행하지 않았다.

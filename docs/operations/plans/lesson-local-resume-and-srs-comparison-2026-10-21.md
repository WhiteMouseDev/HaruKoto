# 레슨의 기기 내 이어하기와 복습 정책 비교 테스트

## 목표와 승인 범위

일본어 입문~N5 학습자가 레슨을 중단하거나 앱을 다시 실행해도 같은 기기에서 학습 단계와 답안을 이어갈 수 있게 한다. 일반 퀴즈의 서버 이어 풀기는 기존 동작을 유지한다. 레슨·퀴즈 복습 정책은 실제 호출 경로를 비교하는 회귀 테스트만 추가한다.

사용자는 두 작업을 승인했고, API·DB 변경이나 기존 복습 기한에 영향을 주는 변경은 적용 전에 구체안을 확인하도록 요청했다. 이번 구현에는 서버 정책·API·DB·기존 학습 기록·Data API·권한·클라우드 설정 변경을 포함하지 않는다. 운영 계정이나 학습 데이터를 검증용으로 수정하지 않는다.

## 구현 계획

1. 기존 의존성과 저장·인증 경계를 사용한 계정별·레슨별 로컬 체크포인트를 설계한다. 접근 토큰이나 인증 세션은 저장하지 않는다.
2. 레슨 단계, 각 단계의 항목 위치, 확정 답안, 현재 선택과 배열 중인 토큰, 매칭 진행 및 섞기 정보를 저장한다. 서버 완료 기록과 레슨 콘텐츠가 바뀌었을 때 안전하게 복원을 거부한다.
3. 화면 재진입·프로세스 재실행·계정 변경·저장 실패·제출 전후를 합성 저장소와 실제 레슨 화면으로 검증한다. 새 학습 시작과 답안 제출은 기존 명시적 사용자 행동에서만 발생한다.
4. 레슨과 퀴즈가 사용하는 실제 SRS 함수에 같은 상태·정오·반응시간·고정 시각을 주는 비교 회귀를 추가한다. 현재 차이를 기록하며, 두 정책이 이미 같다는 잘못된 테스트를 만들거나 정책을 바꾸지 않는다.
5. 각 영역의 좁은 회귀와 전체 검사, 독립 코드 리뷰를 마친 뒤 변경 범위와 제한을 보고한다.

## 로컬 복원의 경계

체크포인트는 같은 앱 설치와 같은 계정에서만 사용한다. 기기 간 동기화와 앱 삭제 후 복원은 이번 범위가 아니다. 콘텐츠의 안정적인 서명과 서버의 기존 진행 정보로 오래된 답안·완료 이후의 임시 상태를 구분한다. 저장을 직렬화해 늦은 쓰기가 최신 상태나 완료 처리를 덮어쓰지 못하게 한다. 저장 실패 시 저장됐다고 표시하지 않고 재시도를 제공한다. 화면 종료와 앱 lifecycle 변경에서 대기 중 저장을 처리하되, OS가 쓰기 완료 전에 강제 종료한 상태까지 보장한다고 표현하지 않는다.

기존 서버 제출은 멱등 키가 없고 같은 요청을 다시 받으면 시도 횟수와 복습 상태를 다시 갱신한다. 따라서 제출 전에 pending 상태를 저장하고, 응답을 확인하지 못한 제출을 복원할 때 자동으로 다시 보내지 않는다. 최신 GET에서 완료·시도 정보가 바뀌었으면 서버 기록을 기준으로 처리하고, 그대로인 경우도 이전 요청이 나중에 반영될 수 있어 안전한 재제출 증거로 삼지 않는다. 확인되지 않은 제출은 답안을 보존한 채 읽기 전용 상태 확인을 제공한다. 멱등 제출과 기기 간 복원은 별도 API·DB 제안 및 승인이 필요하다.

## 회귀 테스트의 완료 기준

- 어휘·문법·이해 체크·매칭·배열의 위치와 미확정 입력이 새 provider/container에서 복원된다.
- 계정 전환·로그아웃·늦은 비동기 응답으로 다른 계정의 상태가 표시되거나 제출되지 않는다.
- 잘못된 형식·버전·콘텐츠 변경·새 서버 완료 기록은 안전하게 처리한다.
- 복원 자체가 start/submit API를 호출하지 않으며, 재시작·중복 탭·자동 skip 경로가 중복 제출을 만들지 않는다.
- 저장 실패·완료 후 삭제 실패·응답 불명 제출에서도 사용자에게 잘못된 저장/완료 상태를 알리지 않는다.
- SRS 비교는 모든 상태, 정답과 오답, 반복 이력, 반응시간 및 날짜 경계를 고정 시각으로 검증하고 현재 차이를 명시한다.

## 검증과 롤백

모바일의 포맷·정적 분석·전체 테스트와 API의 Ruff·테스트를 실행한다. 운영 DB와 클라우드 설정은 변경하지 않는다. 새 로컬 체크포인트만 버전별 이름을 사용하며, 코드 revert 시 기존 로그인·서버 학습 기록에 대한 데이터 보정 없이 이전 앱 동작으로 돌아갈 수 있어야 한다.

최초 로컬 구현 단계: 모바일 체크포인트 구현과 로컬 회귀, SRS 비교 회귀와 API 검증을 완료했다. 별도 오프라인 native QA에서 다섯 학습 유형의 실제 프로세스 종료·재실행 복원을 확인했다. 마지막 안내 문구를 포함한 최종 native 빌드의 업데이트·추가 프로세스 재실행 확인까지 완료했다. 이 최초 단계에서는 PR 병합·서버 배포·실기기 설치를 수행하지 않았다. 이후 사용자 승인에 따른 적용 상태는 아래에 구분한다.

## SRS 비교에서 확인한 기존 동작

비교 회귀는 DB 연결을 사용하지 않고 실제 `srs.process_answer`와 `quiz_answer_progress`의 어휘·문법 갱신 경로에 같은 입력과 UTC 고정 시각을 준다. DB 경계와 시각만 대체해 현재의 차이를 명시한다. 차이가 있다는 사실을 어느 정책의 우월성이나 즉시 통합 필요성으로 해석하지 않는다.

| 비교 조건                               | 현재 레슨 경로                  | 현재 퀴즈 경로                      |
| --------------------------------------- | ------------------------------- | ----------------------------------- |
| 같은 초기 LEARNING 상태에서 정답        | LEARNING, 다음 기한 +3일        | LEARNING, 다음 기한 +1일            |
| 처음 만난 항목을 등록한 뒤 첫 정답      | 레슨 등록을 거쳐 LEARNING, +3일 | PROVISIONAL, +1일                   |
| 같은 초기 LEARNING 상태에서 오답        | 다음 기한 +1일                  | 다음 기한 +10분                     |
| 일부 장기 REVIEW·MASTERED 상태에서 오답 | RELEARNING, +1일                | 이전 간격에 따라 RELEARNING, +2~3일 |

첫 등록의 비교는 레슨의 실제 등록 함수를 거친 경로다. 이미 존재하는 항목을 다시 등록하는 경로는 기존 필드를 보존하는지도 검사한다. 반응시간 임계값, 기록 메타데이터, 같은 날 연속 답안 및 UTC 월·연도 경계에서도 차이를 확인한다. 같은 날의 반복 답안은 현재 두 경로 모두 처리되며, 이를 새 제한 정책으로 바꾸지 않는다.

`apps/api/tests/test_lesson_quiz_srs_comparison.py`의 DB 없는 비교 회귀 90개가 통과했다. API 전체는 900개 통과·기존 admin fixture 스킵 13개, 실제 PostgreSQL 필수 회귀는 85개 모두 스킵 없이 통과했다. Ruff 295개 파일과 mypy 172개 소스도 오류가 없었다. DB 없는 90개와 실제 PostgreSQL 85개는 서로 다른 검증 범위이며 합산해 한 검사 수로 표현하지 않는다.

이번 작업은 현재 동작을 설명하는 비교 테스트다. 복습 기한·이력·점수·XP를 재계산하지 않고, 서버의 SRS 정책·API 계약·DB·Data API·권한·운영 설정을 변경하지 않는다. 검증을 위해 운영 데이터를 조회하거나 수정하지 않았다. 향후 정책 통합이 필요하면 기존 기한에 미칠 영향과 API·DB 변경안을 별도로 검토하고 승인받는다.

## 모바일 구현과 로컬 검증 결과

모바일 전체 657개가 실패 없이 통과했다. 기존 617개와 신규 회귀 40개이며 정적 분석 오류는 0개, 포맷 검사 539개 파일의 변경은 0개다. 저장·복원, 계정·콘텐츠·서버 가드, 미확정 입력과 배치, 직렬 저장·실패 안내 및 응답 불명 제출 경계를 다룬다. 서버 SRS 정책이나 API 계약을 변경한 검증이 아니다.

별도 앱 식별자의 오프라인 native QA는 실제 SharedPreferences를 사용한다. 서버 통신을 차단하고 Supabase 초기화를 실행하지 않으며 두 identity 경계를 합성 값으로 대체했다. 운영 로그인이나 실기기 설치와 분리한 검증이다. 재설치 없이 OS의 실제 terminate→launch를 수행해 다음 상태를 확인했다.

| 학습 유형 | 프로세스 재실행 뒤 복원된 상태                     |
| --------- | -------------------------------------------------- |
| 어휘      | 2/3 위치                                           |
| 문법      | 2/2 위치                                           |
| 이해 체크 | 2/2 위치, 현재 선택 d와 앞서 확정한 답안           |
| 매칭      | 맞춘 한 쌍, 현재 왼쪽 선택 및 양쪽 배열 순서       |
| 배열      | 중복된 は 두 개를 포함한 2/3 입력과 남은 보기 순서 |

QA의 합성 시작 요청은 한 번, 제출 요청은 0번이었다. 이 결과를 실제 서버 학습 저장이나 운영 계정 재로그인 확인으로 확대하지 않는다. 앱 재실행은 hot reload와 구분하며, 쓰기 완료 전에 OS가 종료한 모든 경우를 보장하는 검사는 아니다.

마지막 기존 사용자 안내 문구 한 줄을 반영한 최종 native 빌드를 같은 QA 앱에 업데이트하고 배열의 は 두 개·2/3 입력·남은 보기 순서 보존을 다시 확인했다. 21:35:40 KST의 추가 OS 종료·재실행 뒤에도 같았다. 앞선 어휘·문법·이해 체크·매칭 네 유형은 이 안내 한 줄 수정 전의 동일 복원 로직으로 검증했고, 최종 빌드에서는 배열을 재확인한 결과다. 최종 소스 스냅샷의 lib 398개 파일을 기준으로 산출물을 확인했다. 다섯 유형 모두를 마지막 산출물에서 새로 반복한 것으로 확대하지 않는다.

앞선 로컬 구현 검증에서는 운영 데이터 조회·쓰기, 실제 운영 Auth·Data API 설정 변경, 서버 배포와 아이폰 실기기 설치를 하지 않았다. SRS 비교는 현재 동작을 기록할 뿐 기존 기한·이력·API·DB를 변경하지 않는다. API 멱등성 추가와 기기 간 복원은 이번 구현과 구분해 향후 별도 설계로 다룬다.

# 가나 학습의 저장 확인·실패 재시도와 첫 챕터 검수 준비

2026-11-04 KST. 기준 main은 PR #229가 병합된 `3bc22f36d4b33a4b9f425f7fcb6153d60afc1456`이다. 사용자는 가나 저장 실패·재시도 개선과 회귀 테스트, 시뮬레이터 검증 및 N5 첫 챕터 전문 검수 자료 준비를 승인했다. 운영 적용은 포함하지 않으며 결과를 먼저 보고한다. API·DB 변경은 필요할 경우 구체안을 먼저 확인한다.

## 확인한 문제

실제 라우터가 여는 `KanaStagePage`와 `KanaQuizPage`는 답안 요청 실패를 무시하고 로컬 답안을 추가한 뒤 다음 문항으로 이동했다. 가나 시작 API는 정답을 응답에서 제외하므로, 서버 판정이 오지 않은 상태의 기본 false가 오답처럼 표시될 수 있었다. 단계 화면은 퀴즈 완료 실패 뒤에도 단계 완료를 기다리지 않고 진행했으며, 별도 퀴즈 화면은 완료 실패 시 결과 복구 없이 가나 홈으로 이동했다. 시작 실패를 단계 완료 화면으로 보내는 경로도 있었다.

PR #217의 서버 완료 원자성·중복 보상 방지와 모바일 계정별 목표는 기존 기능이다. 이번에는 활성 모바일 화면에서 서버의 저장 확인을 기다리는 경계를 보완한다. 이 소스 분석만으로 기존 사용자의 기록이 실제로 손상됐다고 판단하지 않는다.

## 기존 계약으로 구현할 범위

백엔드 담당자가 현재 API와 PostgreSQL 회귀 소스를 읽기 전용으로 대조했다. 이번 모바일 개선에 API·DB 변경은 필요하지 않다.

| 경로           | 현재 의미                                                        | 모바일 처리                                                           |
| -------------- | ---------------------------------------------------------------- | --------------------------------------------------------------------- |
| 가나 시작      | 요청마다 새 세션. 정답 ID 제외                                   | 실패·빈 응답을 성공 완료로 표현하지 않고 명시적 재시도 제공           |
| 신규 가나 답안 | 같은 사용자·세션·문항·선택 재전송은 원래 판정 반환, 변경 선택409 | 저장 확인 전 판정·문항 이동 금지, 실패한 동일 선택·세션 유지          |
| 신규 퀴즈 완료 | 미저장 답안409. 완료 재전송은 정확도와 추가 XP0 반환             | 성공 확인 전 완료·단계 완료 금지. 서버 정확도를 사용                  |
| 단계 완료      | 최초 완료만 보상·해제, 재전송은 첫 점수·시각 보존                | await 후 성공 표시. 퀴즈 완료 성공 이후 단계만 실패하면 단계만 재시도 |

답안의 재전송 보장은 현재 앱이 새로 시작하는 태그된 세션의 계약이다. 오래된 비태그 세션을 새 정책으로 백필하거나 보장 범위를 확대하지 않는다. 시작 요청은 멱등 키가 없으므로 응답 유실 뒤 사용자의 명시적 재시도가 답안 없는 다른 세션을 만들 수 있다. 같은 시작 세션 복원을 보장한다고 표현하거나 자동 재시도를 추가하지 않는다.

완료 재전송의 `xpEarned: 0`은 추가 지급이 없다는 뜻이며 최초 보상0의 증거가 아니다. 응답이 불명확했던 완료를 다시 확인했을 때는 최초 보상액을 만들어 표시하지 않고 저장 확인 문구로 구분한다. 서버 응답을 근거로 한 점수·상태만 사용한다.

서버의 단계 완료는 특정 퀴즈의 성공과 연결을 검증하지 않는다. 이 관계를 서버에서 강제하는 API·구 클라이언트·기존 세션 정책은 이번 범위 밖이며, 필요하면 별도 구체안을 먼저 제시한다.

## 화면 상태와 보존

- 시작·답안 저장·퀴즈 완료·단계 완료의 로딩과 오류를 구분한다. 응답을 기다리는 동안 중복 탭을 막고 실패 뒤 같은 동작을 재시도한다.
- 답안 저장 실패에서 문항·선택·세션을 유지한다. 통신 오류를 정오 판정으로 바꾸거나 타이머로 다음 문항에 보내지 않는다.
- 성공한 퀴즈 완료 응답을 보존해 단계 저장만 다시 시도한다. 부분 실패를 이유로 답안이나 퀴즈 전체를 다시 제출하지 않는다.
- 화면 진입 계정과 현재 계정을 요청 전후 확인한다. 늦은 응답·타이머·화면 종료·계정 전환은 이전 화면을 진행시키거나 새 계정의 대시보드를 갱신하지 않는다.
- 한국어 오류는 기존 `ApiException.userMessage` 경계를 사용한다. 새 인증 저장·키·의존성·환경 계약·플랫폼 설정은 추가하지 않는다.
- 저장 확인은 HTTP200만으로 확정하지 않는다. 필요한 기존 정오·정답 ID·완료 정보가 없거나 `success:false`인 응답은 오류로 남겨 같은 작업을 재시도한다.
- 기존 인증 인터셉터의401 자동 갱신은 현재 계정의 토큰으로 재전송할 수 있다. 계정에 민감한 가나 쓰기는 기존 요청별 소유자 확인·자동 재전송 제외 패턴으로 보호하고, 다른 기능의 전역 인증 정책은 바꾸지 않는다.

기존 로그인·학습 기록·복습 기한·오늘 단어 목표·음원·Data API 차단은 보존한다. 이 작업은 새 학습일 정책이나 완료 보상·SRS 정책 변경이 아니다. 기존 기록의 백필·삭제·재채점은 하지 않는다.

### 문자카드 진도는 별도 계약 필요

인트로·연습의 `POST /kana/progress`는 같은 요청에도 횟수를 누적한다. 응답 유실 뒤 재시도 버튼을 추가하면 이미 저장된 기록을 중복 집계할 수 있어 이번 수정에서 재전송하지 않는다. 기존 카드 이동은 유지하고 실패 안내·계정/자동 재전송 보호만 보완한다. 카드 저장 확인 뒤 이동·앱 재실행 재시도까지 보장하려면 [새 접수 API와 기존 영수증 CHECK 확장안](kana-card-progress-retry-contract-proposal-2026-11-04.md)을 별도로 승인받아야 한다. 이 안은 미구현이며 현재 API·DB는 변경하지 않았다.

## 검증 계획

1. 두 활성 가나 화면을 실제로 렌더링하는 회귀를 추가한다. 시작 실패/빈 결과, 답안 실패/응답 유실 후 동일 요청, 완료 실패·단계 실패와 재시도, 중복 탭·계정 변경·늦은 응답·dispose를 검증한다.
2. 서버 저장 확인 전 정오 표시·다음 문제·완료 화면·단계 완료 요청이 발생하지 않는지 요청 이력으로 확인한다. 성공한 퀴즈 완료를 단계 재시도 때문에 반복하지 않는지 검사한다.
3. 기존 환경 정의와 Flutter3.41.3·잠금 파일을 사용해 좁은 회귀, 전체 모바일 테스트, 정적 분석·포맷을 실행한다.
4. 운영 인증·소켓을 차단한 전용 네이티브 시뮬레이터에 제품 코드를 그대로 복사해 실패→같은 선택 재시도→완료 확인을 수행한다. 외부 드라이버의 프레임 이후 실제 콜백 실행과 제품 오류를 구분한다.
5. 시뮬레이터의 제품 파일 manifest와 요청 종류·회수·순서, 화면 및 실패/성공 경계를 기록한다. 합성 결과를 실제 운영 DB 보존 검사로 확대하지 않는다.

## 적용·되돌리기 경계

구현·회귀·시뮬레이터 검증과 draft PR을 준비한 뒤 사용자에게 보고한다. PR 병합·서버 배포·운영 설정 변경·아이폰 업데이트는 수행하지 않는다. 모바일 변경만 되돌릴 수 있고 저장 키·기존 로그인·서버 기록·복습 기한을 보정할 필요가 없어야 한다. 가나의 정상 학습 API 호출 자체는 기존 서버 정책에 따라 기록되므로, 운영 계정으로 장애 시나리오를 만들지 않는다.

### 전용 네이티브 시뮬레이터

전용 bundle `com.harukoto.kanaretryqa`에 제품 Dart434개 파일을 그대로 복사하고 root가 고정한 manifest와 대조했다. 별도 합성 환경·로컬 폰트·실제 제품 페이지/완료 서비스/repository·Dio의 메모리 adapter를 사용했다. 정상 운영 Auth를 초기화하지 않고 외부 소켓을 차단했다. 시뮬레이터 빌드와 서명 검사를 통과했다.

- 단계 학습: 시작503→명시적 재시도, 답안503→같은 세션·문항·선택 유지, 응답을 보류한 동안 정오 표시·답안 추가·문항 이동 없음, 저장 확인 후 다음 문항을 확인했다.
- 퀴즈 완료503 동안 단계 요청은0이었다. 퀴즈 저장 확인 뒤 단계503에서 단계만 재시도했고, 퀴즈 완료 요청 수는2회로 유지한 채 단계 요청만1→2회가 됐다. 두 저장 확인 뒤에만 완료 화면이 보였다.
- 별도 가나 퀴즈: 답안 실패/보류 중 같은 문항을 유지했다. 완료503/응답 보류에서도 가나 퀴즈 화면을 유지하고, 저장 확인 뒤에만 결과 화면으로 전환했다. 자기 일관적인 합성2/2 결과의100%·정답2/2·XP12를 확인했다.
- 실제 위젯 콜백15회, 메모리 합성 요청20회(POST18/GET2), 외부 소켓·예상하지 않은 요청·Flutter 오류는0이었다. 합성 POST를 운영 저장으로 표현하거나, fake adapter의 요청 수로 서버의 한 번 반영을 증명하지 않는다.

콜백은 로컬 디버그 VM에서 프레임 이후 실제 제품 위젯의 버튼을 실행했다. 물리 터치 검사는 아니다. 계정 전환·401 재전송 차단과 불완전 응답은 앞선 실제 Dio 회귀, 좁은 화면·글자200%는 위젯 회귀 범위다. 기존 운영 로그인 앱·실기기·운영 API/DB는 사용하지 않았다. 전용 QA 앱과 기기만 종료했다.

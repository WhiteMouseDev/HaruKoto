## 청취 확인 항목

- 원문과 소리의 대응, 앞뒤 잘림·단어 누락·추가. 특히 2번 映画（えいが）와 音楽（おんがく）.
- 映画・本当・旅行・料理의 장음 위치, `りょ`, 音楽의 `ん`, 조사·의문문이 자연스럽고 따라가기 편한지.
- 문장별 재생 중 정지·다시 재생, 전체 듣기 1→2→3→4 순서·완료 표시, 정지 후 다음 문장이 나오지 않는지.
- 다시 듣기는 첫 문장부터 시작하는지, 시트 닫기·레슨 이탈·백그라운드 전환 시 멈추고 복귀 후 자동 재생되지 않는지.
- 기존 로그인과 저장된 레슨명·카드/문제 위치가 유지되는지. 새 검수 동작을 과거 UAT와 합산하지 않고 확인 시점·앱 빌드·레슨·문장 번호를 남긴다.

사용자는 조합을 채택하고 HN5-004의 재생·정지·이어하기·재실행과 이후 전체 듣기의 순서·완료·정지·다시 듣기·시트 닫기·백그라운드 정지를 정상으로 보고했다. 제품 수용과 기능 확인의 근거이며, 전문 일본어 감수나 전체 448개 개별 언어 PASS는 아니다. 전체 검수에서 실제 들은 파일·SHA·검수자·날짜·판정을 명시해야 한다.

## 10월 26일 검수표를 사용하는 방법

[전체 목록과 9개 packet](n5-human-audio-qa-packets-2026-10-26.md)의 448개 원문·구 URL·길이·SHA·PENDING은 당시 증거로 보존한다. 특히 HN5-004의 구음원 네 개를 현재 앱 음원으로 안내하거나 그 판정을 새 파일에 이월하지 않는다. HN5-001 대안의 구 링크도 10월 26일 확인 자료이며, 이번에는 새 HTTP 검사·현재 DB 연결 확인·Kenzo/Shizuka 전환을 주장하지 않는다.

전체 청취 검수는 **최신 대상·음원과 판정의 연결을 먼저 새로 확인한 뒤** 별도 작업으로 진행한다. 최소 한 챕터 전체의 정식 대표 검수, 남은 챕터와 36개 무음 비율 경고의 실제 청취 판정, 미연결 문제 안내 음성의 검수와 앱 재생 범위를 구분해야 한다. 36개는 10월 26일 파일 검사 경고이며 현재 음성의 불량 확정 건수가 아니다.

보고 도구가 챕터별 최신 날짜 packet 하나를 선택하므로 네 문장만 담은 새 `n5-human-audio-qa-ch01-YYYY-MM-DD.md`를 만들지 않았다. 그러면 기존 45개 대상이 네 개로 대체될 수 있다. 이 현재 대표 자료는 발견 glob 밖에 두고 기존 9개·448행을 유지한다. 이후 전체 packet을 새로 만들 때도 최신 전체 대상 수와 SHA를 대조해야 한다. 도구 PR 병합은 음원 전체 공개 승인과 별개다.

## 이번 갱신의 보존·검증 범위

API 계약·DB·음성 캐시·권한/RLS·Data API·운영 설정·사용자 로그인과 학습 기록은 변경하지 않는다. 운영 DB/API 인증 요청·음성 생성·판정 적용·배포·아이폰 설치도 실행하지 않는다. 검증은 공개 네 파일 읽기, 기존 실행 receipt 대조, 합성 환경·격리 로컬 PostgreSQL 회귀와 문서 검사로 제한한다.

최신 main 통합의 회귀·문서 검사 결과는 [검증 이력](n5-audio-qa-refresh-2026-10-26.md)의 10월 28일 절과 [PR #162 checks](https://github.com/WhiteMouseDev/HaruKoto/pull/162/checks)에 기록한다. 과거 909개/85개 결과와 새 결과를 합산하지 않는다.

## 빌드와 로그인 보존

정확한 병합 소스에서 기존 환경 파일을 dart defines로 전달해 iOS Simulator debug 앱을 빌드했다. 생성되지 않은 ignored plugin registrant만 같은 의존성의 생성물로 보완했다. CocoaPods의 tool-version footer 변경은 pod 버전·checksum이 같은지 확인하고 원본 stamp로 복원했다. 추적 모바일 파일 **679개**가 병합 소스와 같고 환경 파일·의존성/lockfile이 변경되지 않았다.

선택한 iPhone 17 Pro 시뮬레이터의 기존 앱 위에 같은 bundle ID로 업데이트했다. 설치 전후 단일 Preferences 파일과 저장 체크포인트가 일치했다. 앱 삭제·초기화·로그아웃·계정 교체는 하지 않았다. 기존 화면은 로그인 선택 화면이었지만 저장된 세션은 API profile 200과 테스트 계정 표식으로 먼저 확인했고, 새 앱은 같은 계정의 로그인을 정상 복원했다. 이를 업데이트 전부터 로그인 홈이 보였다고 서술하지 않는다.

입력 자동화는 로컬 debug VM에 Flutter 도구를 attach해 **실행 중인 앱의 실제 위젯 콜백**을 호출했다. 실제 화면 캡처와 운영 API·DB의 읽기 전용 대조를 함께 사용했다. 답안·provider 상태·저장 위치를 주입하거나 API 응답을 가짜로 바꾸지 않았고, hot reload/restart를 앱 완전 재실행의 증거로 사용하지 않았다. OS 좌표 입력·아이폰 실기기 검증과 구분한다.

## 기존 기록과 운영 설정의 대조

시뮬레이터 시작 전 알려진 QA 계정의 기존 40개 퀴즈·23개 답안과 관련 학습 행을 읽기 전용으로 기록했다. 테스트 계정 표식·API identity 일치를 확인하기 전 DB 읽기는 자동 승인 검토에서 차단됐다. 먼저 GET profile만으로 계정 증거를 확보한 뒤 범위를 고정한 읽기 전용 대조가 허용됐다. 권한 차단을 우회하거나 계정 ID를 추측하지 않았다.

기존 미완료 퀴즈 한 건은 이미 24시간이 지나 있었다. 앱 실행 전에 이 영향을 고지하고, 승인된 정상 앱 검증 범위에서 기존 정책의 `completed_at` 한 건 전환을 별도 집계했다. 원본 문항·정답 수·답안·점수·XP는 그대로였다. 파생 완료 퀴즈 수에는 정상 만료의 영향이 있으므로 전체 profile payload가 완전히 같다고 주장하지 않는다. 직접 SQL update나 정책 수정은 하지 않았다.

새 테스트 활동은 별도로 식별했다. 실제 저장한 서로 다른 단어 ID 2개가 정답 1·오답 1인 것을 확인했고, 서버 helper와 독립적인 Python UTC→KST 변환·집합 계산 결과가 대시보드·단어 미리보기의 **2개**와 같았다. 목표 15일 때 남은 입력 13과 기존 배분 정책의 합계 13도 일치했다. 퀴즈를 완료하지 않아 XP 증가 0은 정상이며, 테스트에 해당하는 두 단어의 SRS 갱신만 구분했다.

배포 직후 기존 N5 대사 캐시 198행·문항 캐시 250행, 총 **448행**은 ID·전체 행 지문이 같았다. N5 레슨 50개와 권한/RLS 카탈로그도 같았다. 익명 Data API HEAD는 **404**이며 실제 앱 계정의 profile·dashboard·history·미리보기 GET은 **200**이었다.

### 시뮬레이터 검증 후 최종 대조

14:12–14:13 KST의 마지막 한 차례 대조에서도 같은 리비전·이미지 digest·트래픽 100%·환경/운영 설정·음성 역할 설정이 유지됐다. 기존 캐시 **448행의 전체 지문과 ID, 레슨 50개, 보안 카탈로그가 동일**했고 캐시 추가·삭제도 없었다. health와 인증 GET은 모두 200, 익명 Data API HEAD는 404였다. 병합 이후부터 14:12:24 KST까지 범위를 제한한 새 리비전 ERROR 로그 조회는 0건이었다. 장래 오류가 없다는 보장은 아니다.

원래 목표 **15 복원**과 독립 집계 **2개**, 두 API의 **2개**, 추천 **13문제**가 마지막에도 일치했다. 새 퀴즈 1개와 답안 2개의 지문은 재실행·목표 변경 전후 같았다. 앱 실행 직후 기준의 기존 40개 퀴즈·23개 답안은 모두 같았고, 기존 일별·레슨·문법 행도 같았다. 정상 테스트 답안에 연결된 SRS 행 두 개만 갱신됐으며 XP 증가 0을 확인했다.

기존 dashboard 필드는 새 객체를 제외하고 같았고 history도 같았다. 문법 미리보기의 `todayCompleted`와 추천량은 기존 전체 답안 집계 방식에 따라 단어 답안 2개 뒤 달라졌으므로 숫자 자체가 고정됐다고 표현하지 않는다. 문법 집계·배분 코드는 변경하지 않았다.

현재 시뮬레이터 계정의 인증 API 기준선은 배포 후에 확보했으므로 이 계정의 구·신 리비전 HTTP 응답을 직접 비교했다고 주장하지 않는다. `last_study_date`·`updated_at`은 별도 전체 열 비교로 보존하지 않았으므로 사용자 행의 모든 열이 불변이라고 확대하지 않는다. 보호한 기존 기록과 정상 테스트 활동의 예상 변경을 구분한 결과다.

## 완료 범위와 롤백

이 기록은 운영 API 배포와 선택한 시뮬레이터의 실제 학습 흐름을 확인한 결과다. 모든 사용자·모든 레슨·모든 음원의 전수 검증이나 아이폰/Android 실기기 검증으로 확대하지 않는다. 개인 화면·토큰·계정 식별자·VM 연결 URI는 저장소에 넣지 않았고, 실제 증거는 private 파일에 보존했다.

롤백은 이전 정상 API 리비전으로 트래픽을 돌리고 필요하면 이전 앱을 같은 앱 위에 설치하는 방식이다. 새 객체 없는 응답도 앱이 지원한다. 정상 학습 기록을 삭제하거나 만료 상태·복습 기한·XP를 임의로 과거 값으로 되돌리지 않는다. [구현 설계·회귀 검증](daily-vocabulary-goal-2026-10-30.md)과 [블로그 초안](../../blog/2026-10-30-daily-word-goal-and-quiz-progress.md)을 함께 참고한다.

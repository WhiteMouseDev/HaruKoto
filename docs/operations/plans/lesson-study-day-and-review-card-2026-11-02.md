# 레슨 학습일 인정 설계와 오늘 복습 카드 개선

## 승인 범위와 구현 순서

2026년 11월 2일 사용자가 레슨 완료의 학습일 인정 **설계**와 모바일 복습 카드 **개선**을 승인했다. 기존 로그인·학습 기록·복습 기한·오늘 단어 목표·Data API 차단은 유지한다. API·DB 변경이 필요하면 적용 전에 구체안을 먼저 제시한다.

기준은 PR #213까지 병합된 main `1986649e`다. 다음 순서로 작업한다.

1. 레슨 완료·퀴즈 완료·달력·연속일의 현재 저장/조회와 동시 실행 경계를 확인한다. 학습일 인정은 구체적인 사전 승인 설계로 남기며 서버 코드·스키마·과거 기록을 변경하지 않는다.
2. 현재 API를 사용하는 모바일 복습 카드에서 조회 실패·조회 중·복습 0개를 구분한다. 실패 시 해당 부분만 재시도하고 다른 레슨은 계속 사용할 수 있게 한다.
3. 단어·문법 각각의 복습 범위와 한 번에 시작할 문항 수를 표시한다. 기존 복습 퀴즈 요청을 사용하고 복습 일정·답안 처리 정책은 변경하지 않는다.
4. 최초 실패/복구·갱신 실패·중복 탭·카테고리 선택·레슨 진입·화면 크기/글자 확대에 대한 회귀와 모바일 전체 검사를 수행한다.
5. 설계안·구현 범위·실제 검증·적용하지 않은 운영 변경을 기록하고 PR로 제출한다. 이번 요청은 운영 배포·아이폰 설치나 DB 마이그레이션 적용 승인이 아니다.

## 실제 구현: 복습의 양과 실행 범위를 같은 약속으로 만들기

기존 카드는 단어+문법 합계를 보여주면서, 버튼은 개수가 더 많은 한 종류만 10문항으로 시작했다. 요약 조회 실패는 `SizedBox.shrink()`로 사라졌고, 갱신 실패에서는 이전 숫자가 남을 여지도 있었다. 정상 0개와 실패를 구분하고 사용자가 고른 종류로 시작하도록 `StudyReviewSection`을 분리했다.

- 초기 조회·재조회 중에는 진행 표시를 보이고 이전 숫자·실행 버튼을 숨긴다.
- 실패하면 `ApiException.userMessage`의 한국어 안내·「다시 확인」·「레슨 학습은 계속할 수 있어요」를 표시한다. 다른 레슨 목록은 독립적으로 정상 작동한다.
- 정상 0개면 「지금 복습할 표현이 없어요」를 표시한다. 기존 `wordNew`·`grammarNew`는 미학습 콘텐츠 수이며 학습 이력이 아니므로 과거 학습 여부로 해석하지 않는다.
- 단어·문법을 각각 선택한다. 예를 들어 단어 12개·문법 2개가 남으면 합계 14개와 함께 「단어 최대 10개 복습」「문법 최대 2개 복습」을 표시한다. 요청 수는 선택한 종류의 `min(남은 개수, 10)`이다. 전체 카드를 누르면 임의의 카테고리로 시작하는 동작은 제거했다.
- 시작 연타는 경로 하나만 열고, 복습에서 돌아오면 해당 레벨의 요약을 다시 조회한다. 계정·레벨 전환 직전의 오래된 콜백과 늦은 이전 계정 응답을 차단한다. 로그인 저장소·토큰·인증 흐름은 변경하지 않는다.

소비하는 계약은 기존 `GET /api/v1/lessons/review/summary?jlptLevel=...`와 `POST /api/v1/quiz/start`의 `mode: review`다. 서버는 이미 요청 count와 해당 카테고리의 현재 due 항목을 지원하므로 새 API·응답 키·DB 변경이 필요하지 않다. 읽은 개수와 시작 시점의 실제 개수는 달라질 수 있어 버튼은 「최대」로 표시한다.

## 독립 리뷰에서 확인한 입문 레벨 연결 문제

복습 요약은 `ABSOLUTE_ZERO`를 N5 콘텐츠로 계산하지만, 기존 카드의 시작 요청은 선택한 레벨을 그대로 보냈다. 서버 enum 자체는 입문 레벨도 허용하지만 복습 콘텐츠 필터에는 N5 변환이 없어 입문 계정이 N5 개수를 보고 빈 퀴즈로 들어갈 수 있었다.

이번에는 **복습 퀴즈를 시작할 콘텐츠 레벨만 `ABSOLUTE_ZERO → N5`로 맞췄다.** 사용자 선택 레벨·설정·요약 캐시·계정 가드·복귀 후 갱신 대상은 유지한다. N4 등 다른 레벨은 그대로 보낸다. 일반·스마트·특수 퀴즈의 공유 시작 함수나 다른 진입점은 수정하지 않았다.

실제 StudyPage에서 단어/문법 버튼이 만드는 `QuizPage`의 입문→N5, N4 유지와 count 2/5를 검사했다. 별도로 N5 캐시를 구독한 상태에서 입문 복습을 끝내면 `ABSOLUTE_ZERO` 요약만 갱신하고 N5 캐시를 건드리지 않는 것도 검사했다.

## 학습일 인정: 구체안만 작성

[레슨 학습일 인정 제안](lesson-study-day-recognition-proposal-2026-11-02.md)에 DB 불리언 한 컬럼, 신규 멱등 제출의 첫 정상 완료만 인정하는 규칙, KST 시각·사용자별 동시 완료·기존 기록 무백필·API 의미 확장과 롤백을 구체화했다. 독립 검토 두 경로에서 기존 영수증만 사용하는 무DDL 대안도 비교했다. 기존 `.planning/escalations/2026-09-29-streak-attendance-marker.md`를 갱신하고 중복 미결 항목은 만들지 않았다.

이 PR에 API 서버 코드·마이그레이션·Prisma·생성 계약 변경은 없다. 사용자 승인 전 서버/API 동작·DB를 변경하지 않는다. 복습 카드 개선은 이 설계안의 채택 여부와 독립적으로 사용할 수 있다.

## 배포와 되돌리기

복습 카드 변경은 모바일 코드만 배포하면 되며 서버 선행 배포가 필요 없다. API/DB·환경·플랫폼·잠금 파일·저장 키를 바꾸지 않았으므로 코드 revert는 저장 데이터 보정 없이 가능하다. 다만 입문 콘텐츠 레벨 보정과 실패 표시까지 되돌아간다는 제품 영향이 있으므로 장애 시 해당 보호를 유지하는 수정 배포를 우선한다. 현재는 PR 준비·검증까지이며 병합·운영 배포·기존 앱 업데이트는 수행하지 않았다.

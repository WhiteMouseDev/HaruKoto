# N5 대화의 화자별 음성 수정안

상태: 제안·결정 대기. 사용자 기능 확인과 소스·공식 문서 조사를 기록하며 코드·설정·DB·음성은 아직 변경하지 않는다.

## 관찰과 확인한 원인

사용자는 기본 재생 네 항목이 정상이라고 보고했지만 두 화자가 동일한 여성 목소리로 들려 어색하다고 했다. 실제 확인한 레슨·문장·기기는 이번 메시지에서 명시되지 않았다. 기능 PASS와 화자 구분 FLAG를 분리하고 448개 문장별 정식 판정은 PENDING으로 둔다.

N5 원본 50레슨·198대사에는 남성 alias 100줄·여성 alias 98줄이 있고 누락·동일 화자의 alias 비일관은 없다. 김은 남성 alias, 다나카는 여성 alias로 설정돼 있다. 이는 voice 선택 메타데이터이며 성씨를 근거로 새 인물 성별을 확정한 결과가 아니다. 원문과 manifest도 198/198 일치한다.

- [콘텐츠 변환 규칙](../content/content-conversion-guide.md): 화자마다 voice_id를 부여한다.
- [resolver](../../../apps/api/app/services/tts_target_resolver.py): text만 읽는다.
- [레슨 TTS 서비스](../../../apps/api/app/services/lesson_script_tts.py): 생성기에 text만 보내고 기존 target/speed/field 캐시를 즉시 반환한다.
- [제공업체 구현](../../../apps/api/app/services/ai_speech.py): ElevenLabs에는 단일 ELEVENLABS_VOICE_ID만 보낸다. generate_tts의 voice 인자는 Gemini 경로에만 전달된다.
- 배치 생성·기존 재생성 도구도 같은 단일 음성 경로를 사용한다. 모델명만 바꾸거나 기존 도구만 다시 실행하면 이 문제는 해결되지 않는다.

## 권장 범위

먼저 콘텐츠의 기존 두 역할을 실제 ElevenLabs 음성에 매핑한다. 일본어로 학습된 두 voice를 같은 인물에 일관되게 사용한다. 단어·가나·문제 안내·채팅의 기본 TTS나 N4의 정책을 전역 변경하지 않는다. N5 대화만 명시적으로 선택한 범위에 적용한다.

제안하는 선택형 설정은 ELEVENLABS_LESSON_FEMALE_VOICE_ID와 ELEVENLABS_LESSON_MALE_VOICE_ID 두 개다. 실제 ID는 계정에서 권한과 사용 조건을 확인해 선택하며 저장소에 설정 값을 기록하지 않는다. 기존 ELEVENLABS_VOICE_ID는 다른 TTS의 기본값으로 유지한다. **새 env 계약과 설정 적용은 사전 결정 대상**이다. 역할 누락·미등록 또는 제공업체 실패를 기본 여성 음성으로 조용히 처리하지 않는다. 승인된 동일 역할 대체 음성이 없으면 명시적인 오류와 재시도를 사용한다.

## 먼저 비교할 샘플

[공식 모델 조사](elevenlabs-model-research-2026-10-26.md)에 따라 대표 HN5-004의 대화 네 줄을 사용한다. 기존 파일은 참고 자료로 남기고, 같은 두 voice의 Multilingual v2 기준 샘플과 Eleven v4 후보를 비교한다. 최신 공식 quickstart는 기존 Text to Speech API에서도 model_id=eleven_v4를 명시하는 예시를 제공한다. 한 줄 비교는 이 경로의 모델·설정·계정 호환 확인부터 시작하고, 전체 문맥의 Text to Dialogue는 별도 실험으로 둔다. 기존 v2 설정 사전을 그대로 재사용하지 않는다. 한 줄용 결과와 대화 전체 결과를 구분한다. 공식 문서의 개선 주장을 실제 일본어 품질 승인으로 처리하지 않는다.

새 샘플 생성은 외부 유료 API 호출과 새 GCS 객체를 만들므로 실제 모델·voice·문자 수·반복 수·비용 상한을 확정한 뒤 별도로 실행한다. 이 제안은 네 줄의 비교 준비까지이며 전체 198줄이나 문제 안내 250개를 재생성하는 승인이 아니다. 이번 조사에서는 유료 생성·직접 청취·외부 계정 API 호출을 하지 않았다.

## 캐시 교체와 보존

스키마·공개 API 요청/응답 변경 없이 우선 설계할 수 있다. 기존 target_id·field·speed는 유지하고 원문·논리 voice·실제 voice·제공업체·모델·설정·정책 버전으로 지문을 만들어 새 객체 경로와 생성 manifest에 남긴다. 기존 GCS 파일은 덮어쓰거나 지우지 않는다. 운영 캐시가 legacy라는 이유만으로 198개를 한꺼번에 cache miss로 바꾸거나 첫 재생에서 자동 유료 생성하지 않는다.

샘플 청취와 운영 반영 결정 뒤에만 지정된 네 개 tts_audio 행의 URL·provider·model을 조건부 교체한다. 이전 행의 식별·텍스트·URL·메타데이터는 private 백업으로 보존하고 원문·역할·기존 행 지문이 계획과 같은지 확인한다. 정확히 네 행이 아니거나 다른 변경이 있으면 트랜잭션을 롤백한다. 복원도 새 URL·행 지문을 확인한 뒤 보관한 값으로 조건부 수행한다. **이 콘텐츠 캐시 DML의 실제 대상·이전/신규 값·검증·롤백안은 적용 전에 다시 제시한다.** 학습·답안·진도·기한·권한·Data API는 변경 대상이 아니다.

문장별 tts_audio URL 교체는 lesson content signature에 영향을 주지 않는다. 반면 reading.audioUrl이나 content의 voice_id를 바꾸면 모바일 체크포인트 서명이 달라져 저장된 레슨 이어하기가 거절될 수 있다. 전체 듣기 도입은 별도 호환 검토 없이 적용하지 않는다. 모바일 URL 메모리 캐시 때문에 교체 후 앱 완전 종료·재실행도 확인해야 한다.

## 구현 후 필요한 회귀

역할별 실제 ElevenLabs voice 인자, 같은 화자 일관성, 누락·알 수 없는 역할, fallback의 역할 보존과 오류, 구/신 캐시 정책, 기존 다른 TTS 기본값, 네 행 조건부 교체·변경 감지 롤백, 기존 레슨 체크포인트 복원을 확인한다. 이번 문서는 수정안이며 해당 구현·검증을 완료했다는 기록이 아니다.

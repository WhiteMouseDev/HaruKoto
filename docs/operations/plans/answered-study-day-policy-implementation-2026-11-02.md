# 한 문항 학습일 인정 구현·격리 검증

## 승인과 작업 범위

2026년 11월 2일 사용자가 [구체안](answered-study-day-policy-proposal-2026-11-02.md)의 일별 `activity_recorded`, 비공개 `study_activity_receipts`, 레슨 활동 POST/GET·선택적 응답 필드와 기존 퀴즈 답안 연결을 승인했다. 승인 범위는 **구현·회귀·시뮬레이터 검증**이며 운영 DB·클라우드 설정·병합/배포·실기기 설치는 제외한다. 기존 로그인·학습 기록·기한·오늘 단어 목표·음원·권한/RLS·Data API 차단을 유지하고 과거 백필은 하지 않는다.

직전 `659aac68`은 문구·설계 기록 커밋이다. 그 시점의 위젯 21개와 이전 완료 기준 API 1,258개 검증을 새 한 문항 기능의 검증 수로 재사용하지 않는다. PR #215는 호환 OFF 구현, #216은 이를 기준으로 API·웹의 두 소스 플래그를 켜는 활성화 draft로 갱신한다. 두 PR 모두 이번 작업에서 병합하거나 운영에 배포하지 않는다.

## 구현 순서

1. backend-agent가 미적용 p6를 generic 마커와 영수증 테이블로 수정한다. 기존 ACL·서비스 역할·RLS·Data API를 보존하고 파괴적 downgrade를 차단한다. 새 API와 OpenAPI를 먼저 발행한다.
2. API의 첫 퀴즈 답안·새 가나 첫 응답과 출석을 원자화한다. 레슨의 개별 출석 접수는 기존 최종 채점·SRS와 분리하고 이전 완료 훅을 제거한다. source gate는 OFF를 기본으로 둔다.
3. web-agent가 자체 Prisma 답안 경로에 첫 출석만 중복 방지하도록 연결한다. 기존 웹 매칭의 오답→정답 재도전 효과와 지원 세션 형식 경계를 보존한다. hasStudied 투영/표시·저장 성공 후 갱신을 맞춘다.
4. mobile-agent가 새 선택 필드·활동 저장/조회와 계정별 영속 outbox를 구현한다. 기존 v1/v2 체크포인트·답안을 보존하고 복원 자체가 이벤트를 생성하지 않도록 한다. 화면 이탈·최종 제출 정리·재실행에도 같은 ID를 유지한다.
5. shared-packages-agent가 승인 Alembic을 적용한 별도 로컬 DB에서 Prisma를 동기화하고 OpenAPI 생성 타입·직접 소비자 검증을 맡는다. packages가 DDL을 소유하지 않는다.
6. 실제 PostgreSQL·API·웹·모바일 회귀와 엄격한 JUnit gate를 확인한다. 별도 합성 계정/로컬 서명 인증/FastAPI/PostgreSQL/전용 시뮬레이터에서 새 답변·실패·응답 유실·완전 재실행을 확인한다. 기존 기기·계정·운영 데이터에는 접근하지 않는다.
7. 검증·한계·운영 마이그레이션/호환 배포/구 writer 종료/활성화·보존 롤백안을 보고한다. 새 운영 적용은 별도 승인을 받는다.

## 최종 구현

- **인정 경계:** 정오와 관계없이 서버가 처음 저장한 유효 답안이다. 단순 진입·카드 이동·이전 위치 복원은 새 인정을 만들지 않는다. 일별 마커와 연속일은 같은 트랜잭션에 저장한다. 첫 오프라인 전달은 서버가 처리한 KST 날짜를 쓰며 재전송은 원래 날짜를 유지한다.
- **독립 지표:** 레슨의 개별 활동 접수는 최종 채점·XP·SRS·단어 목표를 실행하지 않는다. 정식 퀴즈 답안의 기존 SRS 효과와 오늘 단어 목표는 기존 정책을 따른다. 레슨 전체 완료의 조건과 제출 영수증은 그대로다.
- **유효성·호환:** 레슨 선택지·문항·배열 토큰/허용 방해 토큰·매칭 어휘와 콘텐츠 버전을 검증한다. 일반 퀴즈의 기존 정답/오답 sentinel과 웹 매칭의 오답 뒤 정답 재도전 정책은 보존한다. 웹의 기존 답안/SRS 전체를 멱등화한 변경은 아니다. 새 가나 세션만 내부 버전 태그와 첫 답안 영수증을 사용하고 구 세션을 백필하지 않는다.
- **모바일 저장:** 기존 v1/v2 체크포인트 바이트를 보존하는 v3 원자적 저장 래퍼에 attempt ID와 고정 활동 outbox를 함께 둔다. 네트워크 전에 기록하고, 같은 계정·같은 ID·같은 payload로 조회/재전송한다. GET 404만으로 새 ID를 발급하지 않는다. 하나의 실패가 다른 레슨을 막지 않으며 완료 정리 뒤에도 미확인 활동을 보존한다.
- **이탈 경합:** 문장 배열의 ‘확인’ 순간 활동을 동기적으로 고정한다. 300ms 화면 전환을 기다리다 X로 나가면 이벤트가 사라지던 경합을 실제 라우트 회귀로 수정했다. 자동 복원과 ‘다음’은 두 번째 활동을 생성하지 않는다.
- **잠금:** 관련 API·웹 writer는 사용자 → 세션/도메인 → 일별 기록 순서로 잠근다. 사용자 잠금을 기다린 뒤 최신 보상·활동 값을 다시 읽고 처리 시각을 정한다. 영수증/연속일의 기존 밀리초 시각은 자정 반올림을 피하도록 동일한 내림 시각을 쓴다.
- **보안:** 기존 owner·테이블/컬럼 ACL·신뢰된 service_role 권한·RLS·기본 권한을 보존한다. 새 영수증은 RLS가 켜진 비공개 테이블로 직접 클라이언트 권한/정책을 만들지 않는다. Data API와 DDL 보호 설정을 바꾸지 않는다.

같은 날 사용자는 [주간 저장 단어 집계](weekly-saved-vocabulary-stats-proposal-2026-11-02.md)도 승인했다. `weeklyStats[].vocabularyAnsweredCount?: number | null`은 사용자 소유 단어 세션·단어 답안의 KST 날짜별 고유 문항 수를 한 번의 GROUP BY로 읽는다. 오답·미완료 퀴즈를 포함한다. 기존 `wordsStudied`·XP와 DB 행을 변경하지 않는다. 최근 과거 그래프는 달라질 수 있지만 출석/연속일 백필은 아니다. 모바일/API 최근 7일과 웹 월~일 범위는 각각 유지했다. 구 응답 누락/null은 완료 기준으로 명시해 호환하며, 활동만 있고 단어 0개인 날은 점으로 표시한다.

## 운영에 적용하기 전 구체안

**아직 실행하지 않았다.** 새 코드의 ORM은 OFF여도 새 컬럼을 읽으므로 p6 마이그레이션이 먼저 필요하다. 또한 OFF는 잠금 순서를 예전 것으로 돌리지 않는다. 구 writer의 세션 → 사용자 잠금과 새 writer의 사용자 → 세션 잠금이 겹치면 교착 위험이 있어, 호환 OFF 배포 전부터 혼용을 통제해야 한다.

1. 별도 승인 전 읽기 전용으로 실제 DB head/마이그레이션 checksum, 기존 학습·기한·음원·권한/RLS·Data API 차단, Cloud Run revision과 Vercel 운영/이전 배포 접근 경로를 인벤토리한다. 현재 p6가 운영 미적용이라는 전제를 확인하지 못하면 같은 revision을 덮어쓰지 않는다.
2. 사용자에게 대상·예상 영향·재개 기준을 명시한 **학습 쓰기 일시 중지와 기존 writer 종료 확인 방식**을 먼저 제시한다. 현재 이 작업에 새 유지보수 기능·환경 변수·클라우드 접근 제어를 추가하지 않았다. 구 Vercel 배포 URL도 운영 DB 쓰기를 새로 시작하지 못하도록 구체 보호/퇴역안을 승인받아야 한다.
3. 승인된 통제로 새 구형 쓰기 진입을 막고, API·웹의 이미 실행 중인 쓰기와 DB 트랜잭션이 종료됐음을 실제로 확인한다. Cloud Run 트래픽 100% 전환·고정 sleep·504·로그 부재만을 drain 증거로 쓰지 않는다. 확인할 수 없으면 진행하지 않는다.
4. 검토된 p6를 잠금 2초/문장 15초 제한으로 적용한다. 락 경합·카탈로그/권한 전제 불일치는 원자적으로 실패시킨다. 이전 행은 false, 영수증은 비어 있고 원본 학습·보상·기한·음원은 유지돼야 한다. 보안/파티션 읽기 검사를 다시 실행한다.
5. 같은 쓰기 통제하에 API·웹 호환 OFF 버전을 배포한다. 새로운 코드만 쓰기를 처리할 수 있고 이전 배포/잔존 프로세스가 다시 writer가 되지 못함을 확인한 후 통제 해제를 검토한다. 새 앱은 capability가 없으면 기존 레슨 기능을 계속 사용한다.
6. API·웹 두 소스 플래그를 켜는 작은 활성화 PR을 배포한다. 새 계정의 한 답안·오답·재전송·서버 저장 후 응답 유실·KST 날짜·운영 로그인/학습/이어하기·주간 1개와 기존 기록 보존을 따로 확인한다. 모바일은 새 프로토콜을 지원하는 빌드로 반영한다.
7. 오류율·잠금 대기/교착·활동 접수 실패와 pending 복구·중복 여부를 확인한다. 무중단이나 운영 로그인 검증을 로컬 결과만으로 보장하지 않는다.

### 보존 롤백

새 학습일 인정만 중지할 때는 **새 스키마와 영수증 조회를 이해하는 호환 OFF API·웹**으로 전환한다. 새 영수증 POST는 막고 기존 영수증 GET과 체크포인트·pending을 보존한다. 구 writer로의 단순 되돌리기는 잠금 순서를 다시 혼용하므로 동일한 쓰기 통제·종료 확인 없이 수행하지 않는다.

이미 기록된 마커·영수증·연속일·학습 기록·복습 기한·음원은 지우지 않는다. 데이터가 있으면 downgrade가 거부되는 것이 정상이다. 강제 컬럼/테이블 삭제, 과거 출석 추정, Data API 재개방은 롤백안에 없다. 주간 집계 표시를 별도로 원복하더라도 기존 답안과 공식 출석은 바꾸지 않는다.

## 릴리스 준비 상태

구현·격리 ON 검증과 최종 OFF 회귀를 완료했다. [호환 구현 PR #215](https://github.com/WhiteMouseDev/HaruKoto/pull/215)와 [활성화 draft #216](https://github.com/WhiteMouseDev/HaruKoto/pull/216)은 병합/운영 적용하지 않는다. 새 커밋의 원격 CI는 각 PR의 현재 head를 기준으로 확인하며 이전 head의 성공을 재사용하지 않는다. 관리자 Vercel Preview의 기존 폰트 외부 다운로드 결함은 [별도 미결 항목](../../../.planning/escalations/2026-11-02-admin-preview-font-build.md)이며 이력이 있으며 직전 문구 head의 현재 Preview는 성공했다. 재발 시 기능 회귀와 별도로 보고하고 임의 폰트/의존성 변경은 하지 않는다. 운영 쓰기 중지/구 writer 종료의 구체 통제는 [미결 운영 항목](../../../.planning/escalations/2026-11-02-study-day-writer-cutover.md)이며 별도 운영 승인 전에 결정해야 한다. 테스트 전용 API·PostgreSQL과 새 시뮬레이터는 검증 뒤 종료했고 fixture 데이터와 증빙은 보존했다.

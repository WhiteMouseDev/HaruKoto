# 가나 쓰기와 음성 연결

## 목표와 범위

기본 46자 추천·쓰기 이어하기(PR #242) 다음 단계로, 기존 쓰기 화면에서 글자와 예시의 소리를 듣고 글자 모양·쓰기·단어 읽기를 연결한다.

- 획순 보기·가리고 쓰기·단어에서 찾기에 명시적인 듣기·정지·다시 듣기·오류 재시도를 제공한다.
- 글자·단계·기기 복습·행 완료를 음성 재생 성공 여부와 연결하지 않는다. 기존 세 단계와 저장 문서 형식을 유지한다.
- 히라가나·가타카나 166자 원문·본보기·ID·예시·복습 저장 키는 변경하지 않는다.
- API·DB 구조·권한·Data API 차단·학습일·XP·오늘 단어 목표·복습 기한·음원 공급자/설정은 변경하지 않는다. 새 의존성을 추가하지 않는다.
- 이번 작업은 구현·회귀·전용 시뮬레이터 검증과 검토용 PR 범위다. 운영 배포·실기기 설치는 포함하지 않는다.

## 음성 대상

- 일반 문자의 단독 듣기는 일본어 글자 자체를 보낸다. 한국어 힌트나 설명을 음성 텍스트로 사용하지 않는다.
- `を/ヲ`, `ん/ン`, 작은 글자, `ゔ/ヴ`, 히라가나 `は/へ` 등은 단독 소리로 오해하지 않도록 예시 단어·문장·조합 안에서 듣도록 안내한다. `は/へ`는 단어와 조사에서 발음이 달라질 수 있어 기존 `はな/へや` 같은 예시로 안내한다. 이는 실제 TTS가 오독했다고 단정한 것이 아니라 문맥을 명확하게 하는 설계 판단이다. 참고: [국제교류기금 문법 자료](https://md.jpf.go.jp/userfiles/file/2018/Lengua%20Japonesa/Gramatica/A1-JP_rev.pdf).
- 예시에는 기존 `wordReading`, 다음 날 복습에는 `reviewWord.reading`을 사용한다. `三ヵ月` 같은 표기는 `さんかげつ`처럼 기존 읽기로 요청한다.
- 가리고 쓰기는 원문 글자를 노출하지 않는 듣기 라벨을 사용한다. 정답 공개와 기존 필기 비교 흐름을 바꾸지 않는다.
- 별도 오디오 대상 모델과 검증을 추가하고, 기존 166자 데이터 파일은 그대로 유지한다.

## 기존 API와 캐시

기존 `POST /api/v1/kana/tts`의 `{text}` → `{audioUrl}` 계약을 재사용한다. 로그인과 기존 rate limit을 유지한다. 허용 대상은 1~10 codepoints의 가나·허용 일본어 구두점이며, 한자·한글·ASCII 공백은 허용하지 않는다. 기존 예시 읽기 332개는 모두 제한에 맞고 최대 길이는 6자이다.

사용자가 듣기를 누를 때만 기존 on-demand 음성 경로를 사용한다. 캐시가 없을 때의 `tts_audio` 저장·GCS 업로드는 기존 서비스의 동작이며, 이 작업에서 대량 생성·기존 캐시 갱신·운영 DB 작업은 하지 않는다. 이 경로는 일반 음성 설정을 사용하고 레슨 대화의 Kenzo/Shizuka 화자 정책을 변경하거나 사용한다고 표시하지 않는다.

## 재생 수명과 오류

- 페이지가 음성 owner를 소유하고, ListView 안의 컨트롤은 상태를 표시한다.
- 다른 음성을 선택하면 기존 TtsService의 단일 재생 소유권·취소 정책을 재사용한다.
- 글자·단계 전환, 연습 목록 복귀, 페이지 종료, 계정 전환, 백그라운드 진입 시 음성을 취소한다. 앱 복귀·이어하기에서는 자동으로 재생하지 않는다.
- 로딩 중 정지도 취소 의도로 처리한다. 늦게 도착한 URL이나 이전 네이티브 완료 이벤트가 새 화면을 재생하게 하지 않는다.
- 오류는 한국어 안내와 명시적 재시도로 표시하며, 기존 학습 진행·저장을 막지 않는다.

## 검증

1. 166자와 예시·복습 음성 텍스트의 기존 API 범위, 한국어/한자 유입 방지, 특수 문자 문맥 안내.
2. 테스트 음성 서비스로 듣기·정지·교체·오류 재시도·화면 종료·계정 전환·백그라운드·자동 재생 없음 검증.
3. 기존 쓰기 위치·손글씨·정답 선택·복습 기록 보존, 전체 모바일 회귀·포맷·정적 분석.
4. 전용 iOS 시뮬레이터에서 실제 audioplayers와 loopback에서만 제공하는 합성 WAV로 네이티브 재생·정지·재진입·재실행 검증. 제품 API·유료 생성·클라우드 저장은 호출하지 않는다.

합성 음원 검증은 재생 수명과 UI 동작을 확인하는 것이다. 실제 일본어 음성의 발음·속도·교육적 품질을 확인했다고 해석하지 않는다.

## 롤백

모바일 변경을 되돌리면 기존 쓰기 흐름으로 돌아간다. 기기 진도·복습 키를 삭제하거나 마이그레이션하지 않으며 서버·DB·음성 설정의 원복은 필요하지 않다.

### 수정한 문제

1. 쓰기에는 시각적 본보기와 한국어 힌트가 있었지만 소리를 확인하는 진입이 없었다. 기존 일본어 glyph/예시 읽기와 TTS 서비스를 연결했다.
2. 소리를 단독으로 듣기 어려운 작은 문자·조사 관련 문자·단위 표기를 같은 방식으로 처리하면 오해할 수 있다. 별도 음성 대상 모델에서 문맥 듣기로 구분했다.
3. 음성 오류와 재시도 라벨이 뒤늦게 나타나면 필기 중 패드 위치가 움직일 수 있다. 정지·재시도까지 고려한 버튼 크기와 상태 영역을 미리 확보하고, 좁은 화면·큰 글씨는 처음부터 세로로 배치했다. 320px/1배, 390px/1.4배, 320px/2배에서 필기 중 로딩·503 오류에도 좌표가 유지되는지 검사했다.
4. 기존 TtsService는 실패 후 재생 run을 비우므로 owner 정지만으로 failed 상태가 지워지지 않는다. 현재 선택 음성과 현재 글자의 대상이 일치할 때만 오류를 표시해 이전 단계의 오류가 다음 글자에 남는 문제를 방지했다. 코어 서비스의 전역 정책은 유지했다.
5. 위젯 테스트의 Dio 응답 스트림과 fake timer 대기는 서로 다른 비동기 경계를 가졌다. 기존 TTS 테스트 패턴을 참고해 fake pump와 실제 응답 drain을 교차 처리했다. 제품 코드를 바꿔 테스트 타이밍을 맞추지 않았다.

### 실제 iOS 시뮬레이터

전용 iOS 26.5 시뮬레이터에 제품 소스를 그대로 빌드하고, 인증·API 응답만 합성 fixture로 대체했다. 실제 audioplayers가 정확히 허용한 loopback WAV를 재생하고 재생 위치가 증가하는 것을 확인했다. Dart HTTP는 차단했고 운영 API·음성 생성·GCS·DB를 호출하지 않았다. 로컬 네트워크 허용은 QA 빌드 복사본에만 적용했다.

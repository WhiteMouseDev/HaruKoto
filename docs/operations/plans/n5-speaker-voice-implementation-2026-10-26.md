# N5 화자별 음성 연결 구현

## 사용자 승인과 목표

사용자는 최신 모델 조사와 네 줄씩 두 모델로 비교하는 제안을 받은 뒤 작업 진행을 요청했고, 우선 레슨 등장인물부터 파악해야 하는지 물었다. 전체 소스와 현재 공개 레슨의 인물·역할·voice alias 인벤토리를 먼저 확인하고 N5 대화의 화자 연결과 회귀를 구현한다. 동일 성씨를 전역 동일 인물이나 성별로 추정하지 않는다.

기존 미커밋 원본과 PR #162의 검수 자료를 보존하기 위해 현재 main 5bfabe4b에서 별도 관리 작업 트리와 codex/n5-speaker-voice-routing 브랜치를 사용한다. 이 구현 PR은 PR #162의 QA 도구 변경에 의존하지 않는다. PR 병합·서버 배포·운영 캐시 교체는 별도 적용 단계다.

## 계획

1. packages/database/data의 정식·draft 레슨을 분리해 레벨·공개 상태·화자·역할·voice alias·누락·모순을 읽기 전용 집계한다. 운영 공개 콘텐츠는 개인 데이터 없이 최소 SELECT·READ ONLY·TLS·상한을 검토한 뒤 확인한다.
2. 등장인물의 서사적 정체성과 현재 두 음성 역할을 구분한다. N5는 기존 김의 남성 alias·다나카 등 여성 alias를 보존한다. 역할명을 하나의 고정 인물로 합치지 않는다. 다른 레벨과 단어·가나·문제 안내·채팅은 이번 적용 대상으로 확대하지 않는다.
3. 레슨 전용 provider adapter가 논리 alias를 실제 ElevenLabs voice ID에 매핑하도록 구현한다. 앞서 제시하고 진행을 승인받은 선택형 ELEVENLABS_LESSON_FEMALE_VOICE_ID·ELEVENLABS_LESSON_MALE_VOICE_ID 두 설정만 소스 계약에 추가한다. 실제 운영 secret·설정 값은 아직 적용하지 않는다. 새 의존성은 추가하지 않는다.
4. 기존 캐시의 무차별 무효화·덮어쓰기·대량 유료 생성을 금지한다. legacy 캐시는 그대로 읽고 새 정책의 미등록·역할 오류·provider 실패가 기본 여성 음성으로 조용히 합류하지 않도록 한다. 원문·역할·실제 voice·모델·파라미터·정책 버전 지문과 새 파일 경로의 계획을 준비한다.
5. 역할별 전달·같은 화자 일관성·누락/미등록·실패·캐시와 기존 타 TTS 경로를 회귀로 검증한다. 공개 API 요청/응답·DB 스키마·기존 학습 이력과 기한·콘텐츠 voice alias 및 reading.audioUrl은 바꾸지 않는다. 후자의 두 필드는 모바일 체크포인트 서명에 포함되므로 기존 저장 레슨 복원을 보존한다.
6. 대표 HN5-004 네 줄의 두 voice·Multilingual v2/v4 각 한 번, 최대 여덟 샘플 비교를 준비한다. 실제 voice 접근·사용 조건·문자 수·요금·실행 범위는 유료 호출 전에 제시한다. 모델별 설정을 분리하고 전체 듣기·대화 분할은 별도 실험으로 둔다. 샘플을 새로 만들더라도 운영 tts_audio 변경은 별도 네 행 적용안과 청취 결과 뒤에 진행한다.

## 검증과 완료 기준

변경 소스 주변 테스트를 먼저 읽고 좁은 회귀부터 실행한다. Python 3.12·합성 환경·격리 PostgreSQL을 사용하고 운영 DB/AI/음성 API를 테스트에 연결하지 않는다. API 전체·필수 PostgreSQL 무스킵·Ruff·mypy 및 계약 신선도를 확인한다. 독립 소스 검토와 문서·비밀정보 검사를 거쳐 별도 PR로 준비한다. 소스 인벤토리와 실제 공개 상태, 구현과 배포, 기계 검사와 사람 청취를 각각 구분해 기록한다.

## 보존과 롤백

원본 학습·답안·진도·기한·로그인·권한·RLS·Data API 설정에 대한 쓰기는 없다. 구현을 revert해 기존 기본 생성 경로로 되돌릴 수 있어야 하며 기존 음성 파일과 캐시는 보존한다. 샘플과 실제 캐시 교체의 rollback은 코드 revert와 구분하고 적용 전에 명시한다. 새 공개 API·DDL·추가 env 계약·실제 운영 캐시 DML이 필요해지면 구체안을 먼저 제시한다.

실제 실행 결과와 제한은 아래에 기록한다.

## 구현과 검증 결과

- [전체 인벤토리](../content/lesson-speaker-inventory-2026-10-26.md)를 작성했다. 정식 소스 81레슨·322대사와 실제 공개 76레슨·302대사를 구분한다. 공개 N5 50·N4 26의 모든 speaker/voice_id/text가 원본과 일치했다. 개인 기록 조회·쓰기 없이 검토된 네 SELECT만 사용했다.
- 선택형 두 설정이 모두 비어 있으면 기존 생성 경로를 유지한다. 기존 캐시가 있으면 새 설정이나 alias 검증보다 먼저 반환한다. N5의 cache miss에서 하나라도 설정돼 있으면 두 실제 voice ID의 존재·서로 다름과 등록된 alias를 확인하고 역할별 생성기를 사용한다. 오류·부분 설정·같은 ID·provider 실패는 기본 여성 음성이나 Gemini로 조용히 합류하지 않는다. 기존 한국어 502와 audioUrl 응답을 유지한다.
- 새 프로필은 원문·실제 전송 입력·논리/실제 voice·모델·파라미터·정책 버전 SHA를 포함한다. API key는 포함하지 않는다. 모델별 유효 설정을 나누며 실제 SDK 2.39의 HTTP 직렬화를 다섯 모델에서 회귀로 확인했다. 샘플 모델은 job 인자로 override해 전역 모델 설정을 바꾸지 않았다.
- 독립 리뷰에서 같은 프로필의 비결정적 재생성이 동일 URL을 덮어쓸 수 있음을 발견해 생성 UUID를 새 경로에 추가했다. 업로드 뒤 commit 실패·같은 프로필 재시도에도 경로가 달라지는 회귀를 추가했다. provider 원시 오류 본문·헤더가 로깅 체인에 전달되는 경로도 from None과 실제 서비스 caplog 회귀로 차단했다. 최종 독립 검토에서 추가 지적은 없다.

처음 일반 sandbox의 PostgreSQL 초기화는 shared memory 권한 제한으로 실패했다. 해당 시도는 환경 제한 로그로 따로 보존했고 최종 검증은 허용된 격리 로컬 PostgreSQL에서 통과했다. 리뷰 수정 전 942개 통과 기록도 별도로 보존하며 최종 949개와 합산하지 않는다. 테스트는 합성 환경을 사용하고 운영 DB·외부 TTS 호출을 하지 않았다.

## 여덟 비교 샘플

[샘플 실행 기록](n5-speaker-voice-sample-results-2026-10-26.md)에 따라 Kenzo/Kaori 후보와 두 모델의 단일줄 음성을 총 여덟 번 생성했다. 테스트의 네트워크 0과 이 승인된 실제 생성 작업을 구분한다. HTTP 200·MP3 디코딩 8/8을 확인했고 provider character-cost 헤더 합계는 114다. 자동 재시도·운영 DB·캐시·GCS 업로드·cloud/env 설정 변경은 0이다. 실제 일본어 청취 판정은 PENDING이다.

샘플은 커밋 제외 build 디렉터리에 저장했고 문장별 A/B와 로컬 이어듣기, ZIP을 준비했다. 이어듣기는 네 개 단일줄 파일을 로컬로 연결한 미리듣기이며 Text to Dialogue 전체 생성 결과가 아니다. 브라우저에서 화면·문장·재생 컨트롤·메타데이터 길이 표시를 확인했다. Codex의 직접 청취나 실제 앱의 새 음성 UAT를 완료한 것으로 표현하지 않는다.

## 다음 적용 경계

이번에는 구현·회귀·표본 전달까지 진행했다. PR 병합·서버 배포·실제 운영 설정·캐시 교체는 하지 않는다. 현재 adapter의 운영 기본 모델은 기존 ELEVENLABS_MODEL_ID를 따르며, v4 표본은 명시 job override다. v4를 향후 레슨 전용 기본 모델로 채택할 때 전역 모델을 바꿔 다른 TTS까지 영향 주지 않도록 별도 설정/정책안을 먼저 확인한다.

청취 뒤 선택한 목소리·모델의 네 행 적용안에는 이전/새 URL·행 지문·조건부 갱신·정확한 영향 행 수·원복을 제시한다. 전체 198대사·250문제나 N4·draft로 자동 확대하지 않는다. 콘텐츠의 voice_id·reading.audioUrl을 유지해 기존 로컬 레슨 체크포인트 서명을 보존한다. 기존 로그인·학습·답안·진도·기한·권한·Data API에 쓰지 않았다.

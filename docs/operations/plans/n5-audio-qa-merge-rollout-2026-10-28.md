# PR #162 병합·자동 서버 배포와 보존 검증

실시일: 2026-10-28 KST. 사용자는 PR #162 병합·자동 서버 배포 확인과 배포 후 로그인·음성 재생·학습·이어하기 검증을 승인했다. 기존 로그인·학습 기록·음원 캐시·Kenzo/Shizuka v4 설정·Data API 차단을 유지하며, 전체 음원 청취 검수는 별도 미완료로 남긴다.

## 변경과 배포 경계

PR #162는 QA 스크립트 두 개·테스트 두 개와 검수 자료·문서를 반영한다. API 런타임·계약·인증·DB 스키마·앱 소스는 바꾸지 않는다. 다만 기존 배포 워크플로는 main의 `apps/api/**` 변경에 반응하므로 검수 스크립트·테스트 변경도 서버 자동 재배포를 시작한다. 이 점을 병합 판단에서 확인한 뒤 실제 실행을 승인받았다.

검수표 생성·집계 도구가 앱 시작 시 실행되는 것은 아니다. Docker 시작 명령은 기존 uvicorn이고, 이번 배포에서 seed·migration·판정 적용·캐시 무효화·음성 재생성 도구를 실행하지 않았다. 기존 `reading.audioUrl`과 콘텐츠의 voice alias도 변경하지 않는다.

## 캐시·콘텐츠·보안 보존

배포 전, 배포 후, API smoke 후, 앱 검증 후의 네 시점에서 TLS 인증서·호스트 검증과 `REPEATABLE READ READ ONLY` 트랜잭션을 사용했다. 마지막 스냅샷은 앱 확인이 끝난 뒤인 16:58:02 KST다. statement/lock timeout과 조회 범위를 제한했고 개인 학습 테이블은 조회하지 않았다.

- N5 대화 캐시 198행과 문제 안내 캐시 250행, 합계 **448개 기존 행의 전체 지문이 동일**했다.
- 세 사후 비교 모두 기존 행 변경·삭제·신규 삽입은 **0개**였다.
- N5 레슨 50개의 콘텐츠 지문과 권한·RLS를 포함한 보안 카탈로그 지문이 같았다.
- orphan·이상 연결·공개 대화/문제 캐시 누락은 0개였다.

이는 N5의 해당 콘텐츠·캐시·보안 범위 보존을 확인한 것이다. 운영의 모든 개인 학습 기록을 읽어 전체 DB가 정지했다고 주장하지 않는다. 직접 답안 제출·기록 보정·초기화 endpoint를 호출하지 않았으며, 정상 로그인과 앱 QA가 만드는 일반 동작은 별도로 구분한다.

## 운영 API와 기존 음원 확인

API helper는 기존 전용 QA 계정으로 정상 로그인 1회를 수행했다. 이후 시뮬레이터 UI 정상 로그인은 아래 앱 검증으로 구분한다. 계정 생성·암호 변경·기존 세션 취소·관리자 로그인 대행은 하지 않았다. 정상 로그인은 인증 세션을 만들므로 이를 Auth DB 전체 쓰기 0회라고 표현하지 않는다.

## 앱 확인

앱 검증 결과는 실제로 관찰한 설치본과 시점에 한정해 기록한다. 운영 API 검사를 실제 앱 재생·복원의 증거로 대체하지 않는다. 이전 PR #196/#197의 사용자 청취 보고를 이번 배포 후 PASS로 재사용하지 않는다.

시뮬레이터 두 설치본에서 다음을 실제 화면·시간순 AX로 확인했다. 실제 아이폰에 새 빌드를 설치하거나 기존 앱을 삭제·로그아웃·초기화하지 않았다.

최종 앱 관찰은 16:34:05 KST다. Atlas의 기존 체크포인트 4건은 한 칸 이동·복원 검증 이후 그대로 보존됐고, 업데이트 대상의 체크포인트 1건도 전후·최종 byte 지문이 같았다. Simulator가 앱의 데이터 컨테이너 경로를 바꿨지만 실제 기록 값과 로그인은 유지됐으므로 경로가 같다고 표현하지 않는다. 답안·레슨 완료 제출과 연습 시작은 하지 않았다.

처음 단어 화면에 말풍선이 없다는 이유만으로 구버전이라 판단한 것은 근거가 부족했다. 말풍선은 학습 단계에 따라 표시된다. 이후 실제 대화 읽기 화면에도 전체 듣기 control이 없는 것을 확인한 뒤 업데이트했다. 설치본 기능 판정에 화면 단계 조건을 함께 확인해야 한다는 경계를 남긴다.

업데이트 빌드의 모바일 소스 476개는 병합 커밋과 최종 byte 일치했다. Xcode 27.1과 기존 Pods의 최소 버전·다중 아키텍처 처리 호환 문제는 임시 xcconfig의 최소 iOS15·arm64·ONLY_ACTIVE_ARCH 설정을 이번 로컬 Simulator debug 빌드에만 적용해 해결했다. 앱의 실제 Mach-O가 IOSSIMULATOR·arm64이고 같은 bundle임을 확인했으며, Flutter/runtime 도구를 패치하거나 프로젝트·의존성·운영 설정을 바꾸지 않았다. 기존 환경 파일은 절대 경로로 참조했고 값을 출력·복사하지 않았다. CocoaPods가 바꾼 lock의 도구 버전 footer 한 줄도 사전 검증한 원본 bytes로 복원했다.

UI의 재생 순서·완료·취소 확인은 직접 청취에 따른 발음·음질·음향 겹침 판정이 아니다. 연습 단계에 진입하지 않아 별도 대화 시트 닫기는 이번에 확인하지 않았고, 레슨 화면 이탈과 백그라운드 취소를 확인했다. 전체 N5 언어 검수와 구분한다.

## 전체 청취 검수와 원복

검수표 9개·448개 항목의 정식 언어 판정은 **모두 PENDING**으로 보존한다. 36개 무음 비율 경고는 10월 26일 스냅샷의 검토 우선순위이며 불량 확정 건수가 아니다. 정식 전체 검수는 최신 전체 대상·음원·SHA 대응을 먼저 확인하고 별도로 진행한다. 검수 도구 병합·앱 기능 확인·음성 선호를 전체 일본어 발음 승인으로 확대하지 않는다.

이번 배포에 문제가 생기면 우선 직전 정상 리비전 `harukoto-api-00246-bd4`로 트래픽을 되돌리는 안을 사용한다. 실행 전 현재 리비전과 후속 운영 변경을 확인해 다른 변경을 덮어쓰지 않는다. 이번에는 DB·캐시 교체가 없어 캐시나 학습 기록의 DB 원복은 필요하지 않다. 코드·트래픽 원복을 캐시 삭제나 전체 음원 재생성으로 처리하지 않는다. 현재 원복은 실행하지 않았다.

안전한 receipt와 비공개 서비스·스냅샷 원본은 `/private/tmp/harukoto-pr162-production-rollout-20261028/`에 보관한다. 비밀 값·토큰·실제 voice ID·개인 계정과 기기 식별자를 저장소 문서에 복사하지 않는다.

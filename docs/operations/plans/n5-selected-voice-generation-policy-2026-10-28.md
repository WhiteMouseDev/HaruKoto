# 채택한 N5 대화 음성과 후속 생성 정책 일치

작성일: 2026-10-28 KST. 대상: PR #196의 **미배포 소스 정책과 회귀 테스트**. 운영 DB·설정·기존 음원 교체와 PR 병합·배포는 이번 실행에 포함하지 않는다.

## 문제와 이미 확인한 범위

사용자는 2026-10-27 대표 HN5-001·002·036의 12문장을 듣고 남성 Kenzo B와 여성 Shizuka를 모두 `eleven_v4`로 채택했다. 선택한 샘플 설정은 남성 stability 0.5, 여성 0.8, 두 역할 similarity_boost 0.75다. 이어 별도 승인한 HN5-004 네 파일 업로드·캐시 네 행 교체도 완료했다. 이 문서는 이후의 생성 정책만 다루며, 해당 파일럿을 다시 실행하는 적용 문서가 아니다.

후속 생성기를 점검하니 다음 차이가 남았다.

1. 역할별 생성기의 기본 모델이 전역 `ELEVENLABS_MODEL_ID`를 따랐다. 샘플의 명시적 v4 인자를 생략한 운영 호출은 선택한 모델을 보장하지 못한다.
2. v4의 남녀 역할 모두 stability 0.5여서 선택한 Shizuka 0.8과 달랐다.
3. 기존 짧은 문장 처리로 8자 이하 원문 뒤에 `。`를 무조건 붙였다. 이미 구두점이 있는 원문은 이중 구두점이 되며, v4 샘플의 원문 보존 조건과 다르다.

이 차이는 **향후 캐시가 없는 N5 대화를 생성할 때의 문제**다. 이미 적용한 HN5-004의 네 원음이나 현재 캐시가 잘못 적용됐다는 의미는 아니다. 음성 생성은 비결정적이므로 같은 요청 프로필도 파일 바이트나 청취 품질까지 동일하게 보장하지 않는다.

## 구체적인 소스 변경안

새 환경변수를 추가하지 않고 N5 대화 전용 adapter의 기본 모델과 v4 역할 설정을 코드로 고정한다. 이미 승인돼 PR #196에 있는 두 선택형 voice ID 계약만 사용한다. 실제 Kenzo·Shizuka ID의 운영 연결은 별도 적용 단계다.

| 경로                                                         | 변경 후 정책                                         |
| ------------------------------------------------------------ | ---------------------------------------------------- |
| N5 대화 + 캐시 있음                                          | 설정 검증·유료 생성 전에 기존 URL 반환               |
| N5 대화 + 캐시 없음 + 두 역할 설정 비어 있음                 | 기존 일반 TTS 경로 유지                              |
| N5 대화 + 캐시 없음 + 역할 설정 활성화                       | 기본 `eleven_v4`, 남성 0.5·여성 0.8, similarity 0.75 |
| v4 텍스트                                                    | 원문·구두점 그대로; 태그·속도·음량·사전 추가 없음    |
| 명시적으로 다른 지원 모델을 지정한 검수 job                  | 기존 모델별 요청 정책 유지                           |
| N4·단어·가나·문제 안내·일반 TTS                              | 기존 경로와 전역 모델 설정 유지                      |
| 역할 설정이 일부만 있거나 동일 ID·미등록 alias·provider 실패 | 명시적 실패; 기본 여성/Gemini로 대체하지 않음        |

전용 프로필 정책 버전도 갱신하고, 정확한 요청·보이스·역할·모델·원문·정책 버전이 기존 지문에 포함되도록 유지한다. 생성별 UUID가 있는 새 객체 경로를 보존해 비결정적 재생성이나 commit 실패 후 재시도가 이전 객체를 덮어쓰지 않게 한다.

공개 API 요청/응답·DB 스키마·환경변수 계약·의존성은 변경하지 않는다. 레슨 `content_jsonb`, `voice_id` alias, `reading.audioUrl`과 모바일 체크포인트 서명도 변경하지 않는다.

## 회귀 테스트와 검증 계획

실제 음성 공급자·운영 DB를 사용하지 않는다. 실패를 먼저 재현한 뒤 최소 수정하고, 실제 잠금 SDK와 메모리 HTTP transport를 사용해 직렬화까지 확인한다.

- 전역 모델이 v2·빈 값·미지원 값으로 달라도 활성화된 N5 대화 기본 요청은 v4다. 전역 설정 자체를 바꾸지 않는다.
- 남녀 두 역할의 정확한 voice ID 전달과 literal v4 요청, 여성 0.8·남성 0.5 및 similarity 0.75를 검증한다.
- 짧은 원문·기존 `。`·`！`·`？`와 긴 대사를 v4에 그대로 전달한다. 명시적 다른 모델의 기존 동작도 검증한다.
- 실제 profile builder → SDK 직렬화 → 서비스의 저장 모델·업로드 경로를 연결한 회귀를 넣는다. 단순 stub 반환값만 확인하지 않는다.
- 요청 설정만 바뀌어도 지문이 달라지고 API key만 바뀌면 동일하다는 기존 추적 조건을 보존한다.
- 잘못된 역할 설정이어도 기존 캐시 적중은 생성·업로드·commit 없이 반환한다.
- N4·일반 경로·문제 안내, 설정 비활성화, 알 수 없는 역할, provider 실패와 commit 실패 뒤 재시도의 객체 보존 회귀를 실행한다.
- API 전체 테스트·Ruff·mypy, 필수 격리 PostgreSQL 무스킵 검사와 공개 계약 신선도를 확인한다. 불가한 검사는 실제 원인과 함께 별도 기록한다.

## 운영 적용 전 확인할 안

**이번에는 다음 변경을 실행하지 않는다.** 향후 PR 병합·배포를 요청받더라도 실제 설정을 활성화하기 전 현재 운영 값을 비밀 노출 없이 확인하고 다음 안을 제시한다.

1. 두 기존 역할 설정을 승인한 Kenzo·Shizuka ID에 연결한다. 실제 ID나 API key를 문서에 복사하지 않는다. 전역 `ELEVENLABS_MODEL_ID`는 바꾸지 않는다.
2. 이 opt-in은 HN5-004만을 대상으로 하는 allowlist가 아니다. 활성화 이후 **모든 N5 대화의 캐시 누락 요청**이 선택한 전용 정책으로 생성될 수 있다. 기존 캐시 자동 재생성이나 일괄 교체는 일어나지 않는다. HN5-004만의 파일럿과 영향 범위를 혼동하지 않는다.
3. 대량 재생성·검수·다음 레슨 적용은 현재 공개 콘텐츠의 최신 인벤토리, 정확한 문장·호출·문자·비용 상한, 새 객체 수와 조건부 캐시 변경 행 수, 이전/이후 지문·롤백을 따로 제시한다.
4. 운영 적용 뒤 확인은 로그인 세션·학습·복습·이어하기와 Data API 차단을 구분해 확인한다. 코드를 수정하지 않았다는 이유로 운영 기능 검증을 통과 처리하지 않는다.

## 롤백과 보존

소스 정책은 이 후속 commit만 revert할 수 있게 기존 PR #196 구현과 구분한다. 코드 롤백은 이미 생성한 캐시 행·객체를 자동으로 되돌리지 않는다. 실제로 새 음원을 적용한 경우에는 승인된 대상별 원본/교체 지문을 비교한 조건부 캐시 원복을 별도 실행해야 한다. 기존 객체를 삭제하거나 덮어쓰지 않는다.

운영 설정을 나중에 활성화한다면 이전 리비전과 설정의 존재/버전을 보존하고, 원복은 그 이전 상태를 복원한다. 기존 HN5-004 네 행의 파일럿 롤백은 해당 실행 기록과 승인 manifest를 따른다. 로그인·학습 기록·기한·권한·RLS와 Data API 차단은 수정 대상이 아니다.

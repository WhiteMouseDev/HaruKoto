# 레슨 문항과 복습 항목 연결 수정

## 요청과 변경 경계

2026년 10월 21일 사용자는 문항과 복습 항목 연결 오류 수정, 회귀 테스트 추가, 기존 학습 기록 영향 조사를 승인했다. DB나 기존 기록 변경이 필요하면 적용 전 구체적인 수정안을 먼저 제시해야 한다.

이번 구현은 소스·콘텐츠 메타데이터·회귀 테스트를 준비하고 운영을 읽기 전용으로 조사한다. 운영 콘텐츠 업데이트, 학습 기록 교정, 마이그레이션, 권한·Data API 설정 변경, 서버 배포는 실행하지 않는다. 원래 작업 폴더의 기존 변경을 보존하고 연결된 깨끗한 작업 트리의 `codex/fix-lesson-review-targets`에서 수정한다.

## 확인한 원인

`_map_questions_to_links`는 명시적인 `vocabulary_id`·`grammar_id`가 없으면 문항 표시 순서와 학습 항목 순서를 같은 것으로 간주한다. 기존 시드는 어휘를 먼저 배치하고 핵심 문법을 마지막에 배치하므로 두 순서는 일치하지 않는다. HN5-001의 학생 문항이 私로 연결되고 です 문법 문항들이 어휘 항목에 연결된다.

문항 타입으로 추측하는 대체도 안전하지 않다. VOCAB_MCQ가 문법을 묻거나 CONTEXT_CLOZE가 단어 뜻을 묻는 예외가 있다. 일부 원본 핵심 문법 참조와 실제 문제 목표도 일치하지 않아 별도 콘텐츠 검토가 필요하다.

## 명시적인 참조 계약

레슨 원본의 각 문항에는 해당 JLPT 레벨 안에서 해석하는 `vocabulary_order` 또는 `grammar_order`를 정확히 하나 넣는다. 이는 문항 순서나 lesson item_order가 아닌 어휘·문법 카탈로그의 식별 참조다. 검수로 단일 대상을 확정할 수 없는 문항은 대상 참조 없이 `srs_skip_reason`에 구체적인 이유를 명시한다. 이 문항도 정오 채점과 레슨 결과에는 포함된다.

시드는 이 참조를 실제 UUID로 해석해 DB content_jsonb의 기존 `vocabulary_id`·`grammar_id` 필드에 저장한다. 서버는 유효한 참조가 해당 레슨의 학습 항목에 속하는지 확인한다. 문항 순서 fallback은 제거한다. 정확한 문항 대상이 기존 레슨 항목에 없다면 검토된 non-core 링크를 추가할 수 있게 준비하되 운영 적용은 별도 승인 대상이다.

서버는 유효한 UUID 대상 하나 또는 명시적인 제외 사유를 요구한다. 누락·두 참조 동시 지정·잘못된 UUID·다른 레슨 항목·이유와 대상의 충돌은 SRS 등록과 학습 기록 쓰기 전에 검증 실패로 처리한다. 기존 오류 응답 형식을 유지하며 외부 요청·응답 필드를 추가하지 않는다.

별도 런타임 manifest나 문자열 의미 추정은 추가하지 않는다. 문항 번호·내용이 바뀌었는데 과거 추측이 유지되는 이중 관리도 피한다. 동일 항목을 여러 문항에서 평가하는 기존 문항별 SRS 처리 정책은 이번 변경과 구분해 검토한다.

## 회귀 검증

1. 첫 레슨을 포함해 원본 전체 문항의 참조 또는 명시 제외 사유가 존재하는지 검사한다.
2. 링크 순서가 섞여도 학생은 学生, です 문항은 검수된 문법 대상으로 연결되는지 검사한다.
3. 누락·모순·다른 레슨·존재하지 않는 대상은 학습 기록 쓰기 전에 실패하는지 검사한다.
4. 명시적인 제외 문항은 점수에는 포함되고 SRS 갱신에는 포함되지 않는지 검사한다.
5. 시드의 해석·동기화 검사가 메타데이터와 실제 링크를 같은 계약으로 처리하는지 확인한다.
6. 격리 PostgreSQL에서 실제 제출·복습 상태·review event의 대상과 트랜잭션 원자성을 검증한다. 기존 기록을 수정하지 않는지도 검사한다.
7. Ruff·mypy·영향받는 API 테스트와 OpenAPI·모바일 계약의 불변성을 검사한다. 공유 콘텐츠 검증과 직접 소비자인 API 검증을 함께 수행한다.

## 운영 영향 조사

관리 연결도 READ ONLY, UTC, 짧은 statement timeout과 총 실행 제한으로 사용한다. 고객 식별자와 답안 본문을 출력·다운로드하지 않고 대상 레슨·기록·사용자 수와 기간만 비식별 집계한다. 기존 monitor 전용 계정에 학습 데이터 권한을 추가하지 않는다.

게시 콘텐츠와 링크의 원본 일치 여부, 레슨 제출 진도와 lesson-origin review event, 현재 어휘·문법 상태에 미친 잠재 영향을 구분한다. 이벤트에 문항 순서·제출 답안·시도 ID·콘텐츠 버전이 없으면 정확한 과거 답안 재귀속을 보장할 수 없다는 한계를 명시한다. 조회 제한에 걸린 결과를 전체 집계로 제시하지 않는다.

## 운영 적용 전 결정할 내용

운영 기존 JSON에는 참조가 없으므로 strict 서버를 먼저 배포하면 해당 레슨 제출이 거부된다. 따라서 구현 검증 후 **검수된 문항 메타데이터와 필요한 링크만 반영하는 DB 데이터 변경안**을 먼저 제시한다. 새 테이블이나 컬럼은 현재 설계에서 필요하지 않다.

구체안에는 대상 레슨·문항 수, 기존 콘텐츠 fingerprint 사전 조건, 기존 텍스트·정답·음성·진도·사용자 기록 보존, 추가 링크, 부분 실패 시 원자적 롤백, 서버 전환 순서와 사후 검증을 포함한다. 일반 시드를 운영에 재실행해 모든 콘텐츠·링크를 덮어쓰지 않는다. 과거 학습 기록 교정은 콘텐츠 참조 보완과 분리해 별도 검토한다.

## 결과 기록

### 구현 및 검증

- N5·N4 원본 16개 파일의 81개 레슨·405개 문항을 검토했다. 단어 189개·문법 211개 문항에 명시 대상을 넣고, 단일 대상을 정하기 어려운 5개에는 구체적인 SRS 제외 사유를 넣었다. 기존 문구·보기·정답·순서·음성 등은 메타데이터를 제거한 원본 비교에서 16/16 동일했다.
- `lesson-question-target-review.json`에 각 문항의 대상·근거와 추가 링크·콘텐츠 후속 검토를 기록했다. 코딩 에이전트의 검토 결과이며 원어민 교육 전문가의 승인을 뜻하지 않는다.
- 서버의 위치 기반 fallback을 제거했다. UUID 누락·모순·잘못된 형식·다른 레슨·중복 링크를 SRS 등록·정오 반영·진도 쓰기 전에 409로 거부한다. 명시적으로 제외한 문항은 정상 채점하지만 SRS 답안 이벤트를 만들지 않는다.
- 전체 API 테스트 **757 passed / 13 skipped**. 선택적 AI 통합 테스트의 skip과 별개로 필수 PostgreSQL **61개가 모두 실행·통과**했다. 신규 9개는 첫 레슨 실제 제출, 잘못된 매핑 6종의 기존 기록 보존, non-core 링크와 기존 응답 계약, 명시 제외의 채점·SRS 분리를 검증한다.
- CI 게이트 단위 테스트 10개, 소스 참조 테스트 8개, 81개 레슨·405개 문항 검사 통과. CI는 필수 PostgreSQL 결과가 누락·중복·skip·failure·error이면 실패하며 콘텐츠 검증도 실행한다.
- API Ruff·mypy와 database lint/typecheck, Prisma validate/generate, N5·N4 기존 품질 게이트 통과. DB DDL이나 의존성은 변경하지 않았다. OpenAPI 102개 경로의 스냅샷은 변경되지 않았다. 모바일 경로 검사 62개도 통과했지만 해당 도구에는 모델 필드 대조 대상이 없어 필드 호환성 전체를 증명하는 결과로 해석하지 않는다.

이번에는 운영 DB·기존 학습 기록·권한·클라우드 설정을 변경하지 않았고 서버도 배포하지 않았다. Data API 차단을 해제하거나 ACL/RLS를 변경하지 않았다. 플랫폼 스위치와 ACL/RLS 상태를 이번 조사에서 별도로 재검증한 것은 아니다.

## 승인 요청할 운영 데이터 적용안

아래는 **제안이며 미적용**이다. DB 변경을 먼저 설명해 달라는 사용자 요청에 따라 적용 전 승인이 필요하다.

1. **수정 범위:** 81개 레슨의 기존 `content_jsonb.questions` 안에 검토한 메타데이터만 추가한다. 400개 문항은 운영 카탈로그의 실제 UUID로 연결하고 5개는 `srs_skip_reason`을 넣는다. 76개 게시·5개 비게시 상태, 문구·정답·보기·순서·음성·나머지 JSON은 유지한다.
2. **추가 범위:** 필요한 17개 문법 링크만 `is_core=false`로 기존 순서 뒤에 추가한다. 기존 링크의 ID·순서·core 여부를 교체하지 않는다. 범용 시드의 링크 삭제/재생성 경로를 운영 보정에 사용하지 않는다.
3. **보존 범위:** 기존 94개 복습 이벤트, 현재 진도 62행, 모든 레슨 점수·완료·시도·XP·연속일을 수정·삭제·재생하지 않는다. 새 테이블·컬럼·권한·환경변수·RLS·Data API 변경은 필요하지 않다.
4. **사전 조건:** 실행 직전 원본 fingerprint, 문항 수, 레벨별 카탈로그 대상·라벨, 기존 링크의 완전성을 다시 검사한다. 확인한 운영 상태와 달라지면 쓰지 않고 중단한다. 변경할 콘텐츠와 새 링크 목록만 보호된 위치에 원복 자료로 확보한다. 고객 학습 기록의 전체 반출은 하지 않는다.
5. **원자성:** 짧은 lock/statement timeout을 둔 트랜잭션 하나에서 81개 콘텐츠와 필요한 17개 링크를 함께 반영한다. 예상 수정 수·중복·참조 검증 중 하나라도 다르면 전부 롤백한다. 다시 실행할 때 이미 동일한 메타데이터/링크는 변경하지 않는 멱등 보정으로 준비한다.
6. **전환:** 먼저 새 서버 리비전을 트래픽 없이 준비한다. 기존 서버는 명시 제외 사유를 이해하지 않으므로 새 코드와 DB 보정을 분리해 장기간 운영하지 않는다. 짧은 작업창에 새 서버로 전환하고 이전 리비전의 진행 중 요청이 끝난 뒤 DB를 보정한다. 이 구간에는 미보정 레슨 제출이 409로 거절될 수 있으나 잘못된 SRS/진도를 쓰지는 않는다. 무중단이라고 안내하지 않는다.
7. **확인:** 승인된 테스트 계정으로 로그인, 레슨 열기·제출·정답/문법 대상 확인, 미완료 퀴즈 조회·이어 풀기를 확인한다. 운영 DB 카탈로그·콘텐츠의 참조 검증과 기존 기록 보존도 재확인한다. API 전체 테스트 통과를 아이폰 실기기 확인이나 운영 확인으로 대체하지 않는다.
8. **장애 처리:** 트랜잭션 내 실패는 전부 취소한다. 적용 후 문제가 생기면 해당 레슨 제출을 막아 오기록을 방지하고, 실제 신규 기록과 콘텐츠 변경 여부를 확인한 후 보호된 사전 이미지와 새 링크 목록으로 콘텐츠만 원복한다. 과거 기록을 덮어쓰지 않는다. 서버만 이전 코드로 되돌리면 위치 fallback 오류가 재도입된다는 한계가 있다.

### 적용 시 알아야 할 부수 효과

- 기존 레슨 소개와 SRS 등록 경로는 `is_core`로 필터링하지 않는다. 따라서 17개 non-core 문법도 소개 목록과 새 복습 카드 등록에 포함된다. 실제 평가 대상이므로 이번 제안에서는 포함을 유지하되, core 문법 안내와 보조 항목의 시각적 구분은 별도 UX 과제로 둔다.
- 동일 문법을 3개 문항에서 물으면 기존처럼 SRS를 3번 갱신한다. 이번 수정은 대상을 바로잡고 이 기존 정책을 바꾸지 않는다. 한 레슨 내 중복 노출을 한 번의 장기 기억 평가로 볼지에 대한 후속 설계·테스트가 필요하다.
- 기존 핵심 문법 참조 중 문항 목표와 다른 사례는 삭제하거나 임의 교체하지 않았다. 검토 manifest의 `curriculum_followups`에 남겼다. 정확한 문항 대상과 기존 커리큘럼 구조의 전면 개편을 혼합하지 않는다.

### 과거 기록 처리 권고

현재는 과거 기록을 보존하고 앞으로의 정확한 평가로 갱신하는 방안을 권고한다. 62개 상태를 초기화하거나 77개 후보 이벤트를 다른 항목으로 옮기면 독립 퀴즈 학습과 과거 정오를 훼손할 수 있다. 과거 상태를 교정하려면 영향 계정 확인, 증거 수준, 재평가 또는 제한적 보정의 대상·효과를 별도 제안하고 다시 승인받아야 한다.

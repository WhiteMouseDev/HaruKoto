# 오래된 퀴즈 이어하기와 결과 복구의 학습일 분리

2026-11-03 KST. 사용자가 승인한 로컬 구현·검증 기록이다. 운영 DB, 클라우드 설정, 배포, 기존 학습 기록은 변경하지 않았다. 이 문서는 [초기 제안](long-lived-quiz-resume-proposal-2026-11-03.md)과 [설계 검토](long-lived-quiz-resume-design-review-2026-11-03.md) 이후 확정된 범위를 설명한다.

## 문제와 결정

사용자가 며칠 쉬었다가 앱을 열면, 읽기 API가 24시간 지난 퀴즈를 완료 처리했다. 새 퀴즈 시작도 다른 미완료를 종료하고 부분 XP를 정산했다. 따라서 같은 퀴즈를 직접 재개할 수 있어도 홈을 먼저 열면 이어할 수 없는 모순이 있었다.

기간 조건만 없애는 것으로는 부족했다. 오래된 세션이 최신의 빈 세션 뒤에 가려질 수 있었고, 웹은 마지막 답안 저장을 기다리지 않고 완료를 요청할 수 있었다. 답안 재전송과 실제 매칭 재도전을 구별하지 못하면 SRS가 중복 반영될 수 있었다. 시작부터 완료까지의 벽시계 차이는 며칠의 휴식도 학습 시간으로 계산했다.

마지막으로 과거에 답안을 전부 저장한 퀴즈의 결과만 오늘 확인해도 XP·완료 집계가 오늘의 학습일을 만들었다. 보상 지급 시점과 실제 학습 활동의 날짜는 목적이 다른 지표다. 사용자는 이를 먼저 분리하는 안을 선택했다.

## 구현한 동작

- 홈·목록·재개는 조회만 한다. 날짜로 종료하거나 새 시작으로 다른 퀴즈를 정산하지 않는다. 이미 완료된 과거 행을 재개방하거나 백필하지 않는다.
- 한 문항 이상 저장된 미완료를 최근 **시작** 순으로 보여준다. 홈에는 대표 카드 하나와 전체 보기, 목록은 최대 50개 cursor 단위다. 무응답 세션은 LIMIT 전에 제외하므로 오래된 저장 세션을 가리지 않는다. 시작 시각을 최근 학습 시각으로 표시하지 않는다.
- 일반·매칭·문장 배열은 원래 세션 ID와 snapshot, 저장 답안을 복원한다. 모두 저장했으면 결과 확인 경로, 호환되지 않거나 콘텐츠가 사라졌으면 기록을 보존하는 안내를 표시한다.
- 웹은 답안 저장 ACK를 순서대로 기다린다. 실패한 제출의 payload와 `attemptId`는 유지한다. 의도적 재도전은 새 ID를 직전 `previousAttemptId`에 연결한다. 같은 ID 재전송은 한 번만 반영하고, 구 웹의 필드 없는 요청은 무변경 409로 새로고침을 안내한다. FastAPI·모바일의 기존 답안 계약과 채점 규칙을 섞지 않는다.
- 서버는 모든 원본 문항의 답안이 저장되기 전 완료를 거절한다. 완료·답안·새 시작은 동일 사용자의 잠금 순서를 따른다. 저장된 최초 답안의 시간 합으로 학습 시간을 계산하고, 앱·웹은 백그라운드 시간을 새 답안 타이머에 포함하지 않는다.
- 계정 전환 또는 오래된 요청 응답은 다른 계정의 저장 목록·퀴즈 상태를 덮어쓰지 못한다. 목록 실패는 빈 목록으로 숨기지 않고 재시도한다.

## 학습일과 집계를 분리한 데이터 계약

Alembic `q7r8s9t0u1v2`는 `p6q7r8s9t0u1` 다음에 `daily_progress.study_day_credited BOOLEAN NULL` 하나를 추가한다. 명시적 DEFAULT, 새 테이블·인덱스, 백필, 권한·RLS 변경은 없다. Prisma는 실제 로컬 DB introspection으로 nullable `studyDayCredited`를 동기화했다.

| 값    | 의미                    | 조회 기준                             |
| ----- | ----------------------- | ------------------------------------- |
| NULL  | 기존 기록               | 기존 마커·집계 해석 유지              |
| FALSE | 과거 답안의 결과만 복구 | XP가 양수여도 출석을 새로 만들지 않음 |
| TRUE  | 실제 활동으로 인정된 날 | 후속 완료 복구가 FALSE로 내리지 못함  |

오늘의 새 답안 저장은 정오와 무관하게 기존 정책대로 학습일을 인정한다. 지연 완료는 기존 완료 보상·완료 횟수를 한 번 정산하되, canonical 최초 답안이 오늘 저장되지 않았고 다른 인정 활동도 없으면 오늘 출석·연속일을 만들지 않는다. 기존 일별 인정 여부는 **완료 집계를 더하기 전**에 판단한다. 레슨·가나·회화 writer도 실제 활동의 TRUE를 보존한다.

오늘 단어 목표는 기존 KST 고유 단어 답안 집계다. 지연 완료의 XP·완료 통계가 목표 수치에 더해지지 않는다. SRS·복습 기한은 실제 새 답안의 기존 정책으로만 처리한다. 가나 `progress` 경로는 기존의 학습 분량/출석 해석을 TRUE로 보존하며, 이 경로 자체가 연속일을 갱신하지 않던 정책까지 새로 정의하지 않는다. 실제 가나·퀴즈·레슨 답안 경로의 한 문항 인정과 연속일 갱신은 유지한다. 응답의 `hasStudied`는 기존 Boolean 계약을 유지하며 모바일·웹은 명시적 FALSE를 XP fallback으로 덮어쓰지 않는다.

## 검증 환경과 결과

운영 인증이나 데이터를 복제하지 않고, loopback FastAPI·폐기형 PostgreSQL·가짜 인증 계정·전용 iOS 시뮬레이터 번들로 검증했다. 실제 제품 API/ORM과 앱 화면 콜백을 사용했다. 운영 Supabase 로그인 및 실제 네트워크의 운영 장애까지 확인했다는 뜻은 아니다.

- 로컬 DB 두 개: q7 upgrade → downgrade → upgrade 성공. 기존 일별 행과 ACL·RLS·Data API 차단 설정 동일.
- Prisma validate/generate 및 실제 DB와 schema diff: 통과, drift 0.
- API: 비 PostgreSQL 1,304개 통과(기존 조건부 테스트 13개 skip), 실제 PostgreSQL 324개 전부 통과. Ruff/format 332파일, Mypy 186파일 통과. OpenAPI 108경로와 모바일 62 Dio 호출·5 모델 계약 일치.
- 웹: 단위·UI 526개 + 실제 Prisma/PostgreSQL 10개 통과. 타입·린트·프로덕션 webpack 빌드 통과. 기본 Turbopack 빌드는 로컬 실행 환경에서 진전 없이 대기해 해당 프로세스만 종료했고, 같은 최종 소스를 webpack 프로덕션 빌드로 검증했다.
- 공유: Prisma 및 database/types lint, admin 직접 소비자 typecheck 통과. API·웹·모바일의 새 학습일 Boolean 응답 타입 변경 없음.
- 모바일: 최종 전체 테스트 1,091개 통과, analyze 문제 0개, source diff whitespace 통과. 최종 시뮬레이터 검증 동안 제품 소스는 변경하지 않았다.
- 첫 시뮬레이터 읽기 검증: 30일 매칭·7일 문장 배열·3일 일반의 동일 세션 재개, 프로세스 종료 후 다음 위치 복원, 목록 503 재시도 성공. 목록에 나타나지 않는 더 최신의 무응답 세션 26개가 있어도 저장 세션 4개가 노출됐다.
- 첫 읽기 검증 전후 사용자·퀴즈·답안·일별 통계·SRS·레슨·활동 영수증·음원 캐시·보안 지문 전체 동일. 이 단계의 새 시작/답안/완료 쓰기는 0건이었다.

GitHub 원격 CI는 아직 실행하지 않았다. 로컬에서 실제 JUnit/JSON을 CI 검사기에 통과시켰다. CI는 테스트 수만 검사하지 않는다. PostgreSQL 필수 324개, 웹 완료·보존 29개, 웹 실제 PostgreSQL 10개를 정확한 이름과 통과 상태로 검사한다. 누락·skip·중복은 실패한다. 웹 실제 DB 테스트는 schema-drift의 로컬 PostgreSQL 서비스에서 별도로 실행한다.

### 실제 시뮬레이터의 결과 복구와 새 학습

가짜 로그인 계정을 유지한 전용 앱을 실제 프로세스 종료/재실행했다. Dart VM inspector에서 제품 화면의 버튼 콜백을 실행했으며 임의로 provider 상태를 주입하지 않았다. 테스트 목표는 기존 합성 계정의 30개를 그대로 사용했다.

| 조작                                       | 앱에서 확인한 결과                                  | 로컬 DB 대조                                                 |
| ------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------------ |
| 5일 전 5/5 저장 세션 열기 → 앱 종료·재실행 | 같은 세션·5/5 복원                                  | 답안·기록 변화 없음                                          |
| 결과 확인 버튼 연속 실행                   | 완료 POST 한 번, 100%·5/5·+50 XP                    | 완료 한 행, XP +50 한 번, 오늘 `study_day_credited=false`    |
| 홈·앱 완전 재실행                          | 오늘 미인정, 연속 0일, 0/30, 주간 XP50·단어0        | 원래 답안·SRS·목표 설정·다른 세션 그대로                     |
| 같은 완료를 로컬 HTTP로 한 번 재전송       | 응답 200                                            | 전체 추적 행·보안 지문이 직전 상태와 완전히 동일             |
| 3일 지난 일반 퀴즈에서 새 답안 하나 저장   | 3/5 저장, 오늘 인정, 연속 1일, 1/30(3%)             | FALSE→TRUE, 답안 한 행만 추가, XP/완료 횟수 변화 없음        |

저장 목록에서 완료된 항목이 사라지는 것은 정상이다. 완료 후 같은 항목을 UI에서 다시 열었다고 주장하지 않는다. 중복 완료의 UI 연속 조작과 별도 HTTP 재전송을 구분해 검증했다. 새 답안의 대상 SRS는 정상 학습 정책대로 생성되며, 관련 없는 기존 SRS/복습 기한은 그대로였다.

## 검증 중 함께 보완한 결함

실제 마이그레이션을 거친 DB에서 가나 진도 INSERT가 필수 `updated_at`을 생략하는 기존 결함을 발견했다. 답안 저장 시각과 같은 값을 INSERT/UPDATE에 명시해 기존 DB 구조를 그대로 사용한다. 오래된 serializer를 답안·완료 경로로 직접 보내는 경우도 500 대신 무변경 409로 거절한다. 이미 저장된 동일 답안 및 기존 완료 결과의 재조회는 먼저 복구한다.

웹에서는 저장 ACK 후 이어하기 목록 무효화를 추가해 진행률이 즉시 갱신되도록 했다. 저장 대기/실패 중에는 포인터뿐 아니라 키보드로도 뒷화면 문항을 더 제출하지 못하도록 막고 재시도 조작은 열어둔다.

기존 보안·파티션 마이그레이션 회귀 중 일부는 옛 스키마 상태에서 최신 ORM으로 학습 smoke를 실행했다. 해당 과거 migration의 권한·범위·롤백 검증은 그 revision에서 그대로 수행하고, 최신 앱 smoke 직전에 로컬 head로 올리는 방식으로 정렬했다. 과거 보안 검증을 삭제하거나 운영 DB를 바꿔 테스트를 통과시키지 않았다.

## 운영 적용 전 제시할 구체안

다음 단계는 아직 수행하지 않았다. 사용자 승인 후 대상 DB·revision·배포 경로를 읽기 전용으로 다시 확인해야 한다.

1. 현재 API·웹 revision, Alembic p6, 로그인 경로, Data API 차단, 기존 ACL/RLS와 학습 기록 기준선을 기록한다. 이전 웹 배포 URL 및 내부 테스터의 쓰기 경로도 확인한다. 필요한 변경은 이 컬럼과 호환 배포뿐이며, 새 환경 변수·WAF·Preview 인프라를 추가하지 않는다.
2. 내부 테스터에게 짧은 사용 중지를 요청하고 진행 중 쓰기를 정리한다. 기존 STOP 기능 또는 자동 배포 일시 중지를 사용할 경우 대상·시간·원복값을 승인 범위로 명시한다. 이 문서를 작성했다는 이유로 설정을 변경하지 않는다.
3. 확인된 p6에서 `alembic upgrade q7r8s9t0u1v2`로 승인된 단일 q7 DDL을 먼저 적용한다. 다른 revision이면 임의로 head까지 올리지 않는다. migration role·현재 RLS·차단 schema·권한을 사전 확인하고, lock timeout 2초/statement timeout 15초를 사용한다. 실패하면 timeout이나 보안 검사를 완화하지 말고 트랜잭션을 원복한 뒤 원인을 확인한다. 새 ORM을 먼저 배포하면 없는 컬럼 SELECT 오류가 나므로 순서를 지킨다.
4. 새 컬럼을 읽고 실제 활동에 TRUE를 쓰는 호환 빌드를 API·웹 양쪽에 배포한다. `STUDY_DAY_CREDIT_SEPARATION_ENABLED=false`인 **소스 빌드**를 사용하며 새 환경 변수는 없다. 읽기·새 시작의 세션 보존과 웹 답안 ID 안전성은 유지한다. 명시적 FALSE가 이미 있다면 OFF도 이를 존중한다. 대상 상수는 API `app/services/study_day_credit.py`와 웹 `src/lib/study-day-policy.ts`의 `STUDY_DAY_CREDIT_SEPARATION_ENABLED`이며, 기존 `ANSWERED_STUDY_DAY_RECOGNITION_ENABLED=true`는 그대로 둔다.
5. 알려진 구 writer가 더 이상 쓰지 않는 것을 확인한 뒤 양쪽 분리 flag가 TRUE인 빌드를 활성화한다. 오래된 웹 주소가 접근 가능한 상태라면 canonical 도메인 전환만으로 해결됐다고 판단하지 않는다. 전환을 보장할 수 없으면 활성화를 미룬다.
6. 새 목록을 쓰는 웹·앱을 반영하고 시뮬레이터로 로그인·일반/매칭/문장 배열 재개·오류 재시도·지연 완료·새 답안·달력·오늘 목표를 확인한다. 합성 또는 명시적으로 승인된 테스트 계정의 변경만 허용하고 기존 기록·SRS·음원·Data API 지문과 자동 배포 원복을 확인한다.

- 학습일 정책 문제: FALSE를 이해하는 호환 API·웹에서 **신규 FALSE 생성만 OFF**로 돌린다. 실제 활동은 계속 TRUE로 올리고 이미 저장한 FALSE는 XP만으로 TRUE가 되지 않는다.
- 답안 재시도 문제: ACK 대기·같은 attempt ID 재전송과 저장 답안 보호를 유지하는 호환 버전으로 수정한다. 중복 반영 가능한 구 웹 writer로 돌아가지 않는다.
- 운영 컬럼 삭제, FALSE→NULL 일괄 변경, 과거 완료 초기화·XP 회수·복습 기한 재계산은 하지 않는다. downgrade는 모든 값이 NULL인 로컬 리허설에서만 통과하며, 인정 결정을 저장한 뒤에는 실패하도록 막았다.
- 과거 24시간 자동 종료 및 새 시작 자동 정산 버전은 보존 중인 세션을 다시 닫을 수 있으므로 롤백 후보로 사용하지 않는다.

# 실전회화 전사 언어 힌트와 시작 감도 수정

## 문제와 변경

실기기 공항 통화의 사용자 전사에 의도하지 않은 스페인어 형태의 짧은 문자열이 나타났다. 당시 사용자는 외부에서 Bluetooth 이어폰을 사용했다. 기존 앱은 음성 시작 감도를 `START_SENSITIVITY_HIGH`로 명시하고 입력 전사 언어 힌트를 제공하지 않았다.

| 설정 | 기존 | 변경 |
|---|---|---|
| 음성 시작 감도 | 명시적 HIGH | 필드 생략, 서버 기본 동작 사용 |
| 입력 전사 | 빈 설정 | `languageCodes: ['ja-JP', 'ko-KR']` |
| 종료 감도·prefix·침묵 대기 | END_HIGH·200ms·사용자 설정 | 유지 |
| 모델·응답 언어·출력 전사 | Live 3.8·일본어/한국어 도움 | 유지 |

새 연결과 토큰 갱신 뒤 재연결에 같은 설정을 사용한다. `UNSPECIFIED`나 `LOW`를 대신 전송하는 변경은 아니다. 언어 힌트는 예상 언어를 알려주는 값이며 다른 언어를 차단하는 허용 목록이 아니다. 전사 원문을 번역·치환하거나 과거 기록을 덮어쓰지 않는다.

## HIGH 생략을 선택한 근거

2026-11-04에 공식 문서와 Google SDK 이슈의 최신 상태를 다시 확인했다.

- [Live API reference](https://aistudio.google.com/api-reference/live#StartSensitivity)는 문서상 기본 감도를 HIGH로 설명한다. 따라서 필드 생략을 감도 LOW 전환이라고 설명하면 안 된다.
- [공식 SDK issue #3193](https://github.com/googleapis/python-genai/issues/3193)는 명시적 HIGH와 필드 생략이 Gemini 3.8에서 다르게 동작한 사례다. [Google 담당자의 10월 27일 확인](https://github.com/googleapis/python-genai/issues/3193#issuecomment-6432952643)은 잡음 clip에서 HIGH 3/3 재현, 기본 VAD 0/3 비교를 기록한다. 확인 당시 이슈는 open이며 마지막 갱신일은 10월 27일이다.
- LOW는 해당 보고에서 짧은 응답 누락 사례도 있었다. 현재 수정은 짧은 일본어 응답에 대한 민감도를 임의의 LOW로 고정하지 않고, 문제와 직접 관련된 명시적 시작 감도만 생략한다.
- 이 근거는 특정 모델 동작의 우회 방안이다. 우리 통화 원음이 없으므로 같은 원인이었다거나 야외 인식 품질이 개선됐다고 아직 확정하지 않는다. 종료 감도 등 나머지 조건을 유지해 변경 범위를 좁힌다.

## 영어 힌트 판단

[AudioTranscriptionConfig reference](https://aistudio.google.com/api-reference/live#AudioTranscriptionConfig)는 `languageCodes`를 BCP-47 언어 힌트로 정의하며, 생략 또는 빈 목록은 자동 언어 감지라고 설명한다.

이번 서비스는 일본어 회화와 한국어 학습 도움을 지원하므로 예상 입력 언어를 일본어·한국어로 제공한다. 영어 힌트를 추가하면 이 서비스의 일본어 인식 정확도가 좋아진다는 공식 비교 근거는 확인하지 못했다. 이는 영어가 성능을 낮춘다는 증명도 아니다.

영어 이름·공항 코드·차용어가 있다는 이유만으로 영어 문장 인식을 위한 세 번째 힌트가 필수는 아니다. 영어 문장 대화가 실제 제품 요구로 확인되면 ja/ko와 ja/ko/en 조건을 따로 평가한다. 이번 변경은 영어를 차단하지 않는다.

## 검증

로컬 회귀 검사는 다음을 확인한다.

- 실제 serializer에서 시작 감도 key가 없고 입력 전사 힌트가 정확한 위치에 있다.
- 서비스 최초 setup과 두 차례 토큰 갱신 후 setup이 같은 정책을 유지한다.
- 음성 형식·모델·종료 감도·침묵 설정·세션 재개·기존 프롬프트가 보존된다.

최신 main `3bc22f36` 기준으로 관련 14개 검사와 전체 모바일 1,221개 검사, 전체 analyze를 통과했다. dependency·lockfile·플랫폼·환경 계약은 바꾸지 않는다.

실제 provider 호환성은 수정된 Dart serializer의 비밀값 없는 setup으로 별도 확인한다. 같은 v1alpha constrained 경로에서 ephemeral token을 사용해 `setupComplete`까지만 확인하며, 음성·인사·사용자 전사는 보내지 않는다. 이 검사는 필드 수용을 확인할 뿐 음질·인식률 개선을 보증하지 않는다.

아이폰 설치 빌드는 같은 소스·기존 운영 환경·같은 bundle/team/keychain 식별자를 사용한다. 설치 전후 저장 설정을 비교하고, 이후 같은 이어폰에서 정해진 일본어 문장과 짧은 응답·무발화 구간을 실제로 대조한다. 아이폰 설치와 실음성 검증 결과는 해당 작업의 실행 기록과 PR에 구분해 남긴다.

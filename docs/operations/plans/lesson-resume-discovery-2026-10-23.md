# 저장된 레슨을 학습 목록에서 발견하고 이어가기

## 문제와 범위

PR #192는 같은 기기·같은 계정의 레슨 위치와 답안을 복원한다. 그러나 단어·문법 단계의 로컬 저장은 서버의 연습 시작보다 앞선다. 서버 목록이 NOT_STARTED인 레슨에도 저장된 진행이 있을 수 있으며, 현재 학습 탭과 전체 목록은 서버 상태만으로 추천한다. 학습자가 원래 레슨을 스스로 다시 찾아야 저장된 위치가 드러난다.

2026년 10월 23일 사용자는 후속 작업과 다음 작업의 진행을 요청했다. 이번 구현은 기존 로컬 저장의 발견성과 진입 경로를 학습 탭·전체 레슨 목록에 연결한다. API·DB·기존 복습 기한·로그인·Data API 설정은 변경하지 않는다. 원본 미커밋 작업 폴더는 유지하고 별도 작업 트리에서 구현한다.

## 설계 경계

- 저장된 레슨은 서버의 추천·완료·점수·역 스탬프와 구분한다. 로컬 저장으로 서버 상태를 덮어쓰지 않는다.
- 현재 계정과 현재 레벨에 공개된 레슨 ID만 대상으로 로컬 저장을 읽는다. 인증 키나 다른 계정의 키를 조회하지 않는다.
- 기존 체크포인트에는 저장 시각이 없으므로 가장 최근 학습이라고 표시하거나 임의의 최신 순서를 만들지 않는다. 복수 저장은 사용자가 고를 수 있도록 한다.
- 목록은 저장된 진행의 진입점이다. 실제 복원 가능 여부와 콘텐츠·서버 상태의 검증은 레슨에 들어간 뒤 기존 상세 조회·복원 로직이 판단한다. 상세 정보 없이 총 문항 수·복원 확정·정확한 퍼센트를 만들어내지 않는다.
- 제출 확인 중인 저장은 일반 이어하기와 구분하고 자동 재제출하지 않는다. 깨진 저장·알 수 없는 버전·기록 확인이 필요한 상태를 안전하게 다룬다.
- 목록을 표시하기 위해 각 레슨의 상세 조회를 반복하거나 학습 시작·제출 요청을 만들지 않는다.
- 로컬 읽기 실패가 기존 추천과 다른 레슨 진입을 막지 않아야 한다. 성공한 저장·완료·삭제와 레슨에서 돌아온 뒤 표시가 갱신돼야 한다.

## 검증

뒤쪽 레슨의 서버 미시작·로컬 저장, 복수 저장, 서버 진행 중이지만 로컬 저장 없음, 완료 레슨의 재학습 저장, 계정·레벨 변경, 제출 확인·깨진 저장, 저장소 실패·복구와 완료 후 삭제를 검사한다. 실제 레슨 경로로 진입해 기존 복원과 연결되는지 확인한다. 목록 조회의 레슨별 상세 GET·start·submit은 없어야 한다. 320px·글자 200%와 접근성 의미를 확인한다.

좁은 회귀 후 모바일 전체 테스트·정적 분석·포맷과 독립 검토를 수행한다. 실행한 결과와 제한은 완료 시 덧붙인다. 실제 운영 DB·기기 설치·계정 전환을 로컬 회귀 결과와 혼동하지 않는다.

## 관련 후속 설계

PR #192의 레슨·퀴즈 SRS 비교 결과는 별도 정책 검토로 정리한다. 기존 복습 기한에 영향을 주는 정책 통합과 API·DB 변경은 구체적인 영향안을 먼저 확인해야 한다. 이번 모바일 목록 개선에 정책 변경을 묶지 않는다.

## 롤백

모바일 표시·조회 변경을 revert하면 된다. 서버 데이터와 기존 복습 기한의 보정이나 DB 롤백은 필요하지 않아야 한다. 기존 체크포인트를 읽기만 하던 진입점의 제거가 저장된 답안이나 인증 상태를 삭제하지 않는다.

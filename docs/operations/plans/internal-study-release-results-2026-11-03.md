새 활동 뒤 B 계정에서도 세 번째 OS 종료·재실행(PID75163→96279)을 수행했다. 연속 1일·오늘 체크·목표 0/20개·0%·주간 오늘 점·단어 0개·XP 0이 유지됐고 자동 음성 재생은 없었다. 실제 저장 목록으로 같은 레슨을 다시 열었을 때 레슨 ID·이해 체크 위치·선택한 오답·문항 순서 seed가 동일했다.

원래 계정 A로 정상 SDK 로그인해 돌아왔을 때 목표 30개·오늘 1/30개·3%·퀴즈 1/8·연속 1일이 같았다. A의 저장 목록 두 개와 원래 레슨 2/2·답안·seed도 유지됐다. 최종 DB 비교에서 A의 전체 학습 지문과 기존 receipt 2개는 동일했다. B에는 새 activity 정확히 1개·오늘 마커 1개·연속 1일만 반영됐고 목표 20개·오늘 단어 0개·일일 XP 0·누적 XP 300이 유지됐다. 두 계정의 기존 SRS 기한·완료 레슨·음원 캐시·카탈로그/권한 보호가 동일했고 새 퀴즈 답안·최종 레슨 제출은 없었다.

사용한 QA 앱을 종료하고 Flutter attach 프로세스 네 개가 정상 종료된 것을 확인했다. 전용 QA 시뮬레이터는 원래 Shutdown 상태로 돌렸으며, 기존 사용자 시뮬레이터와 실물 아이폰에는 명령을 실행하지 않았다. 테스트 API·PostgreSQL 종료는 별도 증거로 남긴다.

운영 API/DB 검증은 앞 절의 실제 운영 증거이고, 이 후속 UI 검증은 로컬 합성 환경의 실제 앱 실행 증거다. 이번 검증을 위해 운영 DB·설정·기존 로그인·학습 기록·음원 캐시를 추가 변경하지 않았다. 기능 코드 수정 없이 완료했다.

### 테스트 환경 복구

원래 테스트 PostgreSQL이 Mac의 SysV shared-memory ID 한도로 시작하지 못했다. 기존 QA 로그로 생성 프로세스를 연결한 56바이트 임시 세그먼트 1개에 대해 현재 사용자 소유·연결 0·생성 PID 종료·마지막 PID 0을 재확인한 뒤 그 ID만 정리했다. DB 파일·커널 설정·다른 프로세스를 바꾸지 않았고, 원래 데이터와 포트로 한 번 재시동해 health 200을 확인했다. 운영 DB에 대한 조치는 아니다.

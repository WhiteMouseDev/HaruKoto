# 가나·웹 완료 저장과 계정별 목표 보완

작성일: 2026-11-03 KST. [구현 재검토](study-metrics-correctness-review-2026-11-02.md)의 F1·F2·F3을 사용자가 수정·회귀 검증하도록 승인했다. 운영 적용 전 결과를 먼저 보고한다. 작업 브랜치는 `codex/study-completion-safety`, 시작점은 `3d1cdcec`이다. 기존 #215 호환 OFF 구현 위의 후속 작업이며 #215/#216을 병합하거나 활성화하지 않는다.

## 수정 범위

1. FastAPI 가나 퀴즈: 사용자→세션 잠금 안에서 최초 완료와 재전송을 구분한다. 완료 표시·보상·일별 집계를 하나의 commit에 담고 실패 시 rollback한다. 새 문항별 영수증 지원 세션은 필요한 저장 답안이 모두 있는지 확인한다.
2. FastAPI 가나 스테이지: 미완료→완료 전이에서만 보상과 학습일을 기록한다. 재전송으로 최초 완료 시각·점수·보상을 덮어쓰지 않는다.
3. 웹 일반/가나 퀴즈와 가나 스테이지: 완료 상태·일별 집계·사용자 XP·업적·알림을 같은 Prisma transaction으로 처리한다. 잠금 대기 뒤 완료를 다시 확인하고, 이미 처리했다면 추가 쓰기 없이 결과를 반환한다. 새 퀴즈 시작의 이전 미완료 세션 자동 완료도 같은 사용자→세션 잠금을 사용하고, 실제 전이한 세션만 원자적으로 집계한다.
4. 모바일: 계정별로 확인된 하루 목표를 저장하고 표시한다. 소유자를 알 수 없는 기존 공통 캐시를 다른 계정의 확정 목표로 이관하지 않는다. 프로필의 늦은 응답과 목표 변경 경합도 검증한다.

## 계약·데이터 보존 경계

새 API 경로·요청/응답 필드·DB 테이블/컬럼·환경 변수·패키지를 추가하지 않는 안으로 구현한다. 최초 정상 완료의 보상 계산은 유지하고 중복 부작용만 제거한다. FastAPI의 재전송 응답은 기존 일반 완료 패턴처럼 신규 지급 XP 0·이벤트 빈 목록을 반환하며, 웹은 기존 결과 표시 방식의 계산된 XP를 유지하되 실제 지급은 반복하지 않는다. 서로 다른 기존 표시 의미를 이번 수정에서 강제로 통일하지 않는다.

문항별 답안 영수증이 없는 구 가나 세션은 새 영수증을 요구하지 않고 최초 완료를 호환 처리한다. 이전 기록을 백필하거나 수정하지 않는다. 이미 완료된 구 세션은 보상을 다시 만들지 않는다. 새 영수증 지원 가나 세션의 미저장 문항은 기존 오류 형식으로 거부한다.

로그인·기존 답안/진도·복습 기한·오늘 고유 단어 집계·음원·Data API 차단·권한/RLS를 바꾸는 운영 작업은 없다. 웹의 만료 연속일 표시(F4)와 오늘 목표 기준 정렬(F5)은 후속 범위다.

## 검증 계획

- 같은 완료의 동시 요청·응답 유실 뒤 재전송·다음 날 재전송이 실제 보상/집계를 한 번만 만든다.
- 완료 표시 이후 일일 기록·사용자·업적·알림 저장에서 실패를 주입하면 전체가 rollback되고 같은 요청으로 복구된다.
- 구 완료 세션/구 가나 세션과 새 영수증 지원 세션을 각각 검사한다.
- 기존 답안·SRS·목표 집계·다른 사용자·보안 메타데이터를 보존한다.
- 모바일 A→B 전환, B 프로필 실패, A의 늦은 응답, 목표 변경 성공/실패/취소, 계정별 캐시와 재시작을 검사한다.
- 관련 실제 PostgreSQL 회귀가 CI에서 누락·skip되지 않도록 필수 JUnit gate에 등록한다.

## 운영 적용 전 남는 조건

이 브랜치는 운영 미적용 학습일 스키마/호환 코드 위에 있다. [기존 전환안](study-day-font-fix-and-rollout-2026-11-02.md)의 마이그레이션·자동 배포 통제·구 writer 종료·별도 활성화 승인 조건은 계속 유효하다. 이번 수정에 새 DDL이 없다는 이유로 운영에 바로 배포하지 않는다. 운영 적용 여부는 실제 검증 결과와 함께 다시 판단한다.

웹의 실제 DB 검증은 가짜 Prisma IO가 아니다. 동시 완료 요청과 자동 완료/명시적 완료의 경합을 실행했고, DB trigger로 세션·일일 통계·사용자·알림 저장을 실패시켰다. 완료 표시·보상·업적이 함께 rollback되고 같은 요청으로 한 번만 반영됐다. 실제 DB 18개는 이번 수동 실행 증거이며, 저장소의 새 웹 회귀 31개와 겹치므로 합산하지 않는다.

자동 완료는 기존 부분 퀴즈 보상 계산과 신규 퀴즈 생성 응답을 유지한다. 기존 자동 완료의 level/streak 미갱신 정책까지 이번에 바꾸지는 않았다. 수정한 것은 이전 snapshot으로 완료와 보상을 다시 적용하던 경합이다.

웹 native 가나의 최초 무답안 완료/세션 타입 거절 강화는 별도 계약·호환 검토 대상으로 남긴다. 이번 범위의 중복·실패 복구와 새 tagged API 세션의 영수증 검증을 전체 과거 세션의 답안 증명으로 확대해 설명하지 않는다.

독립 검토에서는 자동 완료 writer가 새 완료 처리의 중복 방지를 우회할 수 있음을 추가로 찾아 같은 범위에 포함했다. 수정 후 API·웹 완료 원자성과 모바일 계정/목표 변경 세대·직렬 캐시 저장을 다시 검토했고 추가 P1/P2 finding은 남지 않았다. 이 검토는 소스와 실행 증거 기준이며 운영·실기기 재검증은 아니다.

# 이번 퀴즈 오답 복습과 오류 화면 개선

## 목표와 현재 상태

일본어 입문~N5 학습자가 결과 화면의 ‘이번 오답 복습’을 누르면 **해당 퀴즈에서 실제로 틀린 항목만** 다시 연습한다. 목록 조회 실패, 퀴즈 시작·복구 실패, 진짜 빈 상태를 구분한다. 사용자는 기존 학습 기록과 Data API 차단을 유지하고, DB 또는 API 계약 변경이 필요하면 구체안을 먼저 설명하도록 요청했다.

2026-10-21 사용자가 상세 API 추가안을 승인해 서버·앱·회귀 테스트의 구현과 로컬 검증을 완료했다. 이 문서의 API 안은 승인 전 검토용으로 제시했고 승인 후 구현 범위로 확정했다. 운영 DB 조회·변경·배포는 수행하지 않았다. 기존의 아주 많은 미커밋 변경과 분리해 관리 작업 트리의 `codex/quiz-wrong-review-errors`에서 작업했다. PR 병합·운영 배포·아이폰 반영 완료로 취급하지 않는다.

## 확인한 원인

- 결과 화면은 `GET /api/v1/quiz/wrong-answers?sessionId=...`로 원본 세션 오답 목록을 받지만, 복습 버튼은 원본 ID 없이 `POST /api/v1/quiz/start`의 `mode=review`, `count=10`을 호출한다. 이 모드는 복습 기한이 된 일반 항목을 고른다.
- 현재 `QuizStartRequest`에는 원본 세션이나 지정 문항 입력이 없다. `stageId`는 실제 학습 스테이지 ID이며 세션 ID·문항 목록을 대신 넣을 수 없다.
- 기존 퀴즈 시작은 먼저 `auto_complete_sessions()`로 다른 미완료 퀴즈를 완료 처리하고 XP를 반영한다. 오답 복습에 그대로 재사용하면 원본과 다른 기록을 보존한다는 요구와 맞지 않는다.
- `QuizSessionController.initialize()`는 실패를 빈 문항 상태로 바꾼다. 결과 화면도 오답 목록의 오류 상태를 표시하지 않으며, 세션 전환 때 이전 목록이 남을 수 있다.

근거: `apps/mobile/lib/features/study/presentation/quiz_result_page.dart`, `presentation/quiz_launch.dart`, `providers/quiz_result_provider.dart`, `providers/quiz_session_provider.dart`, API `app/schemas/quiz.py`, `app/services/quiz_start.py`, `quiz_mode_questions.py`, `quiz_session.py`.

## 승인 없이 진행 가능한 오류 화면 범위

1. 퀴즈 준비 실패를 빈 콘텐츠로 표시하지 않고 `ApiException.userMessage`를 통해 안내한다.
2. 기존 세션 이어 풀기 실패는 **같은 세션 ID로** 재시도한다. 새 퀴즈 생성 응답이 실패한 경우 서버 생성 여부를 단정할 수 없어 자동 POST 재전송을 하지 않고 학습으로 돌아가 확인할 수 있게 한다. 정확한 신규 생성 재시도에는 별도의 멱등 설계가 필요하다.
3. 결과의 오답 목록에 로딩·오류와 GET 재시도·실제 빈 목록·목록 표시를 분리한다. 실패하거나 목록이 없는 상태에서는 일반 복습으로 우회하지 않는다.
4. 세션 전환·dispose·늦게 도착한 이전 요청으로 다른 세션의 목록이나 저장 상태가 섞이지 않게 한다.
5. 기존 선택지 채점·답안 저장·XP·SRS·로그인·API 요청·응답 형식은 유지한다.

## 사용자 검토용 API 추가안

### 요청과 응답

새 엔드포인트 **`POST /api/v1/quiz/wrong-answer-review/start`**를 추가한다.

```json
{"sourceSessionId": "완료한 원본 퀴즈의 UUID"}
```

요청은 원본 ID 하나뿐이다. 타입·레벨·개수·임의 항목 ID는 클라이언트로부터 받지 않고 서버가 원본으로 결정한다. 성공 응답은 기존 `QuizResumeResponse`와 같은 스키마를 재사용한다.

```text
sessionId, questions, answeredQuestionIds, totalQuestions, correctCount, quizType
```

새 복습이면 답안 ID는 빈 목록이고, 이미 진행 중인 같은 원본의 복습이면 저장한 답안과 다음 문제를 복원한다. 기존 시작·기한 복습·일반 이어 풀기 계약은 바꾸지 않는다. 레벨 표시는 결과 화면이 가진 원본 레벨을 사용한다.

### 범위와 무결성

- 1차 지원은 일반·스마트 및 이번 오답 복습 결과의 **단어/문법/한자/듣기 선택형 퀴즈**다. 복습 결과에서 다시 복습하면 그 복습 시도에서 틀린 항목만 대상이 된다. 가나·매칭·빈칸 특수 모드·문장 배열 등 저장·답안 구조가 다른 유형은 별도 지원 전까지 명확한 미지원 안내를 제공하며 다른 항목을 대신 내지 않는다.
- 본인 소유의 완료된 원본만 허용한다. 원본 문항별 최초 저장 답안을 `answered_at, id` 순서로 하나 선택하고 원본 스냅샷의 문항과 대조한다. 최초 정답 뒤 중복 오답이 있는 과거 기록을 현재 오답으로 오인하지 않는다.
- 기존 오답 목록 GET도 같은 canonical 최초 답안 규칙을 공유해 표시와 실제 출제 대상을 맞춘다. 응답 키는 유지한다. 이 동작 교정도 승인 후 범위이며 과거 답안 행을 삭제·수정하지 않는다.
- 전체 원본 문항에 답안이 있어야 한다. 자동 완료된 부분 풀이, 원본 중복 ID·손상된 보기/정답·정오 불일치·삭제된 카탈로그 대상은 전체 실패로 처리한다. 임의 추측이나 일반 복습으로 대체하지 않는다.
- 해당 오답의 원본 문항·보기·정답·순서를 새 세션에 복제한다. 원본 문제나 다른 학습 항목을 추가하지 않는다.
- 원본 행을 잠가 동일 원본의 시작 요청을 직렬화한다. 같은 원본의 복습이 **진행 중인 동안**에는 반복 요청을 같은 세션으로 돌려준다. 완료되거나 기존 정책에 따라 자동 종료된 뒤 다시 시작하면 새 시도로 취급한다. 원본 ID만으로 완료 후 지연 재전송과 명시적인 새 시도를 구별할 수 없으므로 완료 이후까지의 영구 멱등성을 약속하지 않는다.
- 기존 `quiz_sessions.questions_data` JSON의 **새 복습 세션에만** `mode=wrong_answer_review`, `source_session_id` 메타데이터를 저장한다. `stage_id`는 복제하지 않고, 이 모드의 완료 요청은 앱이 명시적인 `stageId`를 보내도 무시하여 부분 오답 복습이 원본 스테이지를 완료 처리하지 않게 한다.
- **신규 오답 복습 시작 API를 호출하는 동안** 원본·다른 세션·기존 답안·점수·XP를 수정하거나 자동 완료하지 않는다. 사용자가 새 복습을 실제로 풀면 그 **새 답안에 한해 기존 퀴즈 정책대로** 학습 상태와 XP가 갱신된다. 다른 일반 퀴즈 시작의 자동 완료와 미완료 조회의 24시간 종료 등 기존 정책 자체를 이번에 변경하거나 무효화하지 않는다. SRS 집계 정책 변경이나 과거 상태 재계산은 포함하지 않는다.

### 실패와 호환성

| 상태 | 동작 |
| --- | --- |
| 성공 | HTTP 200, 신규 또는 진행 중인 같은 원본의 복습 세션 반환 |
| 원본 없음·다른 사용자 | 404, 원본 존재 여부 노출 방지 |
| 미완료·전체 답안 없음·오답 0·손상/삭제 콘텐츠 | 409, 새 세션과 학습 쓰기 없음 |
| 미지원 퀴즈 유형 | 400, 일반 복습 대체 없음 |
| UUID 형식 오류 | 422, 기존 입력 검증 형식 유지 |
| 네트워크·서버 실패 | 오류 상태 표시, 동일 원본으로 재시도 |

새 DB 테이블·컬럼·마이그레이션·권한·RLS·Data API 설정·환경 변수·제품 의존성 변경은 필요 없다. 기존 앱은 기존 API를 계속 사용한다. 새 앱은 신규 API 배포 전에는 안전하게 오류를 표시하고 일반 복습으로 우회하지 않는다. 서버 먼저, 앱 나중 순서로 출시한다.

승인 후 OpenAPI 스냅샷과 생성 TypeScript 타입을 갱신하고 web/mobile 호환성을 검증했다. 공유 타입 수정은 shared-packages-agent가 담당했다. 이번 승인은 API 추가·소비자 구현 범위이며 서버 배포와 실기기 설치는 포함하지 않았다.

## 회귀 테스트 계획

- 결과 화면: 세션 A 오답만 표시, A→B 전환과 응답 역전, 로딩·오류·재시도·빈 목록, 조회 실패 시 복습 우회 없음.
- 시작·복구: 실패와 빈 목록 분리, resume 재시도의 원본 ID 보존, 새 start의 불확실한 실패 후 자동 재전송 없음, dispose·늦은 응답 무시.
- 승인 후 API: 본인/다른 사용자 격리, 완료/부분 풀이, 오답 0, 원본 스냅샷 교집합, 최초 답안 중복 규칙, 지원/미지원 유형, 훼손·삭제 콘텐츠의 원자적 거부.
- 승인 후 실제 PostgreSQL: 더블 탭·동시 요청·응답 유실 재시도에서 같은 진행 중 세션, 부분 답안 복원, 완료 후 새 시도, 원본·다른 미완료 세션·원본 XP 불변, 신규 답안 중복 제출 방지.
- 모바일·web 호환: 기존 일반 기한 복습과 일반 퀴즈 이어 풀기 회귀 유지. 백엔드 채점·저장 경로를 우회한 로컬 가짜 퀴즈를 만들지 않는다.

모바일 통합 테스트는 실제 결과 CTA → 원본 오답만 출제 → 새 복습에만 답안·완료 → 원래 결과의 점수·목록 복귀를 검증했다. 새 API 실패를 같은 원본으로 재시도하고 일반 복습 풀 호출이 0개인 것도 확인했다. 세션별 provider로 원본과 자식 결과를 분리했고, 단어장 일괄 저장 중 화면 전환·dispose의 늦은 응답도 다른 결과를 변경하지 않게 했다. 전체 테스트 후 마지막으로 같은 프레임의 빠른 두 번 탭을 막는 화면 진입 가드를 추가했고, 해당 조건을 넣은 결과·실제 복습 흐름 9개를 다시 통과했다. 서버의 세션 중복 방지와 앱의 화면 중복 방지를 각각 검증한 것이다.

저장 답안이 첫 문제부터 연속되지 않는 경우에는 실제 문항 ID 교집합으로 이미 푼 문제와 미답을 나눠 복원한다. 모든 답안이 저장됐으나 완료되지 않은 경우에는 문제를 다시 제출하지 않고 결과 저장만 재시도한다.

OpenAPI 최초 생성에서 원본 Python venv의 editable import가 원본 작업 폴더를 가리켜 무관한 `hasStudied` 변경을 넣은 것을 구조 비교가 검출했다. 관리 작업 트리를 명시한 `PYTHONPATH`로 다시 생성해 제거했다. pytest의 실제 앱·라우터·신규 서비스 import 경로도 관리 작업 트리임을 확인했다. 최종 명세에 무관한 변경은 없다.

이 결과는 로컬 폐기 PostgreSQL·단위/위젯·통합 테스트이며 운영 사용자 기록을 사용하거나 변경한 검증이 아니다. Data API·RLS·권한·DDL·환경 변수·의존성·lockfile을 변경하지 않았다. 기존 SRS 집계와 일반 퀴즈 자동 종료 정책도 유지한다. 실제 서버 배포와 아이폰 화면 확인은 후속 단계다.

독립 검토의 비차단 후속 제안은 이미 진행 중인 복습 자체의 훼손 조건에 대한 직접 PG 사례 보강이다. 현재 구현에는 유형·문항 수·스냅샷·스테이지 메타데이터·답안 범위·정답 수 불일치의 409 방어가 있다. 기존 기록을 임의 교정하지 않는다.

## 출시와 롤백

서버를 먼저 배포하고 신규 API의 정상·거부·재시도·기존 기록 보존을 검증한 뒤 앱을 배포한다. 새 앱에서 서버 API가 아직 없거나 실패하면 오류를 표시하며 일반 복습을 대신 시작하지 않는다. API 추가와 명세 생성은 기존 클라이언트 계약을 바꾸지 않았다.

되돌릴 때는 새 앱의 CTA·소비자부터 이전 동작 또는 기능 비노출로 전환하고, 신규 세션 유입을 멈춘 뒤 기존 진행 중 복습의 처리 방안을 검토한다. 신규 모드 세션이 생긴 후 서버를 단순히 이전 버전으로 돌리면 부분 복습의 stageId 차단 가드가 없어질 수 있으므로 임의 전체 revert만으로 운영 복구가 끝난다고 설명하지 않는다. 신규 복습 기록이나 원본 사용자 기록을 삭제·초기화하는 절차는 포함하지 않는다. 이번에는 운영 배포가 없어 운영 데이터 롤백은 필요하지 않다.

# 문장 음원을 순서대로 재생하는 대화 전체 듣기

상태: **구현·로컬 검증 완료, 실기기 신규 기능 검수 대기.** 2026-10-27 사용자가 전체 듣기·정지·다시 듣기·화면 이탈 취소와 회귀 테스트를 요청했다. 기존 로그인·학습 기록·Data API 차단을 보존하고 API/DB 변경이 필요하면 먼저 구체안을 제시하는 범위다. API/DB 변경 없이 모바일 코드만으로 구현했다.

## 문제와 구현 방향

HN5-004의 Kenzo·Shizuka v4 문장 음원은 운영에 연결됐지만 `reading.audioUrl`이 null이라 기존 ‘전체 듣기’ 버튼이 표시되지 않았다. 비교 화면의 통합 음원은 검수용 파일이다. 운영에 별도 통합 음원을 연결하면 콘텐츠 서명이 바뀌어 저장된 레슨 위치의 복원에 영향을 줄 수 있다.

이번에는 앱이 기존 문장 TTS endpoint를 차례로 호출하고 재생 완료 후 다음 문장으로 넘어간다. 새 통합 음원이나 API 계약·DB 스키마·레슨 내용·운영 설정 변경 없이 제공한다. 재생 전에 전체 레슨 음원을 대량 생성하거나 선조회하지 않는다. 기존 문장 endpoint의 캐시·생성 정책은 그대로 따른다.

## 사용자 동작

- 읽기 화면과 대화 다시 보기에서 ‘대화 전체 듣기’를 시작할 수 있다.
- 현재 재생 문장과 준비 상태를 표시하고, 준비 중에도 정지할 수 있다.
- 정지하면 남은 문장의 조회·재생을 취소한다. 이미 시작한 요청이 늦게 완료돼도 재생하지 않는다.
- 다시 듣기는 첫 문장부터 시작한다. 기존 문장별 재생과 전체 재생은 동시에 소리를 내지 않는다.
- 문장 조회·재생 실패 시 그 지점에서 멈추고 한글 안내와 재시도를 제공한다. 실패 문장을 건너뛰어 성공처럼 끝내지 않는다.
- 단계 이동·X로 닫기·뒤로가기·대화 시트 닫기·앱 백그라운드 전환 시 현재 재생과 대기열을 취소한다.

## 코드 경계

모바일 `TtsService`의 재생 완료 대기·요청 취소·상태 통지를 정리하고 UI가 이를 소비한다. 기존 단어·가나·직접 URL 재생 호출자의 호환성을 유지한다. 주입 가능한 player factory와 Dio adapter로 실제 네트워크·오디오 장치 없이 경합을 시험한다. 생산용 의존성은 추가하지 않는다.

`reading.audioUrl`·체크포인트 서명·진도/복습 정책·로그인·API 응답 파싱 계약은 바꾸지 않는다. 서버 배포·DB 쓰기·권한/RLS·Data API·클라우드 설정 변경은 이번 작업에 없다. 사용자 요청은 구현·검증이며 아이폰 설치는 별도 결과로 구분한다.

## 회귀 검증

핵심은 음원 시작과 재생 완료가 서로 다른 이벤트임을 검증하는 것이다. 단순 `for/await`로 재생 시작 Future만 기다리면 다음 문장이 앞 문장을 끊는다.

1. 완료 이벤트 전에는 다음 문장을 요청/재생하지 않고, 완료되면 원래 순서로 진행한다.
2. 조회 중 정지·재생 중 정지·빠른 재시작·다른 문장 재생으로 전환해도 늦은 작업이 다시 소리를 내지 않는다.
3. 플레이어 명령 경합·완료 이벤트·실패 후 재시도를 제어해 중복 구독·미완료 대기를 방지한다.
4. 전체 듣기 컨트롤·현재 문장·로딩/정지/다시 듣기·오류 UI를 위젯 테스트한다.
5. 화면 이탈·단계 변경·시트 종료·백그라운드에서 재생을 취소하는지 확인한다.
6. 기존 레슨 이어하기·저장 목록·체크포인트·문장별 TTS 연결 시험을 포함해 모바일 분석과 전체 테스트를 실행한다.

## 롤백과 기록 보존

모바일 코드만 되돌리면 기존 문장별 재생 동작으로 복귀한다. 이번 작업은 운영 음원이나 캐시 행을 바꾸지 않으므로 HN5-004 파일럿의 4개 음원은 그대로 유지된다. 앱 데이터 삭제·로그아웃·진도 초기화 없이 대응한다.

검증 결과·변경 파일·제약은 구현 완료 후 아래에 기록한다.

## 구현 결과

문장별 native player와 완료 구독을 분리하고, 실행·문장·컨트롤 소유자를 확인한다. 이전 음원의 지연 완료·오류 이벤트가 새 문장에 반영되지 않으며, 준비 중 정지는 `play()`가 끝나기를 기다리지 않고 즉시 요청한다. 이전 음원 정리 확인 후 다음 음원을 시작한다. stop 실패 시 dispose로 정리를 시도하고 둘 다 실패하면 새 재생을 막아 겹침을 피하고 앱 재실행 안내를 표시한다.

기존 단일 음원 재생 메서드는 시작 후 반환하는 동작을 유지하고, 전체 듣기만 재생 완료를 기다린다. 취소 시 URL 응답과 native 준비를 기다리는 Future도 끝나며, 늦게 완료된 작업은 재생을 재개하지 않는다. 같은 화면에서 다른 문장 버튼을 누르면 전체 대기열을 취소하고 선택한 문장으로 전환한다.

화면 이탈 취소는 dispose에만 의존하지 않는다. 레슨 단계 변경·X·뒤로가기·시트 pop·앱 비활성화 시점에 취소한다. 컨트롤의 소유자를 구분해 이전 AnimatedSwitcher 자식의 늦은 dispose가 새 화면 재생을 끊지 않게 했다. 전체 듣기 컨트롤은 ListView에서 화면 밖으로 스크롤돼도 유지하므로, 스크롤 자체는 재생 중단으로 취급하지 않는다.

마지막 리뷰에서는 같은 레슨을 빠르게 재진입했을 때 이전 Page의 늦은 dispose가 레슨 ID로 새 재생까지 정지하는 경합을 추가로 발견했다. 실제 같은 ID의 Page 두 개로 실패를 먼저 재현하고, Page.dispose의 광범위한 stop 한 줄을 제거했다. 즉시 이탈 취소와 자식의 owner 기반 정리는 유지하며, 새 Page의 재생 중 이전 Page만 제거해도 재생이 유지되는 회귀를 추가했다.

회귀 테스트는 가짜 player가 실제로 소리를 시작하려는 지점까지 모델링한다. 최종 상태만 idle인지 확인하는 대신, 준비 중 취소 후 audible start가 없는지 검증한다. UI 테스트에서 발견한 실제 시간대/FakeAsync 경계 문제는 테스트 객체 생성과 정리를 같은 위젯 테스트 안으로 옮겨 해결했으며 기대값을 완화하지 않았다.

새 테스트 30개는 완료 전 다음 문장 요청 금지, 실제 준비 단계의 audible start 취소, 같은 대화의 이전 문장과 새 실행의 늦은 완료/오류 격리, 양방향 개별/전체 재생 전환, 실패 후 처음부터 재시도, 정리 실패 시 겹침 방지, 조회·native 정리 대기 중 취소, 스크롤·시트·페이지·생명주기·동일 레슨 재진입을 검증한다. 페이지 시험에서 레슨 start/submit 호출 0회와 기존 답안·메모리 체크포인트 보존도 확인했다. 전체 모바일 테스트에는 기존 로그인·레슨 이어하기·저장 목록·체크포인트 회귀가 포함돼 있다.

### 검증의 한계와 운영 경계

- 새 페이지 복원 시험은 같은 테스트 프로세스의 메모리 저장소 기준이다. 실제 앱 프로세스 재실행·디스크 복원을 새로 실측한 결과로 표현하지 않는다.
- 오디오는 설치된 플러그인의 준비/정지 동작을 모델링한 fake player로 시험했다. 실제 아이폰의 재생·문장 사이 간격·빠른 정지/다시 듣기·화면 이탈은 업데이트 후 확인해야 한다. 앞선 HN5-004 문장별 재생 사용자 확인과 이번 신규 전체 듣기 검증은 별개다.
- 로컬 미리보기에서 작은 화면의 컨트롤·재생/오류 배치를 확인했다. 대체 글꼴과 애니메이션 중간 프레임이 포함돼 제품 화면 증거로 채택하지 않았으며 임시 capture helper는 제거했다.
- 이번 개발 작업에서 운영 서버·DB 접속이나 설정 변경은 하지 않았다. 이를 Data API 운영 상태의 새 실측 검증으로 표현하지 않는다. 설정과 권한을 유지한 모바일 변경이다.
- 실제 앱은 기존 TTS POST를 재사용하므로 cache miss 때 서버의 기존 생성·캐시 쓰기가 발생할 수 있다. 학습 기록 보존과 모든 DB 쓰기 금지는 서로 다르다. 신규 bulk 생성·미리 조회는 추가하지 않았다.

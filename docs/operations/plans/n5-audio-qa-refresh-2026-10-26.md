## 구현 계획

1. 충돌한 검수 보고 스크립트와 회귀에서 기존 N4 챕터 검색·판정 의미와 N5 level 선택을 함께 유지한다. 새 날짜의 N5 챕터 packet을 추가할 때 과거 파일이 중복 합산되거나 예전 PASS가 새 PENDING을 가리지 않도록 회귀를 둔다.
2. 기존 공식 CA·검증된 TLS와 REPEATABLE READ·READ ONLY, 시간·행 수 제한을 사용한 새 기준선으로 기존 학습 기록·보안 지문을 비교한다. 과거 임시 기준선이 없어 사흘간 기록 불변을 주장하지 않는다. 개인 행·자격 증명·서명 URL을 공개 자료로 내보내지 않는다.
3. 현재 공개 N5 레슨·대화·문제와 저장 TTS를 batch SELECT로 가져와 같은 스냅샷에서 대조한다. 공개 콘텐츠와 공개 GCS URL만 private 작업 자료로 저장한다. runtime 입력과 cached text의 정확 일치·누락·중복·source order를 구분한다.
4. 같은 snapshot을 기반으로 현재 날짜의 챕터별 packet·index·정합 보고서를 만든다. 5월 자료는 과거 기록으로 보존한다. 기존 판정을 현재 음성·문장에 검증 없이 이월하거나 자동 PASS로 만들지 않는다.
5. 가능한 범위의 공개 음성 URL·파일·길이·무음 검사는 DB 접속 없이 snapshot으로 수행한다. machine 검사, STT 실행 여부, 사람 판정, 실제 앱 UAT를 각각 구분한다.
6. 대표 레슨 HN5-004 ‘공통점이 반가울 때’의 대화 네 줄과 기초 대안 HN5-001 ‘처음 만난 자리’를 직접 들을 수 있는 짧은 확인표를 준비한다. 실제 운영 연결과 현재 텍스트를 확인한 URL만 제공한다. 단어 TTS는 별도 경로, question TTS는 현재 모바일 UI 미연결, 전체 듣기는 reading.audioUrl이 있을 때만이라는 범위를 명시한다.
